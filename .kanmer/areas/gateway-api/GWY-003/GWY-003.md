## What

Resolve the authenticated staff bearer principal into a Core `ActionActor` through `StaffActorFactory.TryCreate`, and add the endpoint filter that requires a named `StaffAccessRight` per `/api/v1` route group, with a positive and negative test for every right.

## Why

Proposal § 8.3 puts authorization on the server and § 10.1 makes the API the boundary that "enforces permissions even if a workstation is misconfigured". `Pegasus.Web` today resolves the staff actor only in `StaffPageModel.TryGetActor`, which is a Razor Pages base class the API cannot use. Operator-visible consequence: a disabled account or a user without a right gets a `not-authorized` problem from the gateway rather than a page they should never have reached, and an Automation token cannot borrow the desktop surface. [[DSK-03-06]] through [[DSK-03-15]] each declare their right against this filter.

3. Add `src/Pegasus.Web/Api/StaffActorAccessor.cs`: a scoped service that calls `StaffActorFactory.TryCreate(User.FindFirstValue(ClaimTypes.NameIdentifier), User.FindAll(ClaimTypes.Role).Select(c => c.Value), out actor)` exactly as `src/Pegasus.Web/Pages/StaffPageModel.cs:11-16` does. Do not copy the parsing logic — call the same Core factory, so there is one claims → actor implementation.
4. Reject non-staff tokens explicitly: if the principal carries the `pegasus-automation-mcp` audience (`src/Pegasus.Web/Mcp/AutomationMcp.cs:31`) or resolves to an `ActorKind` other than `Staff`, fail with 403 `urn:pegasus:problem:not-authorized`. Add the same `ISecurityEventWriter` denial record the MCP resolver writes at `AutomationActorResolver.cs:76-90`, reusing that writer rather than adding a second audit path.
5. Add `src/Pegasus.Web/Api/RequireStaffRightFilter.cs`: an `IEndpointFilter` taking a `StaffAccessRight`, resolving the actor via the accessor and calling `Pegasus.Core.Identity.StaffAuthorization.IsAuthorized(actor, right)`. On refusal, return the 403 `not-authorized` problem from [[DSK-03-02]]. Expose it as `RouteGroupBuilder.RequireStaffRight(StaffAccessRight right)` so each group in later tickets declares its right in one line.
6. Make the filter a fail-fast boundary, not a policy engine: every Core use case still calls `StaffAuthorization.Require(...)` itself (see `src/Pegasus.Core/Intake/IntakeQueryUseCases.cs:16`). Add an XML doc saying so and never widen the filter with business preconditions — that is the *Two policy engines* trap in § 7.
7. Make the actor available to endpoint handlers without re-resolving: register the accessor in DI in `AddPegasusDesktopGateway` and have the filter stash the resolved `ActionActor` in `HttpContext.Items` under a constant key exposed by `DesktopGateway`.
8. Handle the `password-change-required` and `account-disabled` cases by mapping whatever `DSK-04-04` signals into the matching `ProblemTypes` constants — do not implement the identity check here; only map it.
9. Add `tests/Pegasus.IntegrationTests/DesktopGatewayAuthorizationTests.cs` with, for each of the twelve `StaffAccessRight` values, one authorized-success fact and one wrong-role-refused fact against a test endpoint mapped inside the group with that right. Add three further facts: a disabled account is refused, an Automation-audience token is refused, and an anonymous request receives 401.
10. Assert the security-event side effect in at least the disabled-account and Automation-token facts, reading through the same `ISecurityEventWriter` port the MCP tests use, so denial is observable and not merely a status code.
11. Run `dotnet test ./tests/Pegasus.IntegrationTests/Pegasus.IntegrationTests.csproj -c Release --filter "FullyQualifiedName~DesktopGatewayAuthorizationTests"`. Done means 27 facts pass (12 × 2 plus 3).
12. Run the simplification pass over the branch diff and record it under a dated `## Simplification pass` heading in the ticket plan.
