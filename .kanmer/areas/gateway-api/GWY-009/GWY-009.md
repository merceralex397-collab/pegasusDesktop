## What

Add the case task and note surface to `/api/v1`: add note, create/assign/complete/cancel task, record a manual chase, and link or unlink report evidence — each an explicit command with the same seven-case test matrix as [[DSK-03-08]] — and make every document removal and custody confirm/fail write exactly one automatic case note onto the timeline the operator actually reads (upstream DOCS-012).

## Why

Proposal § 13.3 puts tasks, notes and chasers in the case lifecycle the desktop must carry, and § 10.2 requires explicit auditable commands. Operator-visible consequence: the case workspace's task strip works natively — an operator can assign, complete and cancel work and record a chase without the web app. Tasks carry their own version (`CaseTaskVersionConflictException`), so the concurrency contract differs from the case-scoped commands and must be tested separately. Upstream DOCS-012 adds the second half: the operator's answer of 2026-08-24 is that document changes are recorded as *"notes (created by system same as other automatic notes)"*, and today they are not recorded at all — logical removal writes only the version flags, while `custody_confirmed`/`custody_failed` write into `CaseHistory`, a second write-only table nothing operator-facing reads. Operator-visible consequence if this is not fixed: the desktop reports a document removed or stored, and the case timeline stays empty — the exact shape of the Release 22 production defect where the page said the note was added and the tab stayed at zero.
