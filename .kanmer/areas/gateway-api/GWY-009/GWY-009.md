## What

Add the case task and note surface to `/api/v1`: add note, create/assign/complete/cancel task, record a manual chase, and link or unlink report evidence — each an explicit command with the same seven-case test matrix as [[DSK-03-08]].

## Why

Proposal § 13.3 puts tasks, notes and chasers in the case lifecycle the desktop must carry, and § 10.2 requires explicit auditable commands. Operator-visible consequence: the case workspace's task strip works natively — an operator can assign, complete and cancel work and record a chase without the web app. Tasks carry their own version (`CaseTaskVersionConflictException`), so the concurrency contract differs from the case-scoped commands and must be tested separately.

## Implementation steps

1. Orient. Read the four Tasks rows quoted above in `docs/desktop/03-gateway-api-and-data/endpoint-map.md` § Cases and `README.md` § 3. Then `get_doc_gates <this ticket id>` and `take_ticket`.

3. Add `src/Pegasus.Contracts/Cases/Commands/` DTOs for the eight commands. Give the task commands a `taskExpectedVersion` field distinct from `expectedVersion`, so the two concurrency scopes cannot be confused by a caller or by the generated client.
4. Add `src/Pegasus.Web/Api/CaseTaskEndpoints.cs` extending the `cases` sub-group. Map `POST /{id}/notes`, `POST /{id}/tasks`, `POST /{id}/tasks/{taskId}/assign`, `/complete`, `/cancel`, `POST /{id}/chases/manual`, `POST /{id}/report-evidence/link` and `/unlink` — eight named routes, no dispatcher.
5. Resolve the actor from `HttpContext.Items` and construct the Core request records exactly as the page handlers do; the endpoint adds no rule of its own.
6. Let `CaseTaskVersionConflictException` reach the problem middleware from [[DSK-03-02]]. If that middleware does not yet map it (it maps the case-scoped conflicts), add the mapping there to `urn:pegasus:problem:version-conflict` with the task's current version, in the same file — do not add a second catch block in this endpoint file.
7. Apply the `operationKey` boundary rule (`desk:` prefix, ≤ 100 characters, no whitespace or control characters) and reuse the `/api/v1` write rate-limit policy added in [[DSK-03-08]].
8. Return the created note id, the task record and the new version as the endpoint-map rows specify, so the desktop can update its task strip without a re-read.
9. Add `tests/Pegasus.IntegrationTests/DesktopGatewayCaseTaskTests.cs` with the seven-case matrix for each of the eight commands: success, unauthorized, version conflict (task version for the task commands, case version for the rest), lease conflict, lease expired, replay of the same `operationKey` returning the same result, and validation failure.
10. Add one fact that a task command sent with the *case* version instead of the task version fails as a validation or conflict problem rather than silently succeeding — this is the specific way the two version scopes get confused.
11. Regenerate and commit the OpenAPI snapshot and the generated client.
12. Run `dotnet test ./tests/Pegasus.IntegrationTests/Pegasus.IntegrationTests.csproj -c Release --filter "FullyQualifiedName~DesktopGatewayCaseTaskTests"`, then run the simplification pass and record it under a dated `## Simplification pass` heading in the ticket plan.
