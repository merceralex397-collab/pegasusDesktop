## What

Harden the finished `/api/v1` surface: response compression for JSON and problem responses only, `ETag`/`If-None-Match` on every read, cancellation propagated into every Core and provider call, per-endpoint provider timeouts, and a contract test that runs the previous OpenAPI snapshot against the current server for the whole supported client range.

## Why

Proposal § 15.2 lists compression and conditional requests as implementation practices, § 16.1 requires cancellation in the operation model, and § 16.2 requires provider-specific resilience. Operator-visible consequence: the desktop stays responsive on a slow link, a cancelled screen release its database connection instead of holding it, and a pilot-ring client one version behind keeps working because the previous contract is tested against the running server. Assumption A-4 in the plan — that Azure SQL S0 tolerates ten desktop clients polling — is measured here and in area 10.

Add `AddResponseCompression` in `src/Pegasus.Web/Program.cs` configured **only** for `application/json` and `application/problem+json`, and register the middleware so it applies to `/api/v1` without changing Razor Pages or static asset behaviour. 4. Audit every read endpoint for a weak `ETag` and `If-None-Match` handling. Where one is missing, add it using the same helper, not a per-endpoint variant; extract the helper into `src/Pegasus.Web/Api/` if it was duplicated as endpoints were added.
5. Audit every handler for `CancellationToken` propagation from `HttpContext.RequestAborted` into every Core call and provider call. A handler that ignores the token is a defect; list every one found and fix them in this branch.
6. Introduce per-endpoint provider timeouts as named constants in one place (the pattern `Directory.Build.props`'s `PlaywrightVersion` establishes for a cross-cutting value): a DVLA/DVSA lookup, a Graph read and a Box operation each get their own timeout, and the constant is referenced, never re-typed.
7. Confirm the retry rule holds across the surface: only idempotent `GET`s are retry-eligible, and no command carries automatic retry. Add an assertion or an analyzer-style test that fails if a command endpoint is marked retryable in the OpenAPI document.
8. Add the compat-range contract test to `tests/Pegasus.Api.ContractTests`: for the supported client range, run every operation described by `openapi/pegasus-v1.previous.json` against the current server and assert the response still validates against the previous schema. A removed field or narrowed type must fail.
9. Add cancellation facts to `tests/Pegasus.IntegrationTests`: cancel a long list request mid-flight and assert the database connection is released (assert through the connection pool or the `OperationCanceledException` path, not a sleep), and assert no partial write occurred for a cancelled command.
10. Add compression facts: a JSON response with `Accept-Encoding: gzip` is compressed; a PDF or image byte response is not; a problem response is compressed.
11. Measure under load with `dotnet-counters` against the local stack with ten concurrent simulated clients, following the `analyzing-dotnet-performance` skill, and record the numbers in the ticket's post-implementation report against the budgets in area 10. Note explicitly whether assumption A-4 (Azure SQL S0 tolerating the read traffic) still holds.
12. Regenerate and commit the OpenAPI snapshot, run the contract and integration tests, then run the simplification pass and record it under a dated `## Simplification pass` heading in the ticket plan.

## Guardrails

- **Azure**: no write. The measurement runs on the local production-mimicking stack (L-02); asking for an Azure load-test resource is out of bounds under ADR-0014.

Must not change any endpoint's contract — this ticket is behaviour-preserving on the wire except for compression and conditional responses.
- **Traps**: compressing byte responses wastes CPU and can break range requests — exclude them explicitly. Contract changes must stay additive until the minimum client version advances; removing a field is a contract-test failure by design. Do not invent a latency threshold. The observability blind spot (App Insights capped at 0.1 GB/day, PLAT-034) means the measurement evidence must be captured locally and attached to the ticket, not looked up in production later.
