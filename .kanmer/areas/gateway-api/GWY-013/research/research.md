## Scope and constraints

Proposal § 10.2 states plainly: "Do not expose a generic 'execute action' endpoint… Workflow-changing operations should be explicit and auditable." The Razor page uses a string dispatcher today, which is fine for a form post and wrong for a contract — a generated client cannot type a string switch, and an audit reader cannot tell one action from another in the route. Operator-visible consequence: triage, unidentified resolution and the operations retry queue all work natively, and every action appears in history under its own name. One route in this set gains behaviour rather than a shape: `POST /unidentified/{id}/resolve` is today a bare resolve, so an Unidentified triage request whose registration only ever appears inside an image dead-ends with no staff action that can open its Triage (upstream INTK-035). This ticket owns that endpoint, so the promote path is built here (step 7) and [[DSK-05-12]] renders it.
