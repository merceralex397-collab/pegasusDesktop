## Approach

Make the document a **gated build output** and guard it with a byte comparison, not a semantic one.
Registering `AddOpenApi`/`MapOpenApi` inside `AddPegasusDesktopGateway`/`MapPegasusDesktopGateway`
means a deployment with `Features:DesktopGateway` off publishes nothing — the same rule the rest of the
surface follows, and the reason `GET /diagnostics/version` (`src/Pegasus.Web/Program.cs:954`) must
**not** appear in the document. The rejected alternative was a semantic comparison (parse both
documents, compare structures): it tolerates formatting churn, which sounds convenient, but it also
tolerates a reordering that changes the generated client, and it cannot be regenerated by an operator
with a single command. The four normalisation rules — stable property ordering, two-space indent,
`\n` line endings, no server-specific host — exist so that a byte comparison is *meaningful*, and this
ticket owns them ([[TEST-001]]'s Guardrails say so from the other side).

One prerequisite is load-bearing and is argued from measurement rather than convention:
`src/Pegasus.Web/Pegasus.Web.csproj:9-12` declares `InternalsVisibleTo` for
`Pegasus.IntegrationTests` and `Pegasus.ArchitectureTests` only. Minimal hosting emits an `internal`
`Program`, so `WebApplicationFactory<Program>` in a third test project **does not compile** until an
entry is added. Neither this ticket's body nor [[TEST-001]]'s names it; this ticket already has that
file in scope, so it adds it.

## Risks / open questions

- **Risk — the snapshot test does not compile.** `src/Pegasus.Web/Pegasus.Web.csproj:9-12` grants
  `InternalsVisibleTo` to two projects and not to the contract project, while minimal hosting emits an
  `internal` `Program`. *Mitigation*: step 3 adds the third entry; neither ticket body names it, which
  is why it is called out here and in the files document.
- **Risk — the export is not deterministic.** If `Microsoft.AspNetCore.OpenApi` orders schemas by
  reflection order, byte comparison churns. *Mitigation*: A-GWY004-2 names the failure and the
  response — the normaliser imposes the ordering itself and that becomes part of the four rules.
  **Never** weaken the test to a semantic comparison: it would tolerate a reordering that regenerates
  the whole Kiota client.
- **Risk — a stale or missing `packages.lock.json` fails every lane, not one job.** The composite action
  restores `--locked-mode` and caches on `src/**/packages.lock.json` and `tests/**/packages.lock.json`.
  *Mitigation*: step 3 (and step 6 in the fallback branch) generates and commits before the solution
  restore.
- **Risk — the document leaks endpoints that are not part of the contract.** `GET /diagnostics/version`
  and the health endpoints are outside `/api/v1`. *Mitigation*: step 4 registers on the group, and
  verification 7 greps for it.
- **Risk — the `unit` job's comment becomes false.** *Mitigation*: step 10 edits it in the same change.
  A stale comment explaining why the `&&` chain exists is precisely what this repository writes
  comments to prevent.
- **Risk — a README lands beside the snapshot.** *Mitigation*: step 8 puts the instructions in the
  script help and the failure message; `scripts/Test-MarkdownPlacement.ps1`'s canonical roots do not
  include `openapi/`.
- **Scope boundary, not an open question — the test project scaffold.** [[TEST-001]] owns it; step 6
  checks and extends in place. Conversely this ticket owns `OpenApiSnapshotTests.cs` and its four
  normalisation rules, and [[TEST-001]] step 5 extends that file. Both bodies say so, in opposite
  directions.
- **Scope boundary, not an open question — promoting `openapi/pegasus-v1.previous.json`.** When the
  previous snapshot is advanced is a release decision tied to the minimum-client-version bump; area 03
  § 7 is the authority and [[GWY-017]] (plan handle `DSK-03-17`) owns the compat-range test.
- **Scope boundary, not an open question — Kiota and the generated client.** [[GWY-005]] (plan handle
  `DSK-03-05`) consumes this file and the `eng/api/` tree this ticket creates.
- **Body imprecision worth recording, not a contradiction.** The body cites
  `.github/workflows/ci.yml:130-146` for the `unit` job; measured, it is `:131-147`. It cites
