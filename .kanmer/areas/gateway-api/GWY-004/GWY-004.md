## What

Produce an OpenAPI document for the `/api/v1` surface with `Microsoft.AspNetCore.OpenApi`, export it to a committed `openapi/pegasus-v1.json`, and add a new `tests/Pegasus.Api.ContractTests` project whose snapshot test fails on any contract change that was not reviewed.

## Why

Proposal § 10.3 says to "treat the OpenAPI document as a build artifact and contract" and to "add a contract snapshot test"; the plan's exit gate requires the snapshot test to pass and regeneration to be a no-op. There is no OpenAPI document, Swashbuckle, NSwag or Kiota in the repository today. Operator-visible consequence: a field silently removed from a response would break installed desktop clients in the field, and the pilot ring cannot be rolled back quickly — the snapshot turns that into a failed build instead. [[DSK-03-05]] generates the client from this document.

## Implementation steps

1. Orient. Read `docs/desktop/03-gateway-api-and-data/README.md` § 3 row *OpenAPI & client* and § 4, then `get_doc_gates <this ticket id>` and `take_ticket` with a real branch and worktree from `origin/dev`.
2. Use `microsoft_docs_fetch` on <https://learn.microsoft.com/aspnet/core/fundamentals/openapi/aspnetcore-openapi> to confirm the .NET 10 `AddOpenApi` / `MapOpenApi` shape, document naming, and how to add a document transformer. Record the fetch date in the ticket research document.
3. Add the `Microsoft.AspNetCore.OpenApi` package reference to `src/Pegasus.Web/Pegasus.Web.csproj` through the central package management introduced by `DSK-02-02` (a version in the csproj is a defect once CPM is on), and refresh `src/Pegasus.Web/packages.lock.json`.
4. In `src/Pegasus.Web/Api/DesktopGatewayExtensions.cs`, call `AddOpenApi("v1", …)` inside `AddPegasusDesktopGateway` and `MapOpenApi("/openapi/{documentName}.json")` inside `MapPegasusDesktopGateway`, both **inside the `Features:DesktopGateway` gate** so the document does not appear on a deployment that has the surface disabled.
5. Add a document transformer that registers the problem schemas from `src/Pegasus.Contracts/Problems` and the paging envelope so `PegasusProblem` and `PagedResult<T>` appear as components, and set the document title, version and description from the assembly product version already read in `Program.cs`.
6. Create `tests/Pegasus.Api.ContractTests/Pegasus.Api.ContractTests.csproj` (xunit, matching the versions used by `tests/Pegasus.IntegrationTests`), add it to `Pegasus.slnx` under `/tests/`, and enable a lock file to match repository practice.
7. Add `tests/Pegasus.Api.ContractTests/OpenApiSnapshotTests.cs`: boot a `WebApplicationFactory<Program>` with `Features:DesktopGateway=true`, `GET /openapi/v1.json`, normalise (stable property ordering, two-space indent, `\n` line endings, no server-specific host) and compare byte-for-byte with the committed `openapi/pegasus-v1.json`. On mismatch the failure message must tell the operator the exact regeneration command from step 8.
8. Add `eng/api/Export-OpenApiDocument.ps1` that boots the same host, writes the normalised document to `openapi/pegasus-v1.json`, and exits non-zero on failure. Commit the first generated `openapi/pegasus-v1.json`. Keep the script in `eng/api/` — [[DSK-03-05]] adds `eng/api/Generate-ApiClient.ps1` beside it.
9. Add a second fact `PreviousSnapshotRemainsSatisfied`: keep the previous accepted document at `openapi/pegasus-v1.previous.json` and assert every path, operation and required response property present there is still present in the current document. This is the additive-only rule from § 7 *Pilot ring compatibility*; removing a field must fail by design.
10. Wire the new project into CI by appending it to the existing `unit` job's chained `dotnet test` command in `.github/workflows/ci.yml` (do not add a new job — C-01 makes a new Windows job a recurring cost).
11. Run `dotnet build Pegasus.slnx -c Release`, then `pwsh ./eng/api/Export-OpenApiDocument.ps1` and `git diff --exit-code openapi/` — expected: no diff on a second run. Then `dotnet test ./tests/Pegasus.Api.ContractTests/Pegasus.Api.ContractTests.csproj -c Release`.
12. Run the simplification pass over the branch diff and record it under a dated `## Simplification pass` heading in the ticket plan.
