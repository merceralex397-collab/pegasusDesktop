## What

Establish the development code-signing certificate pipeline — generate it with `winapp cert generate --manifest`, install its trust on the Test/UAT machines using the **same store the production route uses** (`Cert:\LocalMachine\TrustedPeople`), and prove a dev-signed MSIX installs on a clean Windows 11 test machine.

## Why

Proposal § 24 Phase 1 requires a development MSIX and an exit gate of "Package install/uninstall works" on a clean Windows 11 test machine, and § 29 item 7 requires the foundation spike to include a **signed** development MSIX. An MSIX cannot be installed unless its signing certificate is already trusted on the machine — the failure is `0x800B0109` (`CERT_E_UNTRUSTEDROOT`), and Microsoft's deployment guidance is explicit that certificate trust must reach devices **before** the app does. Rehearsing that ordering now, on disposable machines, is what makes the production rollout in [[DSK-09-08]] routine rather than discovered under pressure.

## Implementation steps

1. Orient: read the § 5 row, `signing-and-hosting-decision-matrix.md` § D-002 chosen shape, and `runbooks.md` § R7 prerequisite 4. Call Kanmer `get_doc_gates` on this ticket id, then `take_ticket`.
2. Load `winui-packaging` and read its Quick Reference table and Troubleshooting table in full.
3. Fix the development certificate subject to the same string as `Package.appxmanifest` `Identity/@Publisher` (the stable placeholder CN established by [[DSK-02-05]]). Generate it with `winapp cert generate --manifest ./src/Pegasus.Desktop --if-exists skip` so the subject is auto-matched — a mismatch produces the "Publisher mismatch" packaging failure.
4. Record where `devcert.pfx` lives and prove it is not committed: add `devcert.pfx` and `*.pfx` to `.gitignore` if not already covered, and confirm with `git check-ignore -v devcert.pfx`.
5. Export the public certificate only: `Export-Certificate -Cert (Get-PfxCertificate ./devcert.pfx) -FilePath ./artifacts/devcert.cer -Type CERT`. The `.pfx` never leaves the build machine.
6. Write `eng/packaging/Install-DevCertificateTrust.ps1` — an elevated script that runs `Import-Certificate -FilePath <cer> -CertStoreLocation Cert:\LocalMachine\TrustedPeople` and then `certutil -verifystore TrustedPeople` and asserts the thumbprint is listed. Use `TrustedPeople`, **not** `Trusted Root Certification Authorities`: `winapp cert install` writes to the machine Trusted Root store, which would let that key vouch for anything the machine trusts, and the MSIX troubleshooting guide warns against it.
7. **Operator step** — on the Test/UAT workstation VM (see `docs/desktop/08-testing/test-uat-stack.md` § Machine prerequisites): run the trust script elevated, then hand back the `certutil -verifystore TrustedPeople` output showing the thumbprint. Trust goes on the machine **before** any package is copied to it.
8. Build and package a dev-signed MSIX: `winapp package ./src/Pegasus.Desktop/bin/x64/Release/<tfm>/ --cert ./devcert.pfx --self-contained` (per `winui-packaging`, the single-step `package --cert` form is preferred over a separate `winapp sign`).
9. **Operator step** — on the clean Windows 11 x64 Test/UAT machine: install with `Add-AppxPackage .\Pegasus_<ver>_x64.msix`, confirm with `Get-AppxPackage CollisionEngineers.Pegasus`, launch the app, then `Get-AppxPackage CollisionEngineers.Pegasus | Remove-AppxPackage` and confirm it is gone. Hand back the console transcript.
10. Prove the negative: on a second machine that has **not** had the trust step, attempt `Add-AppxPackage` and record the exact failure. Expected: `0x800B0109`. Then run the trust script and retry successfully. This is the evidence that the ordering rule in R5/R7 is real.
11. Write up the renewal and revocation shape for the **development** certificate in the ticket plan (throwaway, regenerate freely, no estate impact) and state explicitly that the production route is [[DSK-09-08]] and is not interchangeable with this one.
12. Record the dated `## Simplification pass` in the ticket plan document; if the diff is only the two scripts and `.gitignore`, say so.

## Acceptance criteria

- [ ] A dev-signed MSIX installs on a clean Windows 11 test machine after the trust step and uninstalls cleanly.
- [ ] The trust step uses `Cert:\LocalMachine\TrustedPeople`, never `Trusted Root Certification Authorities`.
- [ ] Installing without the trust step reproduces `0x800B0109`, and the recorded fix is trust-then-retry.
- [ ] `devcert.pfx` is git-ignored and never committed; only the `.cer` is distributed.
- [ ] The certificate subject equals `Identity/@Publisher` in `Package.appxmanifest`.

## Verification

- [ ] `certutil -verifystore TrustedPeople` on the test machine — expected: the development certificate thumbprint is listed.
- [ ] `Add-AppxPackage .\Pegasus_<ver>_x64.msix` then `Get-AppxPackage CollisionEngineers.Pegasus` — expected: install succeeds and the package version matches the build.
- [ ] `Get-AppxPackage CollisionEngineers.Pegasus | Remove-AppxPackage` — expected: exit code `0` and the package no longer listed.
- [ ] `git check-ignore -v devcert.pfx` — expected: a matching `.gitignore` rule is reported.
