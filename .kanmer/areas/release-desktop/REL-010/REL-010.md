## What

Finalise runbook **R3 · Mandatory-update enforcement** and prove it: raising the gateway's minimum client version blocks an old client with the update-required screen and a correlation id, while a current client proceeds normally.

## Why

Proposal § 9.1 makes the gateway minimum-version gate the layer that protects against App Installer configuration failures and lets the API reject a version with a serious defect — it is the **fail-closed** half of the two-layer design, because the package check fails open when the feed is unreachable. Programme exit criterion 4 ("Unsupported versions cannot proceed") and Phase 9's "update and rollback exercised" both depend on this being demonstrated, not assumed. Until R3 is proven, nobody can say what actually happens to a workstation left behind.

3. Read the admin surface delivered by [[DSK-04-06]] and write R3 step 1 against the real control: the minimum client version is a **DB-backed Administrator setting with an audit entry**, changed with a reason. Name the exact screen or endpoint in the runbook — not "the admin surface".
4. Build the rehearsal on the Test/UAT stack first (L-02): install version N-1 from the stack's local feed, raise the minimum client version to `<ver>` in the stack gateway, relaunch, and record which of the two layers fires. With the feed reachable, App Installer should update; with the feed made unreachable, the gateway's update-required screen must appear and no work must be possible.
5. Script the enforcement check as part of the packaging suite ([[DSK-08-10]]): a scenario that sets the minimum version, launches the old client, asserts the update-required screen by `AutomationId` using `winui-ui-testing`, and asserts that every `/api/v1` call from that client returns the `client-unsupported` problem response.
6. Use `microsoft_docs_search` for `Package CheckUpdateAvailabilityAsync Required Available` and record in the runbook what `Required` means — that the `.appinstaller` policy blocks activation — so the two layers are not confused in the write-up.
7. R3 step 2 — **Operator step**: from a pilot machine still on the previous version, launch. Expect App Installer to update if the feed is reachable; if the feed check is bypassed or unreachable, expect the gateway's update-required screen **with the correlation id** and confirm no work is possible. Hand back a screenshot and the correlation id.
8. R3 step 3 — **Operator step**: confirm a current client logs in normally and completes a routine workflow. Hand back the transcript.
9. R3 step 4 — record the minimum-version change (who, when, reason) in the desktop release row in `docs/operations.md`.
10. Write and rehearse the rollback path: lowering the minimum version to its previous value through the same admin setting restores the old clients. Prove it on the Test/UAT stack and record the observed recovery time.
11. State the runbook's limits explicitly in R3's "does not prove" section: it does not prove App Installer behaviour on a machine whose policy overrides update settings — CSP (Intune) settings override PowerShell and `.appinstaller` settings, which override an embedded `.appinstaller`; R7 records the expected policy state and `Get-AppxPackageAutoUpdateSettings` is the check.
12. Mark R3 proven in `runbooks.md` with its date and record the dated `## Simplification pass` in the ticket plan document.

## Guardrails

- **Azure**: no write. The minimum-version setting is application data in the gateway's database, changed through the audited admin surface — not an Azure resource change. Do not touch Container App configuration.
- **Scope boundary**: `docs/desktop/09-.../runbooks.md`, the packaging test suite under `eng/packaging/`, `docs/operations.md`. Must not modify the gateway's compatibility endpoint or middleware — that is [[DSK-04-06]]; if a defect is found there, raise a `fix` ticket rather than patching from here.
- **Traps**: the package check fails open, so a test with a reachable feed proves the wrong layer — test both with the feed reachable and unreachable. `Package.Current.CheckUpdateAvailabilityAsync` fails with access denied; the client uses `PackageManager.FindPackageForUser` ([[DSK-04-09]] owns that code). Group Policy/CSP can override App Installer settings on managed devices. Do not raise the minimum version while a pilot user is known to be off-network — they would be locked out of work until they return.
- **Operator-only**: changing the production minimum-version setting and launching an old client on a pilot workstation are operator actions.
