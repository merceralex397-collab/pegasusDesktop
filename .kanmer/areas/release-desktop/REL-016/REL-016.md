## What

Add a **Desktop releases** table to `docs/operations.md` — version, date, commit, package hash, signer, channel, compatibility range, pilot/production — with the first row from the pilot release, and join its compatibility range to the gateway release number.

## Why

Proposal § 21.2 item 15 requires every release to record package hash, version, source commit and API compatibility range, and `AGENTS.md` § Safety rails requires current-state documents to be refreshed in the same task as the release. `docs/operations.md` already carries the authoritative gateway release table (releases 1–20, newest 2026-08-22), but nothing records a desktop release, its signer, or which gateway releases a given desktop version is compatible with. Without this table, the compatibility range that the minimum-version gate enforces exists only inside build artefacts.
