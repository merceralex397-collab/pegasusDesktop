## What

Add `scripts/Build-DesktopRelease.ps1`: a clean-HEAD, locked-restore, x64 Release desktop build that runs `winapp package`, generates the `.appinstaller` and `desktop-release-manifest.json`, records SHA-256 hashes and a vulnerability report, and signs **only** when `-Sign` is passed with an explicit certificate route.

## Why

Proposal § 21.2 lists the release stages a desktop build must perform (locked restore, Release build, MSIX, packaging tests, SBOM, sign only in the protected job, record hash/version/commit/compat range). Today `scripts/Build-ReleaseArtifacts.ps1` does the equivalent for the gateway and Worker only — it publishes `linux-x64` Web and Worker images and an EF migration bundle, and knows nothing about MSIX. Without this script the pilot release runbook R1 step 2 has no command to run, and every release becomes hand-assembled, which is exactly the drift the plan's § 7 traps warn about.

## Implementation steps

1. Orient: read the § 5 row, `runbooks.md` § R1 steps 1–4, and area plan § 3. Call Kanmer `get_doc_gates` on this ticket id, then `take_ticket`.
2. Read `scripts/Build-ReleaseArtifacts.ps1` end to end and reuse its safety shape verbatim in structure: `Set-StrictMode -Version Latest`, `$ErrorActionPreference = 'Stop'`, `Push-Location $repositoryRoot` / `finally { Pop-Location }`, the exact-HEAD check (`git rev-parse HEAD` must equal `-SourceRevision`), the clean-tree check (`git status --porcelain=v1 --untracked-files=all` must be empty), and the output-root escape guard.
3. Create `scripts/Build-DesktopRelease.ps1` with parameters `-Channel` (`ValidateSet 'pilot','prod'`), `-Version` (`ValidatePattern '^1\.\d+\.\d+\.0$'`), `-SourceRevision` (`ValidatePattern '^[0-9a-f]{40}$'`), `-Sign` (switch), `-CertificatePath`, `-TimestampUrl`, `-FeedRoot`. Fail immediately if `-Sign` is passed without both `-CertificatePath` and `-TimestampUrl`.
4. Set `$releaseRoot = artifacts/desktop-releases/<Version>` under the repository root, apply the same `StartsWith` escape guard as the gateway script, delete and recreate it.
5. Restore and build: `dotnet restore ./src/Pegasus.Desktop/Pegasus.Desktop.csproj --locked-mode`, then `dotnet build ./src/Pegasus.Desktop/Pegasus.Desktop.csproj -c Release -p:Platform=x64 -p:DesktopPackageVersion=<Version> -p:ContinuousIntegrationBuild=true --no-restore`. Throw on any non-zero `$LASTEXITCODE`, following the gateway script's per-step `if ($LASTEXITCODE -ne 0) { throw '…' }` pattern.
6. Package with the WinApp CLI, self-contained per proposal § 7.1 so the package carries .NET and the Windows App SDK and the `.appinstaller` needs no `Dependencies` element. Unsigned by default: `winapp package <build-output-dir> --self-contained --quiet`. When `-Sign` is passed use the single-step form from `winui-packaging`: `winapp package <build-output-dir> --cert <CertificatePath> --self-contained --timestamp <TimestampUrl> --quiet`. Name the output `Pegasus_<Version>_x64.msix`.
7. When `-Sign` was used, verify the signature before anything else is written: `signtool verify /pa /v <releaseRoot>/Pegasus_<Version>_x64.msix` and throw unless the output reports a valid chain **and** a timestamp. Extract the signer subject and thumbprint from that output for the manifest.
8. Write the vulnerability report: `dotnet list ./src/Pegasus.Desktop/Pegasus.Desktop.csproj package --vulnerable --include-transitive > <releaseRoot>/vulnerability-report.txt`, and throw if the text contains `Critical` or `High`. Leave the SBOM **generator choice** to [[DSK-09-16]]: add a `-SbomPath` pass-through parameter now, record the open question in `open-questions/`, and do not invent a generator here.
9. Call `eng/packaging/New-DesktopReleaseManifest.ps1` ([[DSK-09-02]]) to emit `desktop-release-manifest.json`, then `eng/packaging/New-AppInstaller.ps1` and `eng/packaging/Test-AppInstaller.ps1` ([[DSK-09-03]]) for the requested channel. Throw on a non-zero validator exit.
10. Write a `build-log.txt` and a hash list (`Get-FileHash -Algorithm SHA256` over the `.msix`, the `.appinstaller` and the manifest) into `$releaseRoot`, and `Write-Output` the manifest path as the script's only stdout result — mirroring `scripts/Build-ReleaseArtifacts.ps1`'s final line.
11. Resolve the script's home and record it: the area plan § 4 says `eng/packaging/`, the § 5 row says `scripts/`. Follow the row (`scripts/Build-DesktopRelease.ps1`, beside `Build-ReleaseArtifacts.ps1`) and correct `docs/desktop/09-release-update-and-distribution/README.md` § 4 in the same task so the plan set stops contradicting itself.
12. Prove determinism for the deterministic parts: run the unsigned build twice from the same clean HEAD and assert the `.msix` **content** hash list is stable apart from the signature and timestamp blocks; record the observed result — including any instability — in the ticket proof rather than asserting reproducibility that was not observed.
13. Record the dated `## Simplification pass` in the ticket plan document over this branch's own diff.

## Acceptance criteria

- [ ] The script refuses to run on a dirty tree or when HEAD does not equal `-SourceRevision`.
- [ ] An unsigned run produces `Pegasus_<ver>_x64.msix`, `Pegasus.appinstaller`, `desktop-release-manifest.json`, `vulnerability-report.txt` and a hash list under `artifacts/desktop-releases/<ver>/`.
- [ ] Signing happens only with `-Sign` plus `-CertificatePath` **and** `-TimestampUrl`; a signed run fails unless `signtool verify /pa /v` reports a valid chain and timestamp.
- [ ] The package is self-contained and the generated `.appinstaller` has no `Dependencies` element.
- [ ] `eng/packaging/Test-AppInstaller.ps1` runs inside the script and a failure aborts the build.
- [ ] The script publishes nothing: no copy to the feed happens here.

## Guardrails

- **Azure**: no write. The desktop release path touches no Azure resource at all (D-002 + D-003).
- **Scope boundary**: may add `scripts/Build-DesktopRelease.ps1` and call into `eng/packaging/`. Must not modify `scripts/Build-ReleaseArtifacts.ps1`, `infra/`, or any gateway release step — the gateway keeps the existing `pegasus-release` procedure.
- **Traps**: signing must never happen on a PR build — only on the protected tag job ([[DSK-09-17]]) or the authorised release terminal. `--timestamp` is not optional: without it every installed package's signature stops validating for new installs when the certificate expires. `Publisher` must equal the certificate subject exactly or packaging fails with `0x8007000B`. The Linux publish of Web and Worker must stay green — desktop projects are excluded from the Linux solution filter.
- **Sizing concern**: this row does a lot (build, package, sign, manifest, validate, vulnerability report). It is deliberately kept as one ticket per the plan; if the diff grows past a reviewable size, split the SBOM/vulnerability half into [[DSK-09-16]] rather than inventing a new handle.
