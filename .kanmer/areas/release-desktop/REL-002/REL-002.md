## What

Fix the desktop package version scheme at `1.<minor>.<build>.0`, flow it from the CI run number into `Package.appxmanifest` at build time, and add `eng/packaging/New-DesktopReleaseManifest.ps1`, which emits `desktop-release-manifest.json` with every field the area plan § 3 lists.

## Why

Proposal § 21.1 requires centralised build properties including package versions and a signing configuration reference, and § 21.2 stage 15 requires each release to record package hash, version, source commit and API compatibility range. The repository's only version today is `<Version>0.1.0-alpha.1</Version>` in `Directory.Build.props:9`, which is the **gateway's** identity and must stay that way; a desktop package needs a four-part, strictly increasing version because Windows refuses to update an installed package without a higher version. Without this ticket, [[DSK-09-03]] has no version to validate and [[DSK-09-04]] has no manifest to emit.

## Implementation steps

1. Orient: read the plan row and `docs/desktop/09-release-update-and-distribution/README.md` § 3 subsections "Versioning" and "Desktop release manifest", then `appinstaller-template.md` § Validator outline. Call Kanmer `get_doc_gates` on this ticket id, then `take_ticket`.
2. Load `directory-build-organization` and read `Directory.Build.props`. Do **not** change `<Version>0.1.0-alpha.1</Version>` — it is the gateway's identity, consumed by `azure.yaml:3`, `package.json:3` and `scripts/Build-ReleaseArtifacts.ps1`.
3. Add a desktop-only property file at `src/Pegasus.Desktop/Directory.Build.props` (the project is created by [[DSK-02-05]]) importing the parent (`<Import Project="$([MSBuild]::GetPathOfFileAbove('Directory.Build.props', '$(MSBuildThisFileDirectory)../'))" />`) and defining `<DesktopPackageVersion Condition="'$(DesktopPackageVersion)' == ''">1.0.0.0</DesktopPackageVersion>`.
4. Add an MSBuild target `StampDesktopPackageVersion` in `src/Pegasus.Desktop/Pegasus.Desktop.csproj` that runs `BeforeTargets="_CreateMsixRecipe;GenerateAppxManifest"` and rewrites `Identity/@Version` in the staged `Package.appxmanifest` to `$(DesktopPackageVersion)`. Validate the value against `^1\.\d+\.\d+\.0$` in the target and fail the build with a clear message otherwise. Use `microsoft_docs_search` for `MSIX Package.appxmanifest Identity Version four part` to confirm the four-part rule before writing the regex.
5. Create `eng/packaging/New-DesktopReleaseManifest.ps1`. Parameters, modelled on `scripts/Build-ReleaseArtifacts.ps1:1-9`: `-Version` (`ValidatePattern '^1\.\d+\.\d+\.0$'`), `-Channel` (`ValidateSet 'pilot','prod'`), `-SourceRevision` (`ValidatePattern '^[0-9a-f]{40}$'`), `-PackagePath`, `-AppInstallerVersion`, `-SignerSubject`, `-SignerThumbprint`, `-MinimumGatewayRelease`, `-MaximumTestedGatewayRelease`, `-WindowsAppSdkVersion`, `-BuildRun`, `-OutputPath`.
6. Emit exactly these fields, in this order, as an `[ordered]` hashtable serialised with `ConvertTo-Json -Depth 8 | Set-Content -Encoding utf8NoBOM`: `schemaVersion` (1), `version`, `sourceCommit`, `packageSha256` (from `Get-FileHash -Algorithm SHA256`), `appInstallerVersion`, `channel`, `signerSubject`, `signerThumbprint`, `minimumGatewayRelease`, `maximumTestedGatewayRelease`, `windowsAppSdkVersion`, `buildRun`, `createdAtUtc`.
7. Add `eng/packaging/Test-NewDesktopReleaseManifest.ps1` following the shape of `scripts/Test-PegasusPlatform.ps1`: assert that a valid invocation produces every field; that `-Version 2.0.0.0` and `-Version 1.0.0.1` are rejected; that `packageSha256` equals `Get-FileHash` of the input file; that the JSON round-trips through `ConvertFrom-Json` with no BOM. Exit non-zero on any failure.
8. Decide and record where the `build` component comes from outside CI: the plan states it is the CI run number and re-based if the CI provider changes. Write that sentence into the script's header comment and add an `open-questions/` entry if the release terminal needs a manual value.
9. Run the generator locally against any file to prove it: `pwsh ./eng/packaging/New-DesktopReleaseManifest.ps1 -Version 1.0.1234.0 -Channel pilot -SourceRevision <40-hex> -PackagePath ./global.json -AppInstallerVersion 1.0.0.0 -SignerSubject 'CN=Collision Engineers' -SignerThumbprint 0000 -MinimumGatewayRelease 20 -MaximumTestedGatewayRelease 20 -WindowsAppSdkVersion 2.4.0 -BuildRun 1234 -OutputPath ./artifacts/desktop-releases/1.0.1234.0/desktop-release-manifest.json`. Expected: the file exists and contains all thirteen fields.
10. Run `pwsh ./eng/packaging/Test-NewDesktopReleaseManifest.ps1` — expected exit code `0`.
11. Record the dated `## Simplification pass` in the ticket plan document over this branch's own diff.
