## What

Author `docs/adr/0105-msix-app-installer-and-minimum-version-gate.md` — the durable decision record for signed MSIX/App Installer distribution with a gateway minimum-version gate — and add its row to `docs/adr/README.md`. ## Why

Proposal § 9 accepts mandatory updates and places substantially more application logic in the desktop client on the strength of them, which makes the update path critical infrastructure. Nothing in the repository records that decision today: `docs/adr/` runs ADR-0001…ADR-0029 and mentions no MSIX, App Installer, code-signing certificate or client-version gate. Until ADR-0105 exists, every other ticket in this epic implements an unrecorded decision and the operator has no written statement of what blocks an obsolete client. Sibling rows [[DSK-00-05]] and [[DSK-04-01]] also name ADR-0105 — see Guardrails.

4. Write § Context from proposal § 9.1: two compatible mechanisms — (a) signed MSIX/App Installer launch update, (b) gateway minimum-version gate with a pre-session `client-compatibility` endpoint and a client version on every authenticated request.
5. Write § Decision with these five clauses, taken from the plan § 3 and stated as decisions, not options: (a) App Installer **2021 schema** with `OnLaunch HoursBetweenUpdateChecks="0" ShowPrompt="true" UpdateBlocksActivation="true"`, `AutomaticBackgroundTask` and `ForceUpdateFromAnyVersion`; (b) the package check **fails open** when the feed is unreachable and the gateway gate **fails closed** after a short cached window — both layers are required; (c) package version `1.<minor>.<build>.0` where `build` is the CI run number and revision is always `0`; (d) one package identity `CollisionEngineers.Pegasus` with two feeds, `pilot/` and `prod/`, and ring changes performed by reinstall; (e) gateway first and backward compatible, desktop second, minimum client version raised last.
6. Write § Consequences recording D-002 and D-003 by name and date (2026-08-23): signing is a self-managed certificate trusted in `LocalMachine\TrustedPeople` (never `Trusted Root`), the feed is a UNC share over SMB, and **the whole distribution path therefore touches no Azure resource and has no recurring cost**. Record the accepted trade-offs verbatim in substance: a per-machine trust rollout, a rehearsed renewal, and update checks that work only on the office network or VPN.
7. Answer the six-question cloud-justification test as a table (questions copied exactly from `docs/desktop/00-governance-and-workflow/README.md` § 3): shared authority, unattended execution, protected credentials, public callback, central enforcement, measured operational advantage. Central enforcement is the `yes` that keeps the minimum-version gate in the gateway; the feed itself answers `no` to all six, which is why it is in-house.
8. Add a § Relates section: ADR-0007 (gateway release route unchanged), ADR-0014 (two environments; no Azure test feed), and a forward pointer to FRD-13 when [[DSK-00-08]] writes it.
