## What

Add a `desktop-package` job to `.github/workflows/ci.yml` on `windows-latest` that restores locked, builds the desktop app x64 Release, packages it with a generated **development** certificate, runs the packaging and `.appinstaller` validator tests, and uploads the unsigned-for-production MSIX as a build artifact — without disturbing the existing nine jobs.

## Why

Proposal § 21.2 puts "Build the MSIX", "Run packaging/update tests" and "Sign only in the protected release job" in the CI stage list, and the repository has **no publish, sign or deploy lane** today: `.github/workflows/ci.yml` runs `changes`, `documentation`, `local-development-scripts`, `reference-data`, `infrastructure`, `unit`, three `sql-integration` shards, `sql-integration-coverage` and `browser`. Without a packaging lane, a change that breaks MSIX generation is not discovered until a release is attempted. Constraint C-01 makes this lane's runtime a real cost, so it must be gated on the build change flag.

## Guardrails

- **Azure**: no write. The lane authenticates to nothing.
- **Scope boundary**: `.github/workflows/ci.yml`, `scripts/Get-CiChangeFlags.ps1`, `scripts/Test-CiChangeFlags.ps1`. Must not touch `infra/`, `azure.yaml`, or any deployment path — GitHub Actions Azure deployment is recorded as `Not planned` in `docs/runbook.md:903`.
- **Traps**: the CI runner has **no production certificate** — dev certificate only, and `winapp cert install` (which writes to the machine Trusted Root store) must **not** be used on a shared runner. `--if-exists skip` keeps re-runs from failing on an existing certificate. Chained `dotnet test` commands need `&&` on one line because pwsh reports only the last command's exit code. Private-repository Windows minutes bill at 2× (C-01), so the lane stays change-gated and time-boxed.
