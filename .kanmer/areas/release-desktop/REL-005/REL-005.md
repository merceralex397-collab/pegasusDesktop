## What

Add the single `desktop-package` job to `.github/workflows/ci.yml` on `windows-latest` that restores locked, builds the desktop app x64 Release, packages it with a generated **development** certificate, runs the packaging and `.appinstaller` validator tests, and uploads the unsigned-for-production MSIX as a build artifact — without disturbing the existing nine jobs. This ticket owns that one packaging lane; the workflow never holds a second.

## Why

Proposal § 21.2 puts "Build the MSIX", "Run packaging/update tests" and "Sign only in the protected release job" in the CI stage list, and the repository has **no publish, sign or deploy lane** today: `.github/workflows/ci.yml` runs `changes`, `documentation`, `local-development-scripts`, `reference-data`, `infrastructure`, `unit`, three `sql-integration` shards, `sql-integration-coverage` and `browser`. Without a packaging lane, a change that breaks MSIX generation is not discovered until a release is attempted. Constraint C-01 makes this lane's runtime a real cost, so it must be gated on the change flag — and it is why three plans naming an overlapping desktop lane must collapse to one: [[DSK-02-15]] proves build and tests and packages nothing, this ticket owns `desktop-package`, and [[DSK-08-13]] extends this job rather than adding a second.

## Guardrails

- **Azure**: no write. The lane authenticates to nothing.
- **Scope boundary**: `.github/workflows/ci.yml`, and `scripts/Get-CiChangeFlags.ps1` / `scripts/Test-CiChangeFlags.ps1` **only in the fallback case step 3 names** — once [[DSK-08-13]]'s `desktop` flag has landed, this ticket touches neither script and gates on the existing output. This ticket owns the `desktop-package` lane and nothing else in the workflow: it must not add or re-add the `desktop-build` lane ([[DSK-02-15]]), and it must not add `desktop-ui-smoke` or `packaging-tests` lanes — [[DSK-08-13]] extends this one job with those. Must not touch `infra/`, `azure.yaml`, or any deployment path — GitHub Actions Azure deployment is recorded as `Not planned` in `docs/runbook.md:903`.
- **Traps**: three plans name an overlapping desktop CI lane ([[DSK-02-15]], [[DSK-08-13]], this ticket) — exactly one lane may exist; reconcile before adding. **One change-flag contract** — [[DSK-08-13]] owns the `desktop` flag in `scripts/Get-CiChangeFlags.ps1` and the matching `changes` job output, and this ticket gates `desktop-package` on it rather than adding a second pattern for `eng/packaging/**`; a second pattern covering the same paths, or one lane gated on two different `changes` outputs by two tickets, is a stop condition, and a lane gated on a flag the classifier never emits never runs at all. The CI runner has **no production certificate** — dev certificate only, and `winapp cert install` (which writes to the machine Trusted Root store) must **not** be used on a shared runner. `--if-exists skip` keeps re-runs from failing on an existing certificate. Chained `dotnet test` commands need `&&` on one line because pwsh reports only the last command's exit code. Private-repository Windows minutes bill at 2× (C-01), so the lane stays change-gated and time-boxed and a duplicate packaging lane bills twice.
