## What

Stand up the update feed decided by **D-003**: a UNC file share on the always-on in-house Windows host, with a permanently stable path, `prod/` and `pilot/` folders, staff-read / publisher-write ACLs, a backup, and a recorded answer to whether `UpdateUris` accepts a UNC fallback.

## Why

Proposal § 9.1 requires an update feed the package layer can check on every launch, and constraint C-01 decided its shape: the repositories become private on completion, App Installer performs plain unauthenticated GETs and cannot send an `Authorization` header, so every GitHub-hosted feed would stop working the day the repository flips. The `.appinstaller` `Uri` is baked into every installed client and re-read on every launch, so the path must be right the first time — changing the host, share or channel folder later forces a reinstall on every workstation. This ticket is the feed's one chance to be permanent.

## Implementation steps

1. Orient: read the § 5 row, `signing-and-hosting-decision-matrix.md` § D-003 in full, `runbooks.md` § R9, and `appinstaller-template.md` § Hosting requirements. Call Kanmer `get_doc_gates` on this ticket id, then `take_ticket`. **D-003 is decided** — build the UNC share; the blob-container acceptance wording still in the § 5 row (`allowBlobPublicAccess`, RBAC, MIME/Range verification) belongs to the withdrawn Azure options and does not apply.
2. Confirm the protocol support on the record: `microsoft_docs_fetch` <https://learn.microsoft.com/windows/msix/app-installer/app-installer-file-overview> and quote the sentence that App Installer downloads and updates support **https, http and smb**. Paste it into the ticket research so the decision is evidenced, not asserted.
3. **Operator step — fix the permanent path.** Choose a DFS namespace or a CNAME'd host, e.g. `\\pegasus-files\apps`, and **never** a raw machine name that may be replaced and **never** a mapped drive letter (mapped drives are per-session and are not guaranteed to exist in App Installer's context). Hand back the agreed UNC root; it is written into every `.appinstaller` `Uri` from then on.
4. **Operator step — create the layout**: `\\<host>\<share>\prod\` and `\\<host>\<share>\pilot\`, each to hold `Pegasus.appinstaller`, the versioned `Pegasus_<ver>_x64.msix` files (at least the previous one retained) and `desktop-release-manifest.json`. Hand back a `Get-ChildItem` listing.
5. **Operator step — set the ACLs**: read and execute for the staff group, modify for the publisher account only, nobody else writes; remove inherited broad grants. Hand back `Get-Acl \\<host>\<share>\prod | Format-List` output. The signing certificate never lives on the share.
6. Write `eng/packaging/Test-FeedShare.ps1` — a verification script run **from a workstation that is not the publisher, signed in as an ordinary staff user**, implementing R9 step 4 exactly: `Test-Path` resolves the channel path; `Select-Xml -Path <path>\Pegasus.appinstaller -XPath /*` shows the expected `Version` and `Uri`; `Get-FileHash` of the package equals `desktop-release-manifest.json`'s `packageSha256`; `Get-Acl` shows the staff group has **no** write permission. Exit non-zero on any failure.
7. Add the publish procedure as `eng/packaging/Publish-DesktopRelease.ps1`, implementing R9 steps 1–2 verbatim in order: copy the new package **first** and the `.appinstaller` **last**, because a client that reads the manifest mid-publish must never find a package that is not there yet — `robocopy <staging> \\<host>\<share>\<channel> Pegasus_<ver>_x64.msix /Z /R:2 /W:5`, then `desktop-release-manifest.json`, then `Pegasus.appinstaller`. Never overwrite a published `.msix` (a new version always means a new file name); only `Pegasus.appinstaller` is replaced in place and its `Version` must increase every time.
8. Resolve the `UpdateUris` caveat and record the answer: `microsoft_docs_fetch` <https://learn.microsoft.com/uwp/schemas/appinstallerschema/element-s4-updateuri> and establish whether a second **UNC** path is accepted as a fallback (the element is documented as "Web URI as a string"). Write the finding into `runbooks.md` § R9 step 6 as a stated fact. If UNC fallbacks are not accepted, state plainly that the feed has **no fallback** and share availability is the single point of failure for updates — acceptable because updates are not time-critical and the gateway gate holds the safety line, but stated rather than assumed.
9. **Operator step — backup**: confirm the share is covered by the host's backup, and record the restore path. A lost share means republishing from the CI artifacts, not a client migration. Hand back the backup job name and last successful run.
10. Rehearse the whole client side on the Test/UAT stack before touching the estate: publish a package to the stack's local file share with `Publish-DesktopRelease.ps1`, install from `\\<stack host>\<share>\teststack\Pegasus.appinstaller`, and confirm an update is detected on relaunch. This is the L-02 rehearsal that must pass before the pilot.
11. Record for the register that **no Azure resource was created**: optionally run Azure MCP `group_resource_list` for `rg-pegasus-prod` read-only and attach the unchanged inventory to the ticket proof, and mirror the "no ⚠ write required" statement in `docs/desktop/11-azure-disposition/README.md`.
12. Record the dated `## Simplification pass` in the ticket plan document over this branch's own diff.

## Guardrails

- **Azure**: no write. D-003 withdrew both blob options; the two existing storage accounts (`infra/modules/platform.bicep:100`, `:154`) are not touched. Read-only inventory calls are permitted with no per-target approval (`docs/runbook.md` § Live-operation approval matrix) and are used only to evidence that nothing changed.
- **Scope boundary**: `eng/packaging/` scripts plus operator configuration of the share host. Must not touch `infra/`, `azure.yaml`, or any Bicep module.
- **Traps**: the `Uri` is baked into every installation — changing host name, share name or channel folder breaks updates for every existing installation and forces a reinstall. Copy order matters: package first, manifest last. Never overwrite a published `.msix`. Off-network clients simply do not check for updates until they are back on the LAN or VPN — do not raise the gateway minimum version while a pilot user is known to be away, or they are locked out of work until they return. MIME types, `Content-Length` and byte ranges are HTTP-only concerns and do not apply over SMB — do not build header checks. GitHub Releases and Pages are permanently excluded by C-01 and must not be re-proposed.
- **Stale row wording**: the § 5 acceptance text for this row predates the decision and still mentions blob public access and MIME verification. Follow D-003 and correct the row's wording in the plan in the same task.
- **Operator-only**: share provisioning, DFS/CNAME naming, ACL assignment and backup configuration require administrative access to the in-house host and the directory service. An agent writes and tests the scripts; the operator performs the provisioning and hands back the evidence.
- **Simplification pass** (`AGENTS.md` step 4): required over this branch diff before the PR, recorded under a dated `## Simplification pass` heading in the plan document.
