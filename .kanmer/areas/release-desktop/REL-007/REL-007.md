## What

Issue the production code-signing certificate decided by **D-002** — self-managed, subject equal to the manifest `Publisher`, ~3-year validity, private key on the signing host under a restricted ACL — export the public `.cer`, prove the trust rollout on two machines, then roll it to the ten-workstation estate, recording whether the mechanism is a scripted `Import-Certificate` or Group Policy Trusted People.

## Why

Proposal § 9.1 requires a **signed** package, and § 17.1 requires a code-signing certificate protection and renewal runbook. D-002 (2026-08-23) settled the route: a self-managed certificate held in-house, because the estate is ten known Windows 11 machines on one network behind a private UNC feed (D-003), so nothing a public CA sells has anyone to serve. The whole distribution path therefore touches no Azure resource. The price is exactly this ticket: trust must reach every machine **before** any package signed with the certificate does, or the install fails with `0x800B0109` and the user is stuck.

## Implementation steps

1. Orient: read the § 5 row, `signing-and-hosting-decision-matrix.md` § D-002 in full, and `runbooks.md` § R5 and § R7. Call Kanmer `get_doc_gates` on this ticket id, then `take_ticket`. D-002 is **decided** — write and execute the self-managed route only; do not re-open Artifact Signing or an OV certificate, whose spikes [[DSK-09-07]] and [[DSK-09-09]] were withdrawn.
2. Fix the subject string once and for all. It must equal `Package.appxmanifest` `Identity/@Publisher` **exactly — same fields, same order, same spacing and case** — or signing fails with `0x8007000B` (AppxPackagingOM Event ID 150). Read the current value from `src/Pegasus.Desktop/Package.appxmanifest` and paste it into the ticket plan as the canonical string; it is never changed afterwards, because changing it changes the package identity.
3. Confirm the issuance command against official documentation before running it: `microsoft_docs_search` for `create a certificate for package signing New-SelfSignedCertificate code signing MSIX`, then `microsoft_docs_fetch` the resulting page. The documented shape is `New-SelfSignedCertificate -Type Custom -Subject "<publisher>" -KeyUsage DigitalSignature -FriendlyName "Pegasus desktop code signing" -CertStoreLocation "Cert:\LocalMachine\My" -TextExtension @("2.5.29.37={text}1.3.6.1.5.5.7.3.3", "2.5.29.19={text}")`; add `-NotAfter (Get-Date).AddYears(3)` for the ~3-year validity D-002 fixes. Do not run it from memory — verify the flags first.
4. **Operator step** — on the signing host (the always-on in-house machine that also serves the D-003 share), run the verified command elevated. Hand back: the thumbprint, the subject, `NotBefore`/`NotAfter`, and the machine name. The private key is generated on that host and never generated anywhere else.
5. **Operator step** — export and protect the key: `Export-PfxCertificate -Cert Cert:\LocalMachine\My\<thumbprint> -FilePath <secure path>\PegasusCodeSigning.pfx -Password (Read-Host -AsSecureString)`, then restrict the file ACL to the publisher account only (`icacls <path> /inheritance:r /grant "<publisher account>:(R)"`). Hand back the `icacls` output. The `.pfx` never leaves this host, is never committed, and is **never** stored as a GitHub secret.
6. **Operator step** — export the public certificate only: `Export-Certificate -Cert Cert:\LocalMachine\My\<thumbprint> -FilePath .\PegasusCodeSigning.cer -Type CERT`. Only this `.cer` reaches a workstation.
7. Write `eng/packaging/Install-ProductionCertificateTrust.ps1`: elevated, takes `-CertificatePath` and `-ExpectedThumbprint`, runs `Import-Certificate -FilePath <cer> -CertStoreLocation Cert:\LocalMachine\TrustedPeople`, then `certutil -verifystore TrustedPeople` and fails unless the expected thumbprint is listed. **`TrustedPeople`, never `Trusted Root Certification Authorities`** — a root grant would let that key vouch for anything the machine trusts, which the MSIX troubleshooting guide explicitly warns against and which ten machines do not need.
8. **Operator step — prove the ordering on two machines.** On machine A: run the trust script, confirm `certutil -verifystore TrustedPeople` lists the thumbprint, then sign a test package with the new certificate (`winapp package <dir> --cert PegasusCodeSigning.pfx --self-contained --timestamp <timestamp url>`) and install it. On machine B: attempt the install **first**, record the exact failure (expected `0x800B0109`), then run the trust script and retry successfully. Hand back both transcripts — machine B's failure is the evidence that R5 and R7 must push trust before publishing.
9. Verify every signature is timestamped: `signtool verify /pa /v <pkg>.msix` must report both a valid chain and a timestamp. Without `--timestamp`/`/tr`, installed packages stop validating for new installs the day the certificate expires.
10. **Operator step — decide and record the estate mechanism.** Choose between (a) the scripted elevated `Import-Certificate` per machine, or (b) Group Policy → Computer Configuration → Windows Settings → Security Settings → Public Key Policies → **Trusted People**, if the estate is domain-joined. Record which applies, why, and the machine list in the ticket plan; GPO is only available if the machines are domain-joined, which is a fact to establish, not assume.
11. **Operator step** — roll trust to the remaining workstations with the chosen mechanism and hand back a per-machine confirmation (machine name, date, `certutil -verifystore TrustedPeople` thumbprint line). Trust reaches every machine before [[DSK-09-11]] publishes the first signed package.
12. Write up the renewal and revocation rehearsal that R5 will formalise: same subject on re-issue, overlap window, new trust pushed before the first signature, old `.cer` removed only after every machine is confirmed, and the fact that **there is no revocation list in a private-trust estate — removing trust is the revocation**. Hand the write-up to [[DSK-09-14]], which owns R5 and R6.
13. Record the certificate facts for the release record: thumbprint, subject, validity window, signing host, rollout date, confirmed machines. [[DSK-09-18]] puts them in `docs/operations.md`.
14. Record the dated `## Simplification pass` in the ticket plan document over this branch's own diff.

## Acceptance criteria

- [ ] A production code-signing certificate exists with subject exactly equal to `Identity/@Publisher`, ~3-year validity, private key generated on and confined to the signing host with a restricted ACL.
- [ ] Only the public `.cer` is distributed; the `.pfx` is not committed, not copied to the share, and not a GitHub secret.
- [ ] Trust is installed in `Cert:\LocalMachine\TrustedPeople` — not `Trusted Root` — and verified by thumbprint on each machine.
- [ ] The trust-before-package ordering is proven: machine B reproduced `0x800B0109` before trust and installed after it.
- [ ] Every test signature is timestamped and `signtool verify /pa /v` reports a valid chain and timestamp.
- [ ] The estate mechanism (scripted `Import-Certificate` or GPO Trusted People) is decided, recorded and applied to every workstation.

## Verification

- [ ] `certutil -verifystore TrustedPeople` on each workstation — expected: the production thumbprint listed, once per machine.
- [ ] `signtool verify /pa /v .\Pegasus_<ver>_x64.msix` — expected: `Successfully verified`, a chain terminating at the self-managed certificate, and a timestamp line.
- [ ] `Add-AppxPackage .\Pegasus_<ver>_x64.msix` on a trusted machine — expected: succeeds; on an untrusted machine — expected: fails with `0x800B0109`.
- [ ] `icacls <pfx path>` on the signing host — expected: only the publisher account has read access; inheritance removed.

## Guardrails

- **Azure**: no write. D-002 explicitly withdrew the Artifact Signing and Key Vault certificate routes; Key Vault `pegasusprodkv252ow37g` is not touched. Read-only Azure calls are permitted but not needed.
- **Scope boundary**: `eng/packaging/` scripts and operator actions on the signing host and workstations. Must not touch `infra/`, `src/Pegasus.Web`, or the gateway release route.
- **Traps**: certificate expiry without timestamping invalidates the signature path for new installs — timestamp every signature. A Publisher/subject mismatch breaks packaging (`0x8007000B`). Trust in `Trusted Root` instead of `TrustedPeople` is a materially broader grant and is forbidden by D-002. The signing host concentrates the share, the CI runner and the private key — that is the design's main operational risk; restrictive ACLs, a backup of the certificate, and a documented rebuild path belong in R9 and the security plan. SmartScreen may warn on the first download of a new package hash; that is reputation, not a signature failure.
- **Operator-only**: certificate issuance, key export, ACL setting, and the per-machine trust rollout are operator actions requiring elevated access to the signing host and physical or remote access to each workstation. An agent prepares the scripts and the evidence template; it does not perform them.
