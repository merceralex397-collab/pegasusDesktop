## What

Build the shared tabular pattern the desktop reuses on every list screen: a virtualized `ListView` with a `Grid`-based `ItemTemplate` and a header `Grid` acting as sort controls, `ComboBox` filters, newest-first default order, 32px rows, keyboard navigation and a locally persisted column chooser.

## Why

WinUI has no `DataGrid`, and the CommunityToolkit `DataGrid`'s columns cannot use `x:Bind` (`.codex/skills/winui-design/SKILL.md` § Reach-for-this control map) — picking it would be an unrecoverable dead end for binding and testability. The authority also fixes the interaction rules: filters are dropdowns not pill rows, tables sort newest first, headers are sort controls (`docs/design/README.md:422-445`). Operator-visible consequence: every queue, case list and document list behaves identically and stays keyboard-operable at 2,000 rows. Consumed by [[DSK-05-01]], [[DSK-05-02]] and every list screen.

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/screen-specs.md` § Queues and § Cases list and search, and `docs/desktop/06-ui-design/keyboard-and-accessibility.md` § Keyboard map. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`, and run `.codex/skills/winui-design/winui-search.exe` for `ListView` header and virtualization guidance before writing XAML. Do **not** add `CommunityToolkit.WinUI.Controls.DataGrid` to the project.
3. Create `src/Pegasus.Desktop/Controls/DataTable/` holding: `DataTableHeader` (a `Grid` of header buttons), the shared `ItemContainerStyle` fixing row height to `{StaticResource PegasusTableRowHeight}` (32), and a `ColumnDefinitionSet` type so header and row share one column definition list — duplicated column widths are the usual cause of drift between header and rows.
4. Each header cell is a semantic `Button` (never a clickable `Border`), styled with `PegasusBodyStrongTextStyle`, showing a sort glyph when it is the active sort. Its `AutomationProperties.Name` states the column and direction, e.g. `Received, sorted descending`, so the sort state is announced (`docs/desktop/06-ui-design/keyboard-and-accessibility.md` § Accessibility checklist). Default order is newest first.
5. Wire sorting and paging to the server: a header click raises a sort request the view model turns into the list endpoint's sort parameters; paging uses the gateway's paged envelope. Render accessible current-page context and keyboard-operable next/previous controls (`docs/design/README.md:600-604`). Never sort or page a full local collection.
6. Filters are `ComboBox` controls in a filter row above the table — not pill tabs, not a toggle strip. Each carries an `AutomationId` of the form `<Screen>.List.Filter.<Name>` per `screen-specs.md` § AutomationId convention.
7. Keyboard: `↑`/`↓` move rows, `Home`/`End` jump, `PageUp`/`PageDown` page, `Enter` and double-click open the selected record, `Space` toggles selection, `Shift+F10`/`Menu` opens a row context menu that duplicates only genuinely useful commands, and `Alt+↑`/`Alt+↓` move between the header row and the first data row. Selection must survive virtualization recycling.
8. Column chooser: a flyout listing the screen's columns with checkboxes, persisted per table in local preferences (`docs/desktop/06-ui-design/screen-specs.md` § Diagnostics and settings — grid column layouts per table are a local preference). Persist to the desktop's local settings store from `DSK-02-07`, never to the gateway.
9. Virtualization: keep the default `ItemsStackPanel` virtualization intact — do not wrap the `ListView` in a `ScrollViewer`, do not set `Height="Auto"` on it, and do not use `x:Phase` unless the perf check demands it (see `.codex/skills/winui-code-review/references/quality-rules.md` § Collection Virtualization).
10. Binding correctness: every row binding uses `x:Bind` with `Mode=OneWay` where the value changes (`x:Bind` defaults to `OneTime`). Never write `Converter={x:Null}` — it compiles and then crashes at runtime; omit the property instead. Prefer `x:Bind` static functions over `IValueConverter`.
11. Build and run: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`. Add a table sample to the gallery page from [[DSK-06-02]] with a 2,000-row in-memory source for the performance check only.
12. Load `winui-ui-testing` and write `tests/Pegasus.Desktop.UITests/datatable-tests.ps1` covering: header click toggles sort and the accessible name updates; a filter `ComboBox` change re-queries; `↓` then `Enter` opens a record; `Alt+↑` reaches the header; the column chooser hides and restores a column across a restart.
13. Performance check on the 2,000-row sample: scroll from top to bottom and back, recording frame behaviour and memory; compare against the budgets in `docs/desktop/10-security-observability-performance/README.md`. Report a regression plainly rather than tuning blind.

## Acceptance criteria

- [ ] Tabular data uses `ListView` + `Grid` item template + header `Grid`; no CommunityToolkit `DataGrid` reference exists in the solution.
- [ ] Rows are 32px; headers are sort controls with accessible sort state; default order is newest first.
- [ ] Filters are `ComboBox` dropdowns, not pill rows; each has an `AutomationId`.
- [ ] Full keyboard navigation works, selection survives virtualization, and the row context menu duplicates only useful commands.
- [ ] The column chooser persists locally per table and restores across a restart.
- [ ] Sorting, filtering and paging are served by the gateway; the client never holds the whole dataset.
- [ ] A 2,000-row list scrolls without a perceptible stall and stays within the recorded memory budget.
