## What

Add a `ReasonDialog` built on `ContentDialog` that implements the authority's reason-dialog contract: a named requirement as the title, the record identity and an approved consequence sentence in the body, a labelled reason box, a verb-labelled primary button and Cancel, initial focus on the reason box, focus containment, Escape where safe, and focus return to the invoking control.

## Why

`docs/design/README.md:622` states the contract, and the desktop's reasoned lifecycle actions (Hold, Block, Unlink, Close with outcome, Reopen with reason) all route through it. Proposal § 14.8 restricts `ContentDialog` to decisions that require interruption. Operator-visible consequence: a destructive action always names what it affects and never confirms on a stray Enter. Consumed by [[DSK-05-06]], [[DSK-05-09]], [[DSK-05-11]] and every reasoned command.

## Implementation steps

1. Orientation. Read the plan row, `docs/design/README.md:622` and `:400-409`, and `src/Pegasus.Web/Pages/Shared/_ReasonDialog.cshtml`. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. Search `microsoft_docs_search` for `ContentDialog.XamlRoot` and `ContentDialog.DefaultButton` — a WinUI 3 `ContentDialog` shown without `XamlRoot` throws, and the default button choice is the safety mechanism in step 6.
3. Add `src/Pegasus.Desktop/Controls/ReasonDialog.xaml(.cs)` deriving from `ContentDialog`, with parameters: `Requirement` (the title — a named requirement, e.g. `Block received item`), `Identity` (the record identity line, e.g. `Case/PO 576059 · EJ17 NBZ`), `Consequence` (nullable — rendered only when supplied), `ReasonLabel`, and `PrimaryVerb`.
4. `Consequence` accepts only a sentence from the closed necessary-copy list at `docs/design/README.md:400-409`. Enforce it: a `ConsequenceCopy` static class holding those exact sentences (with the `<reference>` placeholder substituted at call time), and a unit test that fails if a caller passes a string not produced by that class. Where an action has no approved consequence sentence, the slot is absent — do not write one.
5. Body layout: identity line, the consequence sentence when present, then the labelled reason `TextBox` (`AutomationId` `Dialog.Reason.Text`) using the field pattern from [[DSK-06-08]] — label and control only, no hint. Primary button `Dialog.Reason.Confirm` carries the verb (`Block`, `Unlink`, `Hold`), secondary `Dialog.Reason.Cancel` carries `Cancel`.
6. Set `DefaultButton="Close"` for destructive actions so `Enter` never destroys (`tokens-and-theme.md` § Control styles). Escape closes only where closing is safe — i.e. where cancelling leaves no partial state; where it is not safe, handle `Closing` and cancel the Escape path, and say so on the control rather than silently swallowing the key.
7. Focus: set initial focus to the reason box on `Opened`; `ContentDialog` contains focus by default — verify it rather than assuming; on close, return focus to the invoking control (capture it in the dialog service before showing).
8. Never use `ContentDialog` for routine information (proposal § 14.8). Add a review note in the plan naming the only permitted uses: reasoned commands, destructive confirmations, and the discard-changes confirmation from the Case workspace.
9. Add view-model tests in `tests/Pegasus.Desktop.ViewModelTests`: `PrimaryIsDisabledUntilAReasonIsEntered`, `ConsequenceMustComeFromTheApprovedList`, and `CancelReturnsNoResultAndMutatesNothing`.
10. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; add a launcher to the gallery page from [[DSK-06-02]].
11. Load `winui-ui-testing` and write `tests/Pegasus.Desktop.UITests/reasondialog-tests.ps1`: invoke the launcher, `search` for the dialog buttons (`ContentDialog` buttons often lack custom ids — use `inspect` to find the actual selector), assert initial focus is `Dialog.Reason.Text`, send `Enter` and assert nothing was confirmed, send `Escape` and assert the dialog closed and focus returned to the launcher, then type a reason and invoke the primary.
12. Narrator smoke: confirm the dialog title (the named requirement), the identity and the consequence sentence are all announced on open, and that focus cannot leave the dialog with `Tab`.

## Acceptance criteria

- [ ] Title is a named requirement; body carries the record identity and, only where one exists, an approved consequence sentence from the closed list.
- [ ] The reason field is labelled with no hint text; the primary button carries the action's verb; the secondary is `Cancel`.
- [ ] `DefaultButton=Close` for destructive actions — `Enter` does not confirm.
- [ ] Initial focus is the reason box; focus is contained; Escape closes only where safe; focus returns to the invoking control.
- [ ] A consequence string outside the approved list fails a test.
- [ ] The dialog is never used for routine information.
