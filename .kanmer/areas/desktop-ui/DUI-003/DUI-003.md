## What

Convert the sixteen SHA-256-pinned Lucide glyphs into `src/Pegasus.Desktop/Styles/Icons.Lucide.xaml`, ship the commissioned raster marks as decorative assets, and copy the approved logo into the desktop project with a unit test that verifies its SHA-256 against the value recorded in the design authority.

## Why

Lucide is the only approved icon system (`docs/design/README.md:334-345`) and the logo may never be redrawn, recoloured or extracted from a screenshot (`:317-322`). A desktop that substitutes Segoe Fluent Icons would introduce a second icon set the authority does not register. Operator-visible consequence: chips, provenance glyphs and the rail carry the same marks the operator already knows from the web. Consumed by [[DSK-06-06]], [[DSK-06-11]] and the shell [[DSK-06-04]].

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/tokens-and-theme.md` § Icons, marks and logo, and `docs/design/README.md:296-380`. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Verify the source assets before converting anything: `Get-FileHash -Algorithm SHA256 src/Pegasus.Web/wwwroot/images/lucide-sprite.svg` must equal `C81F067708B5EF1C2CEDABF4A38BADC175A11DEFE7919DA69192100EE6922BF1`, and `Get-FileHash -Algorithm SHA256 docs/design/brand/logos/logo_no_margin.png` must equal `E7247BE45911C46905343473E4C57B9F6ED7A450563D19C508C2D9652C2C63E2`. A mismatch stops the ticket — report it, do not proceed.
3. Decide and record the stroke method. `PathIcon` fills its geometry, and Lucide glyphs are 2px strokes on a 24×24 viewBox, so a raw copy renders wrong. `tokens-and-theme.md` § Icons, marks and logo names the two permitted options: (a) convert each stroked path to an outlined path and use `PathIcon`, or (b) use a `Path` with `Stroke="{ThemeResource ...}"`, `StrokeThickness="2"`, `StrokeLineJoin="Round"`, `StrokeStartLineCap`/`StrokeEndLineCap="Round"` inside a 24×24 `Viewbox`. Pick the one that preserves the glyph shape, prove it on `alert-triangle` and `refresh-cw` side by side against the web rendering, and record the choice and the comparison in the ticket plan. Search `microsoft_docs_search` for `PathIcon` versus `Path` stroke rendering in WinUI 3 if the behaviour is unclear.
4. Create `src/Pegasus.Desktop/Styles/Icons.Lucide.xaml` holding one resource per glyph, keyed `PegasusIcon<PascalName>` for all sixteen: `search`, `user`, `refresh-cw`, `clock`, `calendar`, `check-circle`, `alert-triangle`, `alert-circle`, `info`, `file-text`, `filter`, `shield`, `chevron-right`, `arrow-right`, `upload`, `lock`. Geometry comes from the pinned sprite — do not redraw, do not fetch from the internet, do not substitute a Segoe Fluent Icons glyph.
5. Merge `Icons.Lucide.xaml` into `src/Pegasus.Desktop/Styles/Pegasus.Theme.xaml` in the position `tokens-and-theme.md` § Files and load order gives it (after `Tokens.Focus.xaml`, before the `Controls.*.xaml` set).
6. Copy the logo master byte-for-byte to `src/Pegasus.Desktop/Assets/logo_no_margin.png` and copy the ten in-use raster marks from `src/Pegasus.Web/wwwroot/images/marks/` to `src/Pegasus.Desktop/Assets/marks/`. Mark every raster asset `AutomationProperties.AccessibilityView="Raw"` at its usage sites — they are decorative and carry no accessible name.
7. Add `tests/Pegasus.Desktop.ViewModelTests/BrandAssetChecksumTests.cs` with two facts: `LogoMatchesTheDesignAuthorityChecksum` compares the SHA-256 of `src/Pegasus.Desktop/Assets/logo_no_margin.png` with the literal `E7247BE45911C46905343473E4C57B9F6ED7A450563D19C508C2D9652C2C63E2`, and `GlyphGeometryMatchesTheRecordedSourceHash` records, per glyph key, the SHA-256 of the source glyph fragment taken from the pinned sprite. Done looks like: both tests green, and the first fails if the asset is recompressed or recoloured.
8. Add a review guard: extend the guard test from [[DSK-06-01]] (or add a sibling) that fails on any `FontIcon`, `SymbolIcon` or `FontFamily="Segoe Fluent Icons"` in `src/Pegasus.Desktop/**/*.xaml`, so an unregistered icon cannot slip in. A new icon requires a new registered glyph in `docs/design/README.md` first (`:370`).
9. Build and run: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`. Add the sixteen glyphs and the logo to the gallery page from [[DSK-06-02]] if it has landed; otherwise render them on a temporary page for the comparison.
10. Visual compare: screenshot the sixteen desktop glyphs and place them beside the same glyphs rendered by `src/Pegasus.Web/Pages/Shared/_LucideSprite.cshtml` in the running web app. Every glyph must match in shape, stroke weight and cap/join style at 16px and 24px. Attach the comparison image to the ticket.
11. Confirm forced-colours behaviour: in a Windows Contrast theme the glyphs must take the system foreground (they are `Foreground`-driven, per `.codex/skills/winui-design/references/theme-accessibility.md` § High Contrast rules — hard-coded fills disappear). Screenshot as evidence.
