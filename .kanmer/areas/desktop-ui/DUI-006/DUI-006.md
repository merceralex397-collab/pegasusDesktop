## What

Add one `StatusChip` control to `src/Pegasus.Desktop/Styles/Controls.StatusChip.xaml` that pairs a tone, a Lucide glyph and a text label, selecting the tone from the same status vocabulary the web uses, so no state in the desktop is ever conveyed by colour alone.

## Why

The authority makes the status chip "the single place a business or query state selects its tone and Lucide glyph; always paired with its text label" (`docs/design/README.md:594`), with amber for incomplete/pending, navy for Review, green for confirmed completion only (`:164-165`, `:200`). Proposal § 14.4 says badges carry text, not colour alone. Operator-visible consequence: a chip's meaning survives forced colours, greyscale printing and a screen reader. Consumes [[DSK-06-01]] and [[DSK-06-03]]; consumed by [[DSK-06-07]], [[DSK-06-12]] and every slice.

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/tokens-and-theme.md` § Control styles (shared), and `src/Pegasus.Web/Pages/Shared/_StatusChip.cshtml` end to end — the switch in that file is the vocabulary, not a paraphrase of it. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. The chip is a templated `Control`, not a clickable `Border` — the `winui-code-review` accessibility checklist rejects semantic-free containers.
3. Add `src/Pegasus.Desktop/Controls/StatusChip.cs` with three dependency properties: `Text` (string, the operator label, rendered verbatim — the control never rewrites the caller's words), `Tone` (enum `Neutral`, `Pending`, `Review`, `Success`, `Blocked`), and `Count` (int?, appended in brackets only when the text carries no digit, matching the web partial's rule).
4. Put the tone selection in **one** place: a static method on the shared vocabulary side, taking the humanised state string and returning `(Tone, glyphKey)`. Reproduce the switch from `_StatusChip.cshtml` exactly — same keys, same tones, same glyphs. Where the web maps a state to `red`, the desktop `Tone` is `Blocked`. Do not add a state the web does not have, and do not drop one.
5. Add `src/Pegasus.Desktop/Styles/Controls.StatusChip.xaml` with the default `Style`/`ControlTemplate`: a `Border` using `ControlCornerRadius` (2) and `PegasusBorderThickness` (1), containing the glyph (`AutomationProperties.AccessibilityView="Raw"` — the text carries the meaning) and a `TextBlock` with `PegasusBodyTextStyle`. Background, foreground and border brushes come from the `Tone` via `{ThemeResource}` keys only.
6. Merge `Controls.StatusChip.xaml` into `src/Pegasus.Desktop/Styles/Pegasus.Theme.xaml` in the `Controls.*.xaml` position defined by `tokens-and-theme.md` § Files and load order.
7. Accessibility: the chip exposes its text through `AutomationProperties.Name` (set from `Text` plus the count when present) so a screen reader reads the state; the glyph is never the only carrier. Set `AutomationId` at each usage site, not on the control default (ids must be unique per window).
8. Add `tests/Pegasus.Desktop.ViewModelTests/StatusChipVocabularyTests.cs`: a theory over every key in the web switch asserting the desktop returns the same tone and glyph, and a fact asserting the tone rules hold — green appears only for confirmed-completion states (`completed`, `post report completion`, `success`), never for progress or availability (`docs/design/README.md:200`).
9. Render all five tones on the gallery page from [[DSK-06-02]] and build/run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`.
10. Confirm contrast: measure each tone's foreground/background pair in Light and Dark against 4.5:1 for the chip text; under a Windows Contrast theme every chip must remain distinguishable by text and glyph. Attach the measurements and the three screenshots.

## Acceptance criteria

- [ ] Only the tones the authority allows exist: neutral, amber (pending/incomplete), navy (Review and in-flight), green (confirmed completion only), red (blocked/failed/denied).
- [ ] Text is always present and rendered verbatim; the control never rewrites the caller's words.
- [ ] The tone/glyph table lives in exactly one place shared with the web vocabulary; a state added on one side is visible on the other.
- [ ] Every chip usage site carries an `AutomationId`; the accessible name includes the state text and count.
- [ ] Contrast passes in Light and Dark; chips stay distinguishable under forced colours.
