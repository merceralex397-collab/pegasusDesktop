## What

Implement the authenticated shell exactly as `docs/desktop/06-ui-design/screen-specs.md` § Shell (§14.2) specifies: a fixed 236px `NavigationView` rail in the authority's route order, rail counts sourced only from the dashboard query, a title bar with logo, environment badge, connection and version, and a status bar; content region capped at 1280 and centred.

## Why

The shell is the frame every other screen renders inside, and the authority fixes its rail width, route order and selection signalling (`docs/design/README.md:65-96`, `:461-504`). Proposal § 14.2 differs (it lists Intake/Documents/Reports/Settings and a title-area global search); the area plan records the authority as winning. Operator-visible consequence: the desktop's navigation is the one the operator already uses, and a shell-level `0` count — the stale placeholder the authority forbids — never appears. Consumed by every slice ticket in plan 05.

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/screen-specs.md` § Shell (§14.2) in full, and `docs/design/README.md:461-504` and `:582-600`. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. Confirm the control choice against its reach-for-this-control map (2–7 sections → `NavigationView`) and use `microsoft_docs_search` for `NavigationView` selection-indicator restyling before writing XAML.
3. In `src/Pegasus.Desktop/Views/ShellPage.xaml` set the `NavigationView` to `PaneDisplayMode="Left"`, `OpenPaneLength="{StaticResource PegasusRailWidth}"` (236) and `IsPaneToggleButtonVisible="False"` — the authority's rail never hides. Set `IsSettingsVisible="False"`; Diagnostics/Settings is reached from the user menu, not the rail.
4. Add the rail items in exactly this order, with these `AutomationId`s: `Shell.Rail.Dashboard`, `Shell.Rail.Inbox`, `Shell.Rail.Upload`, `Shell.Rail.Queues`, `Shell.Rail.Cases`, `Shell.Rail.Operations`, `Shell.Rail.Administration`. `Administration` is **present only** for the Administrator role and `Inbox` **only** when the capability is composed — in both cases absent, never disabled (`docs/design/README.md:584`). Set `AutomationProperties.LandmarkType="Navigation"` on the pane.
5. Restyle the selection indicator so the current item shows a weight change **plus** a 2px `PegasusAccentBrush` left marker; never colour alone. Verify the accessible state still reports selection (`winapp ui get-property` on the selected item).
6. Rail counts: bind each count to the dashboard rail-counts query result. When the query has not returned, the count element is **absent** — do not render `0`, `—` or a placeholder. `0` renders only when the query returned zero. Add a view-model test `RailCountIsAbsentUntilTheQueryReturns` proving it.
7. Title bar: extend into the client area, place the checksummed logo asset from [[DSK-06-03]], the environment badge (`Shell.Title.Environment` — rendered only for `Pilot`, `Test/UAT`, `Development`), the connection glyph plus word, version and channel, and the user menu (`Shell.Title.User`) with Change password, Sign out, Diagnostics. Keep a working drag region.
8. Status bar: `Shell.Status.Connection`, last sync time formatted Europe/London through the shared label map ([[DSK-06-05]]), a background-transfer summary that opens the transfer pane, and `Shell.Status.Update`. Set `AutomationProperties.LandmarkType="Custom"` with name `Status`, and make connection changes a Polite live region only.
9. Content region: host the frame in a `Grid` whose content column has `MaxWidth="{StaticResource PegasusContentMaxWidth}"` (1280), centred, with 24px gutters (`PegasusGutter`). Below 1280 effective width the layout reorders secondary content rather than clipping (`docs/design/README.md:279`). Do not use `SizeToContent` — WinUI 3 has none (`winui-design` § Window sizing).
10. Shell states from the spec: authenticated (this shell); unauthenticated (the login screen replaces the shell); update-required and blocked (full-window, no rail); disabled account; stale role. Implement the switch so a full-window state genuinely removes the rail rather than disabling it. Disconnected shows "Disconnected — reconnecting" in the status bar with saves disabled and existing content still visible.
11. Backdrop: solid `PegasusGroundBrush`. Mica is permitted only behind the title bar and rail and only if the contrast review passes (`docs/desktop/06-ui-design/README.md` § 3, Surfaces and backdrop). Default to no backdrop and record the decision.
12. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; capture the PID. Load `winui-ui-testing` and write `tests/Pegasus.Desktop.UITests/shell-tests.ps1` asserting: each rail item exists by `AutomationId`, the order matches, `Shell.Rail.Administration` is absent for a non-admin session, `Tab` traversal order is title bar → rail → page header → content → status bar, and `F6` cycles the regions.
13. Run the AutomationId coverage audit from `winui-ui-testing` (`winapp ui inspect -a <PID> --interactive --json`, filter to app elements, assert none is missing an `automationId`) and screenshot the shell at 1280 and at 1024 effective width.

## Acceptance criteria

- [ ] Rail order is Dashboard → Inbox → Upload → Queues → Cases → Operations → Administration; pane width 236; no pane toggle.
- [ ] `Administration` is absent (not disabled) for non-admins; `Inbox` is absent when the capability is not composed.
- [ ] Counts render only from the dashboard rail-counts query; a shell-level `0` never appears for an unqueried count.
- [ ] The current route is signalled by weight **and** a 2px red left marker, never colour alone, and the accessible selection state is correct.
- [ ] Environment badge appears only outside production; status bar shows connection, last sync (Europe/London), transfers and update availability.
- [ ] Content region is capped at 1280 and centred with 24px gutters.
- [ ] Every interactive shell control has a unique `AutomationId` from `screen-specs.md` § AutomationId convention; rail, content and status bar carry landmarks.
