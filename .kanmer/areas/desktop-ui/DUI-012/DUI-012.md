## What

Add the shared page header — one title, the exact queue or filter it shows, the last-good Europe/London time, the current refresh state and at most one primary action, with no lede — together with the manual-refresh control that reruns the same filter, gives start and completion feedback, keeps last-good data visible and is protected against double submission.

## Why

The authority makes freshness and manual refresh an exercised component with an exact contract (`docs/design/README.md:590`, `:487-495`), and forbids a lede or an introductory sentence under a heading (`:422-445`). Operator-visible consequence: every screen states what it is showing, how old it is and whether the last refresh worked — and a `0` is only ever a current result, never a stand-in for stale or unavailable. Consumed by every screen in plan 05.

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/screen-specs.md` rules preamble and § Cross-cutting state contract, and `src/Pegasus.Web/Pages/Shared/_FreshnessBanner.cshtml` in full. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. Add `src/Pegasus.Desktop/Controls/PageHeader.xaml(.cs)` with: `Title` (rendered once, `PegasusPageTitleTextStyle`, `AutomationProperties.HeadingLevel="Level1"`), `Scope` (the exact queue or filter shown, e.g. `Review · all principals`), a freshness area, and a single optional `PrimaryAction`.
3. There is **no** lede, subtitle, eyebrow or description property. Do not port the eyebrow/lede slots from `_PageHeader.cshtml`. One H1-equivalent per screen — add a review assertion that a page declares exactly one `PageHeader`.
4. Freshness: render the last-good time through the Europe/London formatter from [[DSK-06-05]] and one refresh-state word from the closed set `current`, `loading`, `stale`, `partial`, `unavailable`, `failed`. Follow the web's economy: a loaded query says so by showing its number and its time, so only non-current states earn a `StatusChip` ([[DSK-06-06]]).
5. Manual refresh (`AutomationId` `<Screen>.Refresh`): reruns the **same** filter and page, keeps last-good data visible while running, and gives start and completion feedback. Never clears the screen to a spinner, and never claims an external action succeeded.
6. Double-submit protection: disable the refresh command while a refresh is in flight and cancel the previous request if the operator retriggers; add a view-model test `RefreshCannotBeSubmittedTwice`.
7. Progress: a thin indeterminate `ProgressBar` at the top of the content region or in the status bar — never a full-page or ring spinner (`docs/desktop/06-ui-design/README.md` § 3, Motion). Honour `UISettings.AnimationsEnabled == false` by substituting a static `Working` text equivalent; add no other animation and invent no duration or easing tokens.
8. Primary action: at most one per view region, styled `AccentButtonStyle`. Add a review assertion (and, where feasible, a test over the visual tree) that a page region never renders two accent buttons.
9. Bind `F5`/`Ctrl+R` to the same refresh command so the keyboard path and the control path are one implementation ([[DSK-06-14]] owns the accelerator registration; expose the command here).
10. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; render a header with each of the six refresh states on the gallery page from [[DSK-06-02]].
11. Load `winui-ui-testing` and write `tests/Pegasus.Desktop.UITests/pageheader-tests.ps1`: invoke refresh and assert the state word moves `current` → `loading` → `current` while the previously loaded rows stay on screen; invoke it twice rapidly and assert only one request ran; force a failure and assert the state word becomes `failed` with the last-good time still shown.
12. Confirm the reduced-motion path: disable animations in Windows, rerun the refresh test, and screenshot the static `Working` equivalent.
