## What

Add the shared form section and field pattern to `src/Pegasus.Desktop/Styles/Controls.Field.xaml`: a field is a label and a control, the required state is a marker on the label with the accessible name `required`, and validation text sits under the control, associated with it and announced once.

## Why

The authority's first hard rule is "a field is a label and a control, nothing more — no hint sentence, no 'Required.'/'Optional.' text, no format guidance" (`docs/design/README.md:422-445`), bound to every UI change by `AGENTS.md:171-178`. A UI that explains itself is a defect. Operator-visible consequence: forms are scannable and a screen reader hears the label, the required state and the error without prose. Consumed by [[DSK-05-04]] (Case create), [[DSK-05-05]] (Case edit), [[DSK-05-21]] (Change password) and every Administration form.

## Implementation steps

1. Orientation. Read the plan row, `docs/design/README.md:422-445` and `:774-808`, and `docs/desktop/06-ui-design/keyboard-and-accessibility.md` § Accessibility checklist. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design` and `winui-code-review`. Search `microsoft_docs_search` for `AutomationProperties.LabeledBy` and `AutomationProperties.DescribedBy` in WinUI 3 before wiring the associations — get the attached-property syntax right the first time (they are static setters from C#, never object-initializer members).
3. Add `src/Pegasus.Desktop/Controls/FormField.cs`, a templated `Control` with `Label` (string), `IsRequired` (bool), `ValidationMessage` (string?) and a `Content` presenter for the input control. It renders **only**: the label (with the required marker when `IsRequired`), the control, and the validation message when non-empty. There is no hint slot and no description slot — do not add one "for later".
4. Required marker: a `*` glyph styled on the label with `AutomationProperties.Name="required"`; also set `AutomationProperties.IsRequiredForForm` on the hosted control. Never render the word `Required.` or `Optional.`.
5. Associations: set `AutomationProperties.LabeledBy` from the control to the label element, and `AutomationProperties.DescribedBy` from the control to the validation `TextBlock`. Done looks like: Narrator on the field reads "<label>, required, edit, <validation message>" and nothing else.
6. Validation placement: the message sits directly under the control in `PegasusDangerBrush` and is a `LiveSetting="Polite"` region so it announces once when it appears. Field-level validation runs immediately; server validation problems attach to the section they concern (an `InfoBar` in that tab, from [[DSK-06-10]]), not to the whole window.
7. Add `src/Pegasus.Desktop/Controls/FormSection.cs` — a titled group using `PegasusSectionTextStyle`, `PegasusSpace6` (24) between sections, `PegasusPanelPadding` inside. A section with nothing recorded and no available action **renders nothing** in read-only view; edit-only sections render only in edit context (`docs/design/README.md:435-440`).
8. Add `src/Pegasus.Desktop/Controls/ErrorSummary.cs`: an `InfoBar`-hosted list at the top of a form naming each failing field as a focusable link that moves focus to it, modelled on `src/Pegasus.Web/Pages/Shared/_ErrorSummary.cshtml`. It announces once, Polite.
9. Two-way input correctness: any `TextBox` inside a field binds with `Mode=TwoWay, UpdateSourceTrigger=PropertyChanged` — the default resolves to `LostFocus` for `TextBox.Text`, and UI-Automation keyboard tests that assert immediately after typing would read stale view-model state (`.codex/skills/winui-design/SKILL.md` § XAML landmines).
10. Targets and focus: keep a practical 44px pointer target via padding while the visual row stays compact; the focus ring is the 3px `PegasusFocusBrush` from [[DSK-06-01]] and must be visible on every field control in Light, Dark and forced colours.
11. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; render a valid field, a required field and an invalid field on the gallery page from [[DSK-06-02]].
12. Run a Narrator smoke pass on the gallery form sample: tab to each field, confirm label, required state and error are read, and that no hint or explanatory text exists to read. Record the pass in the ticket — automated results do not replace it (`docs/engineering.md` § Required evidence tiers, tier 7).

## Acceptance criteria

- [ ] A field renders a label and a control only; no hint text, no `Required.`/`Optional.` prose, no format guidance.
- [ ] Required state is a visual marker with the accessible name `required`, plus `IsRequiredForForm` on the control.
- [ ] Validation text is associated through `DescribedBy`, announced once Polite, and placed under the control.
- [ ] The error summary lists failing fields as focusable links that move focus.
- [ ] Read-only sections with nothing recorded are absent; edit-only sections appear only in edit context.
- [ ] `TextBox` fields commit per keystroke (`UpdateSourceTrigger=PropertyChanged`).
- [ ] Focus is visible on every field control in all three themes.
