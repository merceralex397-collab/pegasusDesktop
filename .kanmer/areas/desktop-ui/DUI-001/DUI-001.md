## What

Create `src/Pegasus.Desktop/Styles/` and implement every token in `docs/desktop/06-ui-design/tokens-and-theme.md` as WinUI resources with explicit `Light`, `Dark` and `HighContrast` theme dictionaries, merged once from `App.xaml`. After this ticket no view in the desktop app may carry a colour literal, a raw `FontSize` or a hard-coded corner radius.

## Why

Proposal § 14.10 asks for "a small documented resource dictionary", and the design authority (`docs/design/README.md:182-293`) already fixes the exact values. Without one dictionary the desktop would grow a second token source beside `src/Pegasus.Web/wwwroot/css/site.css`, which the "one list per concept" rail (`AGENTS.md` § Simplicity rails) forbids. Operator-visible consequence: state colours, focus ring and density match the web exactly, and forced-colours mode keeps every control legible. Sibling tickets [[DSK-06-02]] (gallery page), [[DSK-06-03]] (icons), [[DSK-06-06]] (StatusChip) all consume these keys.

## Implementation steps

1. Orientation. Read `docs/desktop/06-ui-design/README.md` § 5 row `DSK-06-01`, all of `docs/desktop/06-ui-design/tokens-and-theme.md`, and `docs/design/README.md:182-293`. Then call Kanmer `get_doc_gates` for this ticket id and `take_ticket`; work in the ticket's own worktree and branch (`AGENTS.md` § Repository task workflow steps 1–2).
2. Load `pegasus-desktop`, then `winui-design` and read `.codex/skills/winui-design/references/theme-accessibility.md` end to end. Its rules govern: `{ThemeResource}` at usage sites, `{StaticResource}` inside theme dictionaries, `SystemColor*` only inside `HighContrast`, never a `Default` dictionary, never `HighContrastAdjustment="None"`.
3. Check whether `src/Pegasus.Desktop/Styles/` already exists from [[DSK-02-09]], which owns the file structure, the `App.xaml` merge and the enforcement test. If it does, fill the existing `Tokens.Colors.xaml`, `Tokens.Typography.xaml`, `Tokens.Spacing.xaml`, `Tokens.Shape.xaml`, `Tokens.Focus.xaml` and `Pegasus.Theme.xaml` in place and create no new file; if it has not landed, create exactly those six under [[DSK-02-09]]'s load order (`Icons.Lucide.xaml` is [[DSK-06-03]] and the `Controls.*.xaml` set is [[DSK-06-06]]/[[DSK-06-08]]/[[DSK-06-09]]/[[DSK-06-10]]) and record in the plan document which case applied. The dictionary set this ticket fills is those six — the five token files plus `Pegasus.Theme.xaml`; `Icons.Lucide.xaml` and the `Controls.*.xaml` set are the remaining names in [[DSK-02-09]]'s eight-file load order, added by their own area-06 tickets and merged into `Pegasus.Theme.xaml` when they land. Add each file to `Pegasus.Desktop.csproj` as `Page` if the SDK does not glob them.
4. Transcribe the § Colour tokens table into `Tokens.Colors.xaml` inside `<ResourceDictionary.ThemeDictionaries>` with `x:Key="Light"`, `x:Key="Dark"` and `x:Key="HighContrast"`. Every key from that table must exist in all three dictionaries with the exact value the table gives; do not invent a key and do not omit one. `#12DB0816` and `#61DB0816` are the pre-multiplied ARGB forms of the authority's `rgba(219,8,22,.07)` tint and `rgba(219,8,22,.38)` focus ring — keep them.
5. In the `HighContrast` dictionary use only `SystemColor*Color`/`SystemColor*Brush` values, mapped as the table's HighContrast column says. Never set `Opacity` on a system brush, and never write `HighContrastAdjustment="None"` anywhere in the project.
6. Write `Tokens.Typography.xaml`. Each key in § Typography is a `Style TargetType="TextBlock"` with `BasedOn="{StaticResource <built-in style>}"` exactly as the table's parenthesis says (`TitleTextBlockStyle`, `SubtitleTextBlockStyle`, `BodyStrongTextBlockStyle`, `BodyTextBlockStyle`, `CaptionTextBlockStyle`). Set `Typography.NumeralAlignment="Tabular"` on `PegasusMetricTextStyle`, `PegasusBodyTextStyle`, `PegasusCaptionTextStyle` and `PegasusReferenceTextStyle`. Do not set `FontSize` on any style except where the table's WinUI column differs from the base style, and record each such case in the plan document.
7. Write `Tokens.Spacing.xaml` as `x:Double` resources: `PegasusSpace1`=4, `PegasusSpace2`=8, `PegasusSpace3`=12, `PegasusSpace4`=14, `PegasusSpace5`=18, `PegasusSpace6`=24, `PegasusSpace7`=32, `PegasusSpace8`=40, `PegasusSpace9`=64, `PegasusGutter`=24, `PegasusTableRowHeight`=32, `PegasusFactRowHeight`=28, `PegasusContentMaxWidth`=1280, `PegasusRailWidth`=236, `PegasusMinimumTargetSize`=44, `PegasusMinimumWindowWidth`=1280.
8. Write `Tokens.Shape.xaml` overriding the platform keys `ControlCornerRadius` and `OverlayCornerRadius` to `2` (the authority's only approved radius, `docs/design/README.md:262`), plus `PegasusBorderThickness`=1. Write `Tokens.Focus.xaml` overriding `FocusVisualPrimaryBrush` to `{ThemeResource PegasusFocusBrush}`, `FocusVisualSecondaryBrush` to `{ThemeResource PegasusPanelBrush}` and `FocusVisualPrimaryThickness` to `3`.
9. Fill `Pegasus.Theme.xaml` in place so it merges the files in the order [[DSK-02-09]] pins from `tokens-and-theme.md` § Files and load order; do not re-order that list and do not add a second theme dictionary. Then verify the `App.xaml` merge [[DSK-02-09]] step 8 performs — `XamlControlsResources` first, then `Pegasus.Theme.xaml`, referenced exactly once. Do not add a second merge; if it is absent because [[DSK-02-09]] has not landed, add it under that exact order and say so in the plan. Done looks like: the app builds and the shell renders with the warm-charcoal rail and white panels rather than the WinUI defaults.
10. Build and run: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`. The repository builds with `TreatWarningsAsErrors=true`, so any analyzer warning from `Microsoft.WindowsAppSDK.Analyzers` fails the build — fix, do not suppress. Capture the PID the script prints.
11. Verify the guard fact [[DSK-02-09]] step 9 adds. If it is absent, add it as `StylesAreTheOnlySourceOfColourAndType` in `tests/Pegasus.Desktop.ViewModelTests` (created by `DSK-02-13`) with exactly the contract [[DSK-02-09]] step 9 pins — it scans `src/Pegasus.Desktop/**/*.xaml` excluding `Styles/` and fails on a hex colour literal (`#` followed by 3, 4, 6 or 8 hex digits), on a raw `FontSize=` attribute and on a numeric `CornerRadius=` literal — and record in the plan document which case applied; never a second scanner. Done looks like: the named test is green and fails when a hex literal is reintroduced.
12. Take `winapp ui screenshot -a <PID> -o artifacts/ui/06-01-<theme>.png` for each and attach all three to the ticket.

## Acceptance criteria

- [ ] Every token key listed in `docs/desktop/06-ui-design/tokens-and-theme.md` exists as a resource and resolves in all three theme dictionaries.
- [ ] `Light`, `Dark` and `HighContrast` are declared explicitly; no `Default` dictionary exists anywhere in the project.
- [ ] `HighContrast` uses only system colours; no `Opacity` on a system brush; `HighContrastAdjustment="None"` appears nowhere.
- [ ] `ControlCornerRadius` and `OverlayCornerRadius` are `2`; the focus ring is 3px `PegasusFocusBrush`.
- [ ] No colour literal, raw `FontSize` or hard-coded corner radius exists in any XAML outside `src/Pegasus.Desktop/Styles/`.
- [ ] Typography is expressed only through styles based on the built-in WinUI text styles, with tabular numerals on the numeric styles.
- [ ] Exactly one `src/Pegasus.Desktop/Styles/` directory, one `App.xaml` merge of `Pegasus.Theme.xaml` and one `StylesAreTheOnlySourceOfColourAndType` guard test exist, and the plan document records for each whether [[DSK-02-09]] had already landed it.
