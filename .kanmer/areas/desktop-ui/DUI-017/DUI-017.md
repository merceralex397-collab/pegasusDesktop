## What

Capture the Claude Design project `710bb42f`'s `github.md` screen map — the record of which Razor page each approved prototype was drawn from — into the repository as `docs/design/references/screen-map.md`, joined to the fifteen `— replaces \`Pages/…\`` headings in `docs/desktop/06-ui-design/screen-specs.md`, and link it from `docs/index.md` as a reference artefact rather than a second authority.

## Why

The desktop conversion treats the approved prototype assets as **binding design input** in three separate places, and none of them can reach the join that makes them usable:

- `docs/desktop/06-ui-design/README.md:67` names the approved `/Inbox/{id}` redesign (`docs/design/references/mockups/inbox-message-page/README.md`) as "the worked example of the rules applied".
- [[DSK-05-10]] (`FEAT-010`) step 1 instructs the implementing agent to read "the approved mockups under `docs/design/references/mockups/inbox-message-page/`" before building the Inbox slice, and its § Source of truth cites them as the screen spec's design source.
- Parity row `PAR-22` (`docs/desktop/01-inventory-and-parity/parity-matrix.md:67`) records the design source for §13.8 Communications as "Inbox message page (approved redesign under `docs/design/references/mockups/inbox-message-page/`)".

What none of them has is the map: nothing in the tree says which Razor page each of the twenty-one approved prototypes was drawn from, and `docs/index.md` does not link the mockups at all. That join lives only inside Claude Design project `710bb42f` — and the repository does not even record how to reach it: `docs/design/README.md:132` carries only the eight-character prefix `710bb42f`, while `.design-sync/config.json`'s `projectId` `d795cfe7-300d-4c42-a837-9a1714dd1a36` is a *different* project (the embedded design **system**, not the screens). The assets are therefore only as durable as a design project nobody in the repository can name.

No seeded conversion ticket is permitted to fix this. [[DSK-06-13]] (`DUI-013`) is the consumer — it adopts every `screen-specs.md` block into FRD-13 — and its own scope boundary reads "Must not touch `docs/design/README.md` (design owner)", with `docs/design` outside the files it may edit. So the ticket that most needs the map may not create it.

Under **D-001** the fork becomes the single release source at the first production gateway change and upstream is frozen, so nobody upstream will capture this either: if it is not captured on the fork before the freeze, and the design project is re-synced or lost, the conversion permanently loses the record of which page each approved prototype restates. Operator-visible consequence: a desktop screen can no longer be checked against the prototype it claims to implement, and a reviewer asked "is this the approved design for this page?" has nothing to answer with.

Placed in `desktop-ui` beside [[DSK-06-13]], the consumer — not in the empty `delivery-repository` area the upstream triage named.
