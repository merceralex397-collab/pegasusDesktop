## What

Add `src/Pegasus.Desktop/Views/Developer/GalleryPage.xaml`, reachable only in non-production channels through Settings → Developer, rendering every brush, text style, spacing step, button state, chip tone, field state, dialog launcher, `InfoBar` severity, glyph and the logo. It is the artefact the theme review screenshots are taken from.

## Why

Proposal § 14.10 says a small resource dictionary plus a gallery/debug page is sufficient; the area plan makes the gallery the place a token change is first seen and the surface the operator reviews the unspecified Dark palette on before Phase 3 exit (`docs/desktop/06-ui-design/README.md` § 7, "Dark theme is unspecified"). Operator-visible consequence: a palette that has never been looked at in Dark or forced colours would ship unreviewed. Consumes [[DSK-06-01]].

## Implementation steps

1. Orientation. Read the plan row, `docs/desktop/06-ui-design/tokens-and-theme.md` § Gallery/debug page, and the resource keys shipped by [[DSK-06-01]] in `src/Pegasus.Desktop/Styles/`. Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. Use its reach-for-this-control map: the gallery is a scrolling `Grid`, not a `NavigationView`; swatch rows are an `ItemsRepeater` or a plain `StackPanel`, not a CommunityToolkit `DataGrid`.
3. Create `src/Pegasus.Desktop/Views/Developer/GalleryPage.xaml` (+ `.xaml.cs`) with sections in this order: Brushes, Typography, Spacing, Buttons, Status chips, Fields, Dialog, InfoBars, Glyphs, Logo, Table sample. Each section header uses `PegasusSectionTextStyle`.
4. Brushes section: one row per key in `tokens-and-theme.md` § Colour tokens showing a 48×24 swatch, the resource key name, and the resolved hex read back from the brush at runtime (`(brush as SolidColorBrush)?.Color`). Do not hard-code the hex string in XAML — read it, so the page cannot drift from the dictionary.
5. Typography section: one line per style key from § Typography rendering the sample text `Case/PO 576059 · EJ17 NBZ · 12/09/2026` so the tabular-numeral setting is visible. Spacing section: a bar per `PegasusSpace1…9`, `PegasusGutter`, `PegasusTableRowHeight` labelled with the key and value.
6. Control states: every `Button` variant (accent, default, disabled, and one under focus), the five `StatusChip` tones from [[DSK-06-06]] (stub them as static content until that ticket lands and replace them when it does), a field in valid and invalid states from [[DSK-06-08]], a `ReasonDialog` launcher from [[DSK-06-09]], one `InfoBar` per severity from [[DSK-06-10]], the sixteen glyphs from [[DSK-06-03]], and the logo asset.
7. Add the theme switcher on the page: a `ComboBox` (`AutomationId` `Gallery.Theme`) setting `RequestedTheme` on `Window.Content` between `Light`, `Dark` and `Default`, per `.codex/skills/winui-design/references/theme-accessibility.md` § Runtime theme switching. Add a scale note row that reads the current `RasterizationScale` so a 200% screenshot is self-identifying.
8. Gate the route. Register the page only when the build channel is not production — reuse the channel value the host configuration exposes (`DSK-02-07` establishes channel-selected configuration); the Settings screen's Developer section (`Settings.Gallery`, `docs/desktop/06-ui-design/screen-specs.md` § Diagnostics and settings) is the only entry point. Done looks like: a production-channel build has no Developer section and no reachable gallery route.
9. Give every interactive control on the page an `AutomationId` following `screen-specs.md` § AutomationId convention (`Gallery.<Region>.<Element>`), so the coverage audit in [[DSK-06-15]] does not fail on the gallery itself.
10. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; capture the PID. Navigate to the gallery and take screenshots at 100% and 200% display scale in Light, Dark and a Windows Contrast theme — six files under `artifacts/ui/06-02/`.
11. **Operator step** — put the six screenshots in front of the design owner and record: whether the Dark values in `tokens-and-theme.md` § Colour tokens are accepted or adjusted, and whether the 14px `PegasusSectionTextStyle` standing in for the authority's 15/700 section heading is acceptable. Evidence to hand back: a dated decision on both, pasted into the ticket and mirrored into `tokens-and-theme.md`.
12. Record the review findings in the ticket plan under the design-authority review headings (four hard rules, banned words, status vocabulary, one primary action) and have `pegasus-desktop-reviewer` sign it.
