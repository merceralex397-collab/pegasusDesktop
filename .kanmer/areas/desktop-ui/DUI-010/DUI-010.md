## What

Add a `ProblemInfoBar` that turns a gateway problem-details response into one operator sentence with a severity mapped from the problem type, plus an expandable copyable *Reference* row carrying the correlation id — and a view-model test set that fails the build when a banned word or a raw code reaches an operator string.

## Why

Proposal § 14.8 asks for "human-readable problem messages with an expandable correlation identifier", but `correlation identifier` is itself a banned word (`docs/design/README.md:412-420`), so the area plan resolves it as a *Reference* value under that label. Operator-visible consequence: a failure says what happened in Pegasus words and gives support one value to quote. Consumes the gateway's problem-details mapping; consumed by every screen.

## Implementation steps

1. Orientation. Read the plan row, `docs/design/README.md:396-445`, and the problem-type list the gateway emits (`DSK-03-02`'s mapping, ported from `AutomationMcpErrors.cs`). Call Kanmer `get_doc_gates` for this ticket id, then `take_ticket`.
2. Load `pegasus-desktop`, then `winui-design`. `InfoBar` is the platform control for inline status (`winui-design` § Reach-for-this control map) — do not build a custom banner and do not use a toast or a notification centre (the area plan records that deviation from proposal § 14.8).
3. Add `src/Pegasus.Desktop/Controls/ProblemInfoBar.xaml(.cs)`: an `InfoBar` with `Severity` bound from the problem type, `Message` bound to the operator sentence, and an expandable content row labelled `Reference` holding the correlation id as selectable text plus a copy button (`AutomationId` `<Screen>.Problem.CopyReference`).
4. Create the one problem-type → (severity, sentence) table, in one place, in the shared presentation layer beside the operator-label map from [[DSK-06-05]]. Every sentence is Pegasus operator language; where an approved necessary-copy sentence exists for the situation, use it verbatim (for example `No case or reference was created; review the missing or conflicting evidence.`).
5. Severity mapping: validation and conflict problems → `Warning`; denial, dependency-unavailable and technical failure → `Error`; replayed/idempotent results and informational outcomes → `Informational`. An unmapped problem type is a test failure, not a fallback string.
6. The copy action puts only the Reference value on the clipboard (`Clipboard.SetContent` with a `DataPackage`), and the button's accessible name is `Copy reference`. The word `correlation identifier` must never render.
7. Placement: one `ProblemInfoBar` per page or per tab section, never a modal. On the Case workspace, a server validation problem attaches to the tab it concerns (`docs/desktop/06-ui-design/screen-specs.md` § Case workspace). The bar is a Polite live region so it announces once.
8. Add `tests/Pegasus.Desktop.ViewModelTests/ProblemPresentationTests.cs`: a theory over every problem type the gateway emits asserting a mapped severity and a non-empty sentence; `UnmappedProblemTypeFails`; and `NoBannedWordAppearsInAnyProblemSentence` over the closed list at `docs/design/README.md:412-420` (case-insensitive, word boundary). Extend the banned-words assertion to cover every operator string constant in the desktop, so this ticket becomes the automated backstop the authority says CI does not have today.
9. Add `NoRawCodeInAProblemSentence`: assert no sentence contains a GUID, a `snake_case` code, a PascalCase compound or an HTTP status number.
10. Build and run with `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj`; render one `InfoBar` per severity on the gallery page from [[DSK-06-02]] with a sample Reference value.
11. Verify copy end to end: `winapp ui invoke` the copy button, then read the clipboard in the test script and assert it equals the Reference value exactly — no label, no prefix.
12. Have `pegasus-desktop-reviewer` record the design-authority review over the full sentence table (four hard rules, banned words, no how-it-works copy) in the ticket plan.
