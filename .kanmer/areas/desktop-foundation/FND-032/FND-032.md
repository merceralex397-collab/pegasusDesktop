## What

Compose the desktop application on a `Microsoft.Extensions.Hosting` generic host built inside `src/Pegasus.Desktop/App.xaml.cs`: one service container, strongly-typed options, embedded `appsettings.json` plus `appsettings.<channel>.json` selected by an MSBuild property at package time, and structured `Microsoft.Extensions.Logging` writing to the bounded, redacting rolling-file sink from [[DSK-02-06]].

## Why

Proposal § 7.2 fixes the composition (Hosting for DI, configuration, logging and lifetime; `IHttpClientFactory`; structured logging) and § 18.1 requires structured rolling local logs with a per-launch session identifier, API correlation identifiers, redaction by default and bounded size and retention. Plan § 3 decision 7 adds the channel model (`pilot` | `production` | `local`) and § 3 decision 9 forbids adding a desktop framework on top of WinUI. Without this ticket every later view model has to construct its own dependencies, and [[DSK-02-08]], [[DSK-02-10]], [[DSK-02-11]] and every slice in area 05 have nowhere to register services. Operator-visible consequence: the environment badge and the status bar read the channel from this configuration, and a token leaking into a log file is a security defect the redaction hook exists to prevent.

3. Create `src/Pegasus.Desktop/Configuration/appsettings.json` plus `appsettings.local.json`, `appsettings.pilot.json` and `appsettings.production.json`, each holding exactly three settings and nothing else: `Gateway:BaseAddress`, `Update:FeedUri`, `Channel`. No secret, token, connection string or Azure identifier may appear in any of them (area 04 § 3 item 8).
4. In `src/Pegasus.Desktop/Pegasus.Desktop.csproj` add an MSBuild property `<PegasusChannel Condition="'$(PegasusChannel)'==''">local</PegasusChannel>` and embed `Configuration/appsettings.json` plus `Configuration/appsettings.$(PegasusChannel).json` as `EmbeddedResource` with fixed logical names. The channel is chosen at package time, not at runtime, so a pilot package cannot be pointed at production by editing a file on disk.
5. Create `src/Pegasus.Desktop/Hosting/PegasusHost.cs` that builds the host: read the two embedded JSON streams with `AddJsonStream`, bind `GatewayOptions` / `UpdateOptions` / `ChannelOptions` with data-annotation validation and `ValidateOnStart`, register `AddPegasusApiClient(…)` from [[DSK-02-06]], register the credential store with `ApplicationData.Current.LocalFolder.Path` as its store root, register the bounded cache, and register navigation/dialog service placeholders only once [[DSK-02-08]] defines them (do not create empty interfaces now — `docs/engineering.md` § Abstractions).
6. Wire logging: `builder.Logging.ClearProviders()` then add the `IDiagnosticsWriter`-backed `ILoggerProvider` from `src/Pegasus.Desktop.Infrastructure/Diagnostics/`. Configure the sink with an explicit total-size cap and file-retention count, and a per-launch session identifier generated once at host build and attached to every log scope alongside the request correlation id.
7. Implement the redaction rule in one place: the sink's message processor removes bearer tokens, refresh tokens, `Authorization` header values, password fields and any value keyed `token`/`secret`/`password` before writing. Assert the rule with a fixture test rather than by inspection.
8. Change `App.xaml.cs` to build the host in `OnLaunched` before creating the window, hold it in a `public static IHost Services` (or an equivalent single accessor), and dispose it on `Application.Current.Exit`. Do not construct services anywhere else; a view model that news up a client is a defect the review must catch.
9. Add tests in `tests/Pegasus.Desktop.ViewModelTests` ([[DSK-02-13]]): a fake host fixture resolves `GatewayOptions`, the API client and the credential store; an options-validation test proves a missing `Gateway:BaseAddress` fails at start; a log fixture writes a line containing a fake bearer token and asserts the token is absent from the file while the surrounding message survives; a rotation test writes past the size cap and asserts the retention count is honoured.
10. Build and launch: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj -SkipRun`, then run it asynchronously and confirm the log file appears under the packaged app's local folder with the session identifier in its first line. Expected: `✅ <pkg> launched (PID: …)` and a non-empty log file.
11. Build a second channel to prove the selection works: `dotnet build ./src/Pegasus.Desktop/Pegasus.Desktop.csproj -c Release -p:PegasusChannel=pilot` and confirm the embedded resource list contains `appsettings.pilot.json` and not `appsettings.production.json`.
12. Run `dotnet test ./tests/Pegasus.Desktop.ViewModelTests/Pegasus.Desktop.ViewModelTests.csproj --configuration Release`, then the simplification pass, recorded under a dated `## Simplification pass` heading in the ticket plan, before the PR into `dev`.

## Acceptance criteria

- [ ] `App.xaml.cs` builds one generic host before any window is created and disposes it on exit.
- [ ] Configuration is embedded, layered as base + channel, and selected by the `PegasusChannel` MSBuild property; the three channels are `local`, `pilot`, `production`.
- [ ] No secret, token or connection string appears in any `appsettings*.json` shipped in the package.
- [ ] Options are bound with validation and fail at start when a required setting is missing.
- [ ] Logs are structured, carry a per-launch session identifier and the API correlation id, rotate within an explicit size cap and retention count, and redact tokens and passwords.
- [ ] Every service a view model needs resolves from the container in a test without a dispatcher.

## Guardrails

- **Azure**: no write. The `local` channel points at the local Test/UAT stack (L-02); asking for an Azure test endpoint is out of bounds without a new accepted decision (ADR-0014).
- **Scope boundary**: may edit `src/Pegasus.Desktop/**` and `Directory.Packages.props`. Must not implement the shell ([[DSK-02-08]]), single-instance redirection ([[DSK-02-10]]), the diagnostics bundle ([[DSK-02-11]]) or any authentication flow (area 04).
- **Traps**: no large desktop framework on top of WinUI — a shell service, a navigation service, a dialog service and a few project controls are the whole permitted surface (proposal § 7.2). No third-party logging framework: the sink is the project's own `ILoggerProvider` over `Microsoft.Extensions.Logging`. `TreatWarningsAsErrors=true` applies. Nothing built but unwired for two weeks survives (`docs/engineering.md` § Abstractions) — register only services with a real caller.
