## What

Produce a development-signed, self-contained MSIX of `src/Pegasus.Desktop` using `winapp cert generate --manifest` and `winapp package --cert devcert.pfx --self-contained`, and add the scripted install/uninstall check under `tests/Pegasus.Packaging.Tests/` that proves the package installs on a clean Windows 11 machine after the certificate is trusted and leaves only intended user state behind.

## Why

The Phase 1 exit gate has two rows this ticket owns: "Clean Windows 11 machine launches the native shell from a dev-signed MSIX" and "Install/uninstall works and leaves only intended user settings". Proposal § 7.1 requires a self-contained signed MSIX and § 24 Phase 1 requires an unsigned/development MSIX before Phase 2 wires the real feed. Operator-visible consequence: this is the first time the application is installed rather than run from a build output, and it is where a wrong `Identity.Publisher` or an untrusted certificate shows up — both of which are permanent once real users install.

## Implementation steps

1. Orient: read the plan row and the plan sections named under Source of truth, read `.codex/skills/winui-packaging/SKILL.md` in full, then `get_doc_gates <this ticket id>` and `take_ticket` on branch `task/desktop-dev-msix` from `origin/dev`.
2. Build for release without launching: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj /p:Configuration=Release -SkipRun`. Note the build-output directory the script reports — the packaging step takes that directory as its argument.
3. Generate the development certificate matching the manifest: `winapp cert generate --manifest src/Pegasus.Desktop --if-exists skip`. The `--manifest` flag auto-matches `Identity.Publisher`, which is what prevents the "Publisher mismatch" failure. Confirm the produced subject equals the manifest `Publisher` string exactly and record both in the ticket plan.
4. Add `devcert.pfx` (and any `*.pfx`, `*.cer` produced here) to `.gitignore` and confirm `git status` never lists it. A certificate file must never be committed, and under D-002 a production `.pfx` is never a repository or GitHub secret at all.
5. **Operator step** — trust the development certificate. `winapp cert install ./devcert.pfx` needs an elevated terminal; the operator runs it and hands back the resulting `Get-ChildItem Cert:\LocalMachine\...` output showing the thumbprint and store. Record explicitly in the ticket plan that the skill's `cert install` places the certificate in the machine Trusted Root store, that this is acceptable for the **development** certificate on development and Test/UAT machines only, and that the **production** certificate goes to `Cert:\LocalMachine\TrustedPeople` per D-002 — [[DSK-09-08]] owns that rollout.
6. Package and sign: `winapp package <build-output-dir> --cert ./devcert.pfx --self-contained`. Expected: a `.msix` is produced, containing `resources.pri`, and the command reports a successful signature. Record the produced package size — a self-contained .NET plus Windows App SDK MSIX is large and [[DSK-09-02]]'s release manifest needs the number.
7. Create `tests/Pegasus.Packaging.Tests/Test-InstallUninstall.ps1` with `Set-StrictMode -Version Latest` and `$ErrorActionPreference = 'Stop'`, taking the `.msix` path as a parameter and performing, in order: remove any existing package (`Get-AppxPackage <Identity.Name> | Remove-AppxPackage`), `Add-AppxPackage <msix>`, assert `Get-AppxPackage` reports the expected `Name`, `Publisher` and `Version`, launch via `winapp run` and assert the process starts, terminate it, `Remove-AppxPackage`, then assert `%LOCALAPPDATA%\Packages\<PackageFamilyName>` no longer exists and that the DPAPI credential-store files are gone.
8. Make each assertion fail loudly with the actual value in the message; a script that exits 0 because a `Get-AppxPackage` returned nothing is worse than no script. Write results (command, expected, actual) to a log file the ticket proof can attach.
9. **Operator step** — clean-machine run. On a clean Windows 11 x64 machine (or a fresh VM snapshot) with the development certificate trusted, run `tests/Pegasus.Packaging.Tests/Test-InstallUninstall.ps1` against the produced `.msix`. The operator hands back: the script log, a screenshot of the launched shell, and confirmation that no administrator elevation was needed for `Add-AppxPackage` itself.
10. Record the package identity actually installed — `Get-AppxPackage <Identity.Name> | Select-Object Name, Publisher, PackageFamilyName, Version` — in the ticket proof. This is the value [[DSK-02-11]]'s bundle manifest and [[DSK-09-02]]'s release manifest must both agree with.
11. Write the `docs/runbook.md` § Supported platform prerequisite sentence this ticket owns: the `winapp` CLI and Developer Mode prerequisites and the development-certificate trust step for a Test/UAT machine. [[DSK-02-03]], [[DSK-02-05]] and [[DSK-04-12]] cite that sentence rather than restating it, so write it once and in full here.
12. Do not build the `.appinstaller`, the feed, the version generator or the CI packaging lane here — [[DSK-09-02]], [[DSK-09-03]] and [[DSK-02-15]] own those. Run the simplification pass, record it under a dated `## Simplification pass` heading in the ticket plan, and open the PR into `dev`.
