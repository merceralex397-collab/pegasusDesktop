## What

Create `src/Pegasus.Desktop.Infrastructure` (`net10.0-windows10.0.26100.0`, x64, referencing only `Pegasus.Core` and `Pegasus.Contracts`) holding the desktop's outbound HTTP pipeline via `IHttpClientFactory` with the `X-Pegasus-Client-Version` and `X-Correlation-Id` headers, the DPAPI-backed credential store, the bounded in-memory cache, and the diagnostics writer that [[DSK-02-07]] and [[DSK-02-11]] build on.

## Why

Proposal § 5.3 fixes the dependency direction inward and forbids the desktop referencing Entity Framework contexts, Azure SDK credentials or server integration implementations; § 7.2 fixes `IHttpClientFactory` plus a generated typed client and a DPAPI-backed store for refresh tokens. Plan § 3 decision 6 chooses DPAPI (`System.Security.Cryptography.ProtectedData`, `DataProtectionScope.CurrentUser`) over `PasswordVault` because the Credential Locker guidance limits AppContainer apps to 20 credentials and warns against storing anything larger than a password, while a session handle may exceed that. Area 03 requires `X-Pegasus-Client-Version` on every `/api/v1` request — its absence yields `client-unsupported`, so a workstation with a broken pipeline simply cannot work. This project is where the boundary lives that [[DSK-02-12]] then enforces with tests.

5. `Api/PegasusHttpClientRegistration.cs`: an `IServiceCollection` extension `AddPegasusApiClient(this IServiceCollection, Action<GatewayOptions>)` that calls `AddHttpClient("pegasus")`, sets `BaseAddress` from options, adds the handler above, and configures a bounded jittered retry for idempotent `GET` requests only. Commands must never be retried automatically (area 03 § 3, Retry row) — assert that in a comment and in the test [[DSK-02-13]] adds.
6. `Authentication/IDesktopCredentialStore.cs` + `Authentication/DpapiCredentialStore.cs`: `Save(string key, string value)`, `TryRead(string key, out string? value)`, `Clear(string key)`; implementation calls `ProtectedData.Protect`/`Unprotect` with `DataProtectionScope.CurrentUser` and writes one file per key under an injected `storeRoot` directory. Constructor takes `string storeRoot` — the app passes `ApplicationData.Current.LocalFolder.Path`, tests pass a temporary directory. Never store the access token here: it stays in memory (proposal § 8.2, § 11.1).
7. `Caching/BoundedSnapshotCache.cs`: an in-memory cache with an explicit entry-count cap and per-entry expiry, holding only what ADR-0104 permits — small reference-data snapshots, thumbnails and the last compatibility response. It must have no file-backed store and no SQLite; adding a durable cache requires the profiling evidence proposal § 11.2 demands.
8. `Diagnostics/IDiagnosticsWriter.cs` and a rolling-file implementation with a total-size cap and a retention count, plus a redaction hook that removes bearer tokens, refresh tokens and password fields before a line is written.
