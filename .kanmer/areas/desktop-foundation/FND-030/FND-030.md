## What

Scaffold the WinUI 3 application project at `src/Pegasus.Desktop` from the `winui-mvvm` template, retarget it to `net10.0-windows10.0.26100.0` / x64 / packaged single-project MSIX / self-contained, pin `Microsoft.WindowsAppSDK` centrally, fix the permanent package identity, and prove it builds and launches with package identity.

## Why

This is the project every later desktop ticket builds inside: proposal § 7.1 fixes the runtime baseline (.NET 10, latest stable Windows App SDK pinned centrally, Windows 11 x64, self-contained signed MSIX, no AOT/trimming initially) and § 7.2 fixes the composition. Nothing in [[DSK-02-06]], [[DSK-02-07]], [[DSK-02-08]], [[DSK-02-10]] or [[DSK-02-11]] can start until it exists. Operator-visible consequence: the package identity and publisher chosen here are permanent — changing `Identity.Name` or `Publisher` after any workstation has installed the app makes it a different application, and D-002 fixes the signing certificate subject to that same `Publisher` string.

## Implementation steps

1. Orient: read the plan row and the plan sections named under Source of truth, read `.codex/skills/winui-dev-workflow/SKILL.md` in full, then `get_doc_gates <this ticket id>` and `take_ticket` on branch `task/desktop-scaffold` in worktree `../pegasus-worktrees/desktop-scaffold` from `origin/dev`.
2. **Operator step** — prerequisites. Run the detection block from `.codex/skills/winui-setup/SKILL.md` (`dotnet --list-sdks`, `winapp --version`, `dotnet new list winui`, the `AppModelUnlock\AllowDevelopmentWithoutDevLicense` registry read). Enabling Developer Mode needs a UAC elevation the operator must accept, and installing the `winapp` CLI (`winget install --id Microsoft.WinAppCLI`) may too. The operator hands back: the SDK list, the `winapp` version (must be ≥ 0.3), confirmation that `Microsoft.WindowsAppSDK.WinUI.CSharp.Templates` is installed, and Developer Mode = 1. Do not attempt to install these yourself if they are missing — stop and ask (`winui-dev-workflow` § Prerequisites).
3. **Operator step** — fix the package identity. Confirm with the operator the permanent `Identity.Name` (plan 09 § 2 assumes `CollisionEngineers.Pegasus`) and the exact `Identity.Publisher` distinguished name, which under D-002 must equal the subject of the self-managed production certificate ([[DSK-09-08]]). Record both verbatim in the ticket plan. These values are never changed afterwards.
4. Scaffold: `dotnet new winui-mvvm -n Pegasus.Desktop -o src/Pegasus.Desktop`. Do not `mkdir` first. The template brings CommunityToolkit.Mvvm, a TitleBar, MicaBackdrop and Frame navigation (`winui-dev-workflow` § Create or Open a Project). Delete nothing from the template except sample pages you replace; never delete `Package.appxmanifest`.
5. Edit `src/Pegasus.Desktop/Pegasus.Desktop.csproj` to the plan's decision 3: `<TargetFramework>net10.0-windows10.0.26100.0</TargetFramework>`, `<TargetPlatformMinVersion>10.0.22000.0</TargetPlatformMinVersion>`, `<Platforms>x64</Platforms>`, `<RuntimeIdentifier>win-x64</RuntimeIdentifier>`, `<SelfContained>true</SelfContained>`, `<WindowsAppSDKSelfContained>true</WindowsAppSDKSelfContained>`, `<PublishReadyToRun>false</PublishReadyToRun>`, no `PublishTrimmed`, no `PublishAot`. Never set `<WindowsPackageType>None</WindowsPackageType>` and never use `AnyCPU` (`winui-dev-workflow` § Critical Rules).
6. Pin the packages centrally: add `<PackageVersion Include="Microsoft.WindowsAppSDK" Version="2.4.0" />` (or the latest 2.x **stable** confirmed at kickoff — check with `microsoft_docs_fetch` on the Windows App SDK 2.0 release-notes page; the minimum is 2.1.3 because earlier 2.x builds fail `MSB3073` with no XAML diagnostic) plus `Microsoft.Windows.SDK.BuildTools`, `Microsoft.Windows.SDK.BuildTools.WinApp`, `Microsoft.WindowsAppSDK.Analyzers` and `CommunityToolkit.Mvvm` to `Directory.Packages.props`, and strip the version literals the template wrote into the csproj. Record the exact chosen version and its release date in the ticket plan.
7. Reference `Microsoft.WindowsAppSDK.Analyzers` explicitly in `src/Pegasus.Desktop/Pegasus.Desktop.csproj`: `BuildAndRun.ps1` only injects a temporary `Directory.Build.props` when none exists up the tree, and the repository root props file means it will skip injection, so without the explicit reference the `WUI*` diagnostics disappear (plan § 7).
8. Set the identity in `src/Pegasus.Desktop/Package.appxmanifest`: `Identity/@Name` and `Identity/@Publisher` to the values fixed in step 3, `Identity/@Version` to `0.1.0.0` for now ([[DSK-09-02]] wires the version from the CI run), `Properties/DisplayName` and `Application/uap:VisualElements/@DisplayName` to `Pegasus`. Document in the csproj or a `README` comment which fields are placeholders and which are permanent.
9. Add the project to `Pegasus.slnx` under the `/src/` folder, keep it **out** of the server entry point from [[DSK-02-03]], and extend the expected array in `DependencyDirectionTests.ApplicationSolutionExcludesSourceWorkspaces` (`tests/Pegasus.ArchitectureTests/DependencyDirectionTests.cs:137-149`) with `src/Pegasus.Desktop/Pegasus.Desktop.csproj`.
10. Restore with the lock file: `dotnet restore ./src/Pegasus.Desktop/Pegasus.Desktop.csproj -r win-x64 --force-evaluate` then commit the generated `src/Pegasus.Desktop/packages.lock.json`. Then `dotnet restore ./Pegasus.slnx --locked-mode` must pass on Windows.
11. Build and run: `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj -SkipRun` (safe synchronously), then `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj` invoked asynchronously — the script stays attached. Done looks like the line `✅ <pkg> launched (PID: …)` in the output and a visible window. Capture a screenshot of the launched window for the proof document. If the build fails with `MSB3073`/`XamlCompiler.exe … exited with code 1` naming no `.xaml`, raise the `Microsoft.WindowsAppSDK` pin (`winui-dev-workflow` § Common Errors).
12. Resolve analyzer noise honestly: `Directory.Build.props` sets `TreatWarningsAsErrors=true` and `AnalysisLevel=latest-recommended`, and template/XAML generated code will trip it. Add narrowly-scoped `<NoWarn>` entries in `src/Pegasus.Desktop/Pegasus.Desktop.csproj` with a comment naming each suppressed rule and why, or exclude generated files by path — do not relax the repository-wide policy in `Directory.Build.props`.
13. Run `dotnet test ./tests/Pegasus.ArchitectureTests/Pegasus.ArchitectureTests.csproj --configuration Release` — expected green with the extended solution list. Run the simplification pass over the branch diff, record findings under a dated `## Simplification pass` heading in the ticket plan, and open the PR into `dev`.
