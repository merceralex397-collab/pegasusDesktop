## What

Clear the residue the board-seeding audits left behind: 21 verification lines that cannot run as written, 19 ambiguous id references, six REL-007 namespace/link sites and one placeholder command. All of it is hygiene — an independent sweep confirmed **zero** references remain that would make an agent act on the wrong ticket.

## Why

The board was seeded on 2026-08-24 and then put through seven repair rounds against independent audits. Those rounds closed every defect that could misdirect an implementing agent — most importantly `FND-022` step 7, which read "**Drop `CASE-001`**" meaning *upstream* CASE-001 while board `CASE-001` is a live imported production defect blocking four tickets.

What is left cannot misdirect anyone, but it does waste their time: an agent reaching a broken verification command gets a parameter prompt or an error, notices, and stops. That is a broken gate rather than a wrong action, which is why it is filed here instead of triggering an eighth repair round. This ticket exists so the residue is **recorded and owned** rather than silently carried.

This ticket has **no plan row** — it originates from the seeding audit, not from `docs/desktop/`. Its title carries no `DSK-` handle for that reason.
