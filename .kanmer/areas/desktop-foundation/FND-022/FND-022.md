## What

Execute the dispositions in `docs/desktop/01-inventory-and-parity/upstream-kanmer-carryover.md`: recreate the 57 carried-over tickets (from 56 distinct upstream ids) on the fork's Kanmer board in the fork areas the triage table names, each with `refs`-style `upstream:<ID>` provenance, the original body and the upstream labels; leave the 53 `unchanged-backlog` rows listed but not recreated.

## Why

The original repository is not a finished project: its board still carries 109 open, non-archived tickets. L-05 makes the fork's board the single work register for the conversion, so anything real that is not carried over is silently lost. Operator-visible consequence: production defects already reported upstream — a triage-request email that creates neither a Triage nor an Unidentified item (`INTK-033`), a case export that cannot be proven (`CASE-019`), Box folder resolution once per image (`PLAT-041`) — would disappear from the fork's backlog and be rediscovered by an operator instead of a ticket. Eighteen upstream UI redesigns also become the desktop screen specifications that area 06 works from, rather than new Razor work.

2. Establish the source of the bodies. The triage table carries the upstream id, area, status, profile, labels and title, but **not** the body. Obtain each body from the read-only upstream clone of `collisionengineers/pegasus` branch `kanmer-board` at `4694067` (`git clone --branch kanmer-board --single-branch <upstream url> <temp dir>` outside the repository working tree, or `git --git-dir=<clone>/.git show 4694067:.kanmer/...`). Never push to upstream; never add upstream as a writable remote here.
3. Build the work list: the 56 upstream ids whose disposition is `desktop-screen-spec`, `gateway-worker-ticket` or `report-decision`. `CASE-009` is recreated **twice** — a `gateway-worker-ticket` half (case read-model data) and a `desktop-screen-spec` half (Communications tab) — giving 57 board tickets. Confirm the counts against the triage table's own totals (18 / 26 / 13 / 53).
4. Confirm the area mapping per row from the triage table's "Fork area" column, not from the upstream area: every `desktop-screen-spec` lands in `desktop-ui`; every `gateway-worker-ticket` and `report-decision` lands in the upstream domain area name that already exists on the fork board (`automation-integrations`, `case-reference-workflow`, `delivery-repository`, `documents-reports`, `intake-processing`, `mail-communications`, `platform-operations`, `pr-review`).
5. Check for duplicates before writing: `search_items` for the upstream id (for example `PLAT-039`) and for a distinctive phrase from the title. Never create a handle twice; if a ticket already exists, `update_item` it rather than creating a second.
6. Create the tickets with `create_items`, **at most 6 entries per call**, checking the per-entry `{ok, item|error}` result and retrying any failure. Per entry: `title` = the upstream title prefixed with the upstream id (for example `upstream:PLAT-041 · Resolve the Box case folder once per export, not once per image`); `area` = the fork area from step 4; `profile` = the upstream profile from the triage table; `labels` = the upstream labels plus `upstream-carryover` and the target area plan (`plan-<NN>`); `body` = the original upstream body copied **verbatim**, followed by a short provenance block naming the upstream id, the upstream area, the disposition, the target area plan and a link to that plan's `README.md`. Leave `status` unset so every ticket enters at Backlog; omit `links` and `blocks`.
7. Do not attach the conversion `EPIC`/`HZN` groups to carried-over tickets unless the triage table names one. These are upstream work items, not conversion plan rows; grouping them into the conversion epics would corrupt the epic counts.
8. Set `docs_todo: true` on any recreated `feature` ticket that has no existing governing document — `feature` is the only profile with a `leave-backlog` gate, and an honest `docs_todo` is what satisfies it. Where the upstream ticket already names an existing `docs/adr/**` or `docs/frd/**` path, use `refs` and verify the path exists first; a non-existent `refs` path fails the whole entry.
9. Record the 53 `unchanged-backlog` rows as a list in the ticket's `plan` document, not as tickets. Proposal §13.11 is explicit: post-alpha capabilities must not be smuggled into "feature parity". Their capability rows stay in `docs/capabilities.md`; the triage table is their register until a horizon activates them.
10.
