## What

Make the two required plan-document headings enforceable: every Kanmer `plan/` document written for a `DSK` conversion ticket must carry a `## Routing` block (subagent · skills with pinned paths · MCP tools) and a dated `## Simplification pass` heading. Add the check as an explicit review lens in `.codex/agents/pegasus-desktop-reviewer.toml` and to the invocation protocol in the `pegasus-desktop` project skill, then prove it on a sample ticket.

## Why

Locked decision L-04 says every ticket names its subagent, skills and MCP tools, and proposal §25 item 7 makes "Agent skills — exact pinned skills to invoke" a required ticket section. `AGENTS.md` § Repository task workflow step 4 separately requires the simplification pass to be recorded in the ticket plan under a dated heading. Both rules exist today only as prose in documents an implementing agent may not read: the reviewer agent's lens list in `.codex/agents/pegasus-desktop-reviewer.toml` checks that the simplification pass is "present with honest dispositions" but says nothing about `## Routing`, and nothing at all tells an agent where those headings must live. The result is plan documents that silently drop routing, which is how a weaker agent ends up loading `winui-wpf-migration` or an Azure deployment skill the plan set explicitly forbids. [[DSK-00-04]] must have seeded the tickets before there is anything to enforce against.
