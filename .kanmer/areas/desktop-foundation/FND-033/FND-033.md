## What

Build the application shell in `src/Pegasus.Desktop/Shell/`: a left `NavigationView` rail with the approved route order, a title bar carrying the logo, environment badge, connection state, version/channel and user menu, a status bar, and the two services the rest of the app navigates and prompts through.

## Why

Proposal § 14.2 and the screen spec in `docs/desktop/06-ui-design/screen-specs.md` § Shell define the frame every screen renders inside; it replaces `Pages/Shared/_Layout.cshtml` and `_LayoutAuth.cshtml`. Every slice in area 05 navigates through it, and the Phase 1 exit gate ([[DSK-02-16]]) requires a clean Windows 11 machine to launch the native shell and navigate. Operator-visible consequence: the environment badge is what stops an operator doing pilot work believing they are in production, and the status bar is where "Disconnected — reconnecting" appears so a save is never silently lost (proposal § 11.3).

## Implementation steps

1. Orient: read the plan row, read `docs/desktop/06-ui-design/screen-specs.md` § Shell in full (it is the specification, not a summary), read `docs/design/README.md` § No explanatory copy and page economy, then `get_doc_gates <this ticket id>` and `take_ticket` on branch `task/desktop-shell` from `origin/dev`.
2. Load `winui-design` and use `winui-search.exe` to confirm the current `NavigationView` API surface before writing XAML; do not guess property names.
3. Create `src/Pegasus.Desktop/Shell/ShellPage.xaml` with a `NavigationView`: `PaneDisplayMode="Left"`, `OpenPaneLength="236"`, `IsPaneToggleButtonVisible="False"`, and `NavigationViewItem`s in exactly this order — Dashboard, Inbox, Upload, Queues, Cases, Operations, Administration. `Administration` is added only for the Administrator role and `Inbox` only when its capability is composed; bind their visibility to view-model state, do not hard-code them visible.
4. Give the current item a weight change plus a 2 px Collision-red left marker by restyling the `NavigationView` selection indicator. Colour alone must never be the only signal (`docs/design/README.md`; `winui-code-review` theming checklist). Use `{ThemeResource}` keys from [[DSK-02-09]] — no hex literal may appear in any view.
5. Build the title bar: logo asset, environment badge shown only outside production ("Pilot", "Test/UAT", "Development", read from the channel option registered in [[DSK-02-07]]), connection glyph plus word, version and channel, and a user menu with Change password, Sign out, Diagnostics. Use `microsoft_docs_search` for `AppWindow TitleBar` drag-region semantics before implementing the custom title bar.
6. Build the status bar: connection state, last sync time rendered in Europe/London, background transfer summary that opens the transfer pane, and update availability. Rail counts come from the dashboard rail-counts query and are simply absent until it returns — never render a shell-level `0`.
7. Create `src/Pegasus.Desktop/Services/INavigationService.cs` and `IDialogService.cs` with their implementations, register them in `Hosting/PegasusHost.cs`, and route every rail item through the navigation service. No other navigation mechanism may exist.
8. Set a unique `AutomationProperties.AutomationId` on every interactive control, using exactly the names in the spec: `Shell.Rail.<Route>` (one per rail item, e.g. `Shell.Rail.Cases`), `Shell.Title.Environment`, `Shell.Title.User`, `Shell.Status.Connection`, `Shell.Status.Update`. Missing AutomationIds break the [[DSK-08-06]] harness and the accessibility audit.
9. Wire the keyboard contract from the spec: rail access keys `Alt+D`, `Alt+I`, `Alt+U`, `Alt+Q`, `Alt+C`, `Alt+O`, `Alt+A`; `Ctrl+K` navigates to Cases search; `F5` refreshes the current screen. Verify tab order reaches every rail item and the user menu.
10. Implement the shell states named in the spec — authenticated; unauthenticated (login replaces the shell); update-required and blocked (full-window, no rail); disabled account; stale role — as view-model states with placeholder content where area 04 owns the real screens. Do not implement authentication here.
11. Add view-model tests in `tests/Pegasus.Desktop.ViewModelTests`: rail visibility for administrator vs non-administrator, environment badge hidden in the production channel and shown otherwise, status-bar connection text for connected/disconnected, and navigation service routing to each route.
12. Verify visually and by automation: run `pwsh .codex/skills/winui-dev-workflow/BuildAndRun.ps1 src/Pegasus.Desktop/Pegasus.Desktop.csproj` asynchronously, navigate every rail item, and capture screenshots for the proof. If the [[DSK-08-06]] `winapp ui` harness exists, run its shell smoke batch instead of manual navigation; if it does not, record in the proof that the evidence is a manual pass and name [[DSK-08-06]] as the automation follow-up.
13. Run the `winui-code-review` checklist over the new XAML (theming, no raw `FontSize`, no hex literals, AutomationIds present), then the simplification pass recorded under a dated `## Simplification pass` heading in the ticket plan, then open the PR into `dev`.
