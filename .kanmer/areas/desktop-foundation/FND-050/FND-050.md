## What

Run the Phase 2 exit review: write and execute a UAT script that walks login with an existing Pegasus account, a blocked obsolete version that then updates, and a disabled account being rejected — and attach evidence for every row of the area's exit-gate table to this ticket's proof.

## Why

Proposal § 24 makes Phase 2 the gate before any feature slice ships: current user credentials work, Microsoft login is not required, an obsolete package is blocked and updates, a disabled account is rejected, and tokens and secrets pass the storage review. `docs/desktop/00-governance-and-workflow/README.md` § *Phase map* names area 04 as the owner of that exit gate. Without a single ticket that gathers the evidence, each of [[DSK-04-02]] through [[DSK-04-13]] proves its own slice and nobody proves the phase, and the operator-visible consequence is a first vertical slice built on an authentication path that was never exercised end to end by a human.

7. **Operator step** — gate row "obsolete package is blocked and updates": raise the minimum client version through the administrator setting from [[DSK-04-06]], relaunch the installed old client, confirm the update-required screen, take the update from the feed, and confirm the app then reaches the shell. 8. Gate row "disabled account is rejected": disable a test staff account while a desktop session is live, make the next `/api/v1` call, and confirm it is refused within **one request** — not one access-token lifetime — and that a refresh is refused with `invalid_grant`. Evidence: the integration-test output from [[DSK-04-05]] plus a live screenshot of the desktop's disabled-account state.
9. Gate row "tokens/secrets pass storage review": walk the checklist from § 4 — the access token is never written to disk, the refresh handle exists only in the DPAPI store, and the MSIX contains no secret. Run the package content scan from [[DSK-10-03]] if it exists, otherwise inspect the extracted package and the embedded `appsettings.<channel>.json` by hand and record what was checked.
10. Gate row "startup sequence observable": export a diagnostics bundle from the running app ([[DSK-02-11]]) and confirm it contains the ordered startup steps with one correlation id and no token literal. Attach the redacted excerpt.
11. Run `winui-code-review` over the Phase 2 desktop diff as an independent reviewer — the agent doing this must not have implemented any of the tickets under review (`AGENTS.md` § Repository task workflow step 5).
