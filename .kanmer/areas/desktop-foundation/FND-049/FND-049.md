## What

Write the workstation first-run and initial-install guide — prerequisites, the required certificate-trust step, opening the `.appinstaller`, first launch, what each blocked state means, where diagnostics live, and how to switch channel — and prove it by having someone other than the author follow it on a clean Windows 11 machine.

## Why

D-002 chose a self-managed certificate, so **every** first install now begins with a per-machine trust step; if the package arrives before the trust does, the install fails with `0x800B0109` and the operator has no way to know that is a trust problem rather than a broken package. Proposal § 9.3 requires interrupted updates, invalid signatures and unavailable feeds to be tested and understood operationally. Without this guide the first pilot install becomes a support incident, and the Phase 2 exit review [[DSK-04-15]] has no reproducible install path to evidence.

3. Check the overlap with [[DSK-09-15]] before writing: that ticket owns the R7 **operator one-pager** (install · sign in · updates itself · what to do when blocked). 4. Write the prerequisites section from R7's checklist, verbatim in substance: Windows 11 x64 (24H2 recommended) signed in as the user who will use Pegasus; Microsoft Edge WebView2 runtime present (default on Windows 11, verify in Settings → Apps); network access to the feed share and the gateway; the certificate trust step; and the managed-device policy note that App Installer auto-update must not be disabled by CSP or PowerShell.
5. Write the certificate-trust step as the **first** action, with the exact commands: import the public `.cer` into `Cert:\LocalMachine\TrustedPeople` from an elevated prompt (or let Group Policy deliver it), then verify with `certutil -verifystore TrustedPeople`. State plainly that if the package arrives first the install fails with `0x800B0109` and the fix is this step followed by a retry. Never instruct anyone to use `Trusted Root`.
6. Write the install steps: open the channel's `.appinstaller` from the share and open the file; App Installer shows the package and publisher; choose Install. Note that `ms-appinstaller:?source=` protocol links do nothing on most devices since December 2023, so the file path is the only supported route.
7. Write the first-launch section describing the startup order in operator words: the app checks for updates, then checks compatibility with the gateway, then shows Login. Name the blocked states from `docs/desktop/06-ui-design/screen-specs.md` — "Update required" and the blocked screen — and say what the operator does for each. Operator vocabulary only: a sentence that explains how the system works is a defect under `docs/design/README.md`.
8. Write the verification section: `Get-AppxPackage CollisionEngineers.Pegasus` lists the version; `Get-AppxPackageAutoUpdateSettings` shows on-launch checks; the app's Settings/Diagnostics screen shows version, channel and gateway URL. Add the support-register row R7 requires (user, machine, channel, date).
9. Write the diagnostics section: where the rolling logs live under the packaged app's `ApplicationData`, and how to run the "Export diagnostics" command from [[DSK-02-11]] when support asks for a bundle. Do not describe the bundle's internals.
10. Write the uninstall/reinstall and channel-switch sections from R7: Settings → Apps → Pegasus → Uninstall (or `Remove-AppxPackage`), then repeat the install; local preferences live in the package's `ApplicationData` and go with the package; the refresh token is removed on uninstall — and verify that removal really happens, because R7 flags it as "to verify in area 04". Switching channel is uninstall, then install from the other channel's `.appinstaller`.
11. Add a short troubleshooting table with only the failures the plans record: `0x800B0109` (trust missing), no update prompt (2017/2 schema or a CSP override), "Cannot reach Pegasus" (network or VPN, because D-003 puts the feed on an internal share), and a SmartScreen warning on first download (reputation, not a signature error).
12. **Operator step**: hand the guide to someone who did not write it and have them reproduce it on a clean Windows 11 VM from a state with no certificate trusted and no package installed. Evidence to hand back: a screenshot of each numbered step, the `Get-AppxPackage` output, the `certutil -verifystore TrustedPeople` output, and a written note of every place they had to guess. Every guess is a defect to fix before the ticket closes.
