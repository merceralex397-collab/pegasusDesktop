## What

Contribute the startup-sequence, blocked-state and diagnostics content — in operator words — into the **single** workstation first-install guide that [[DSK-09-15]] owns at `docs/desktop/09-release-update-and-distribution/first-install.md`, verify the refresh-token removal that runbook R7 defers to area 04, and prove the whole install path by having someone other than the author follow it on a clean Windows 11 machine. This ticket authors **no** guide of its own.

## Why

D-002 chose a self-managed certificate, so **every** first install now begins with a per-machine trust step; if the package arrives before the trust does, the install fails with `0x800B0109` and the operator has no way to know that is a trust problem rather than a broken package. Proposal § 9.3 requires interrupted updates, invalid signatures and unavailable feeds to be tested and understood operationally. Without the startup and blocked-state content in that guide, the first pilot install becomes a support incident, and the Phase 2 exit review [[DSK-04-15]] has no reproducible install path to evidence. What this ticket must not do is produce a second page: two first-install guides at two paths is worse than one late one, so the guide has one owner ([[DSK-09-15]]) and this ticket is a contributor to it.
