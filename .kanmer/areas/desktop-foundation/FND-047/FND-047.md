## What

Add the connectivity state to the desktop: a status-bar indicator that says Pegasus is disconnected, an automatic recheck on a fixed interval, authoritative saves disabled while offline, and no command that reports success without server confirmation.

## Why

Proposal § 11.3 is prescriptive: on connectivity loss existing on-screen data stays visible, new authoritative saves are disabled or queued only as an explicit draft, the status area clearly says Pegasus is disconnected, the app rechecks automatically, and nothing is presented as complete until the server confirms it. Proposal § 8.4 adds that server-unreachable must never be shown as invalid credentials. Without this ticket an operator on a dropped VPN sees commands that appear to work and silently do not, which is the exact failure the online-required design (ADR-0104) exists to prevent.

## Implementation steps

1. Orientation. Read `docs/desktop/04-auth-session-update-and-startup/README.md` § 3 (the session failure matrix) and `docs/desktop/06-ui-design/screen-specs.md` § *Shell*. Call `get_doc_gates <this ticket id>`, then `take_ticket`. Load `pegasus-desktop`, then `winui-design`.
2. Add `IConnectivityState` to `src/Pegasus.Desktop.Infrastructure` under a `Connectivity/` capability folder, exposing a `Connected | Disconnected` value, the timestamp of the last successful server response, and a change event. Inject `TimeProvider` so the recheck interval is testable.
3. Set `Disconnected` from the HTTP pipeline itself: the `DelegatingHandler` from [[DSK-02-06]] marks the state disconnected on a transport exception or TLS failure and marks it connected on any successful response. Do **not** add a separate ping loop as the primary signal — the real traffic is the signal.
4. Add the automatic recheck: while disconnected, poll `GET /api/v1/client-compatibility` (anonymous, cheap, already required by [[DSK-04-09]]) on a fixed interval defined as a named constant in one place, and record the interval value in the plan document. On success, set `Connected` and raise the change event.
5. Bind the status bar from [[DSK-02-08]] to the state: the connected form shows the connection word plus the last sync time in Europe/London per the screen spec; the disconnected form shows "Disconnected — reconnecting". Set `AutomationProperties.AutomationId` to `Shell.Status.Connection`. Use text plus glyph, never colour alone (tier 7 requires text-plus-colour states).
6. Disable authoritative saves while disconnected: introduce one base command behaviour that every save/command view model uses — `CanExecute` returns false when `IConnectivityState` is `Disconnected`. Do not implement a queue: proposal § 11.3 allows only an explicit draft, and drafts are owned by area 05, not this ticket.
7. Keep existing on-screen data visible while disconnected — no page clears itself, no navigation is blocked, and read-only content stays readable. Logout and token clearing must remain available (§ 11.3).
8. Ensure no command reports success without a server confirmation: audit every command path added so far and assert in a test that a transport failure produces a failure state, never a success state with a local-only effect.
9. Honour reduced motion: the reconnecting indicator is a thin indeterminate `ProgressBar` per `docs/desktop/06-ui-design/tokens-and-theme.md`, with a static "Working" text equivalent when `UISettings.AnimationsEnabled` is false. No ring spinner, no full-page spinner.
10. Write view-model tests in `tests/Pegasus.Desktop.ViewModelTests`: a transport exception flips the state within one handler pass; save commands report `CanExecute == false` while disconnected; a successful recheck flips back and re-enables the commands; a transport failure never produces an invalid-credentials message.
11. Load `winui-ui-testing`, then add the disconnected and reconnect cases to `tests/Pegasus.Desktop.UITests/ui-tests.ps1` — **do not author a second harness**. That file's contract is owned and pinned by [[DSK-08-06]]: the signature is `param([Parameter(Mandatory)][int]$AppPid)` (never `$Pid`, which is read-only in PowerShell) and the pass/fail counter is its `Test-UI` helper. Add each case as a `Test-UI` case: start the local stack, sign in, then stop the gateway with `pwsh ./scripts/Invoke-LocalDevelopment.ps1 -Action Stop`, and assert with `winapp ui wait-for` that `Shell.Status.Connection` reads the disconnected text within one recheck interval and that a save button reports disabled. Restart the stack and assert the state returns. Use `wait-for`, never `Start-Sleep`. If [[DSK-08-06]] has not landed yet, create the file from the `winui-ui-testing` script template with exactly that signature and that helper so the two cannot fork, and record in the plan document that [[DSK-08-06]] takes ownership of the skeleton when it lands.
12. Capture `winapp ui screenshot` for the connected and disconnected status bar and attach both to the ticket proof.
13. Run the simplification pass over this branch's diff, record it under a dated `## Simplification pass` heading in the plan document, then open the PR into `dev`.

## Acceptance criteria

- [ ] Pulling the network (or stopping the local gateway) shows the disconnected state within one recheck interval.
- [ ] The status bar states connectivity in words, not by colour alone, under `Shell.Status.Connection`.
- [ ] Authoritative save commands are disabled while disconnected; nothing is queued silently.
- [ ] Existing on-screen data stays visible and logout stays available while disconnected.
- [ ] No command reports success without a server confirmation.
- [ ] Reconnection is automatic and re-enables the disabled commands without a restart.
- [ ] A transport failure is never surfaced as an invalid-credentials message.
