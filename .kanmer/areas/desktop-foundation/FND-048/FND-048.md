## What

Produce the `teststack`-channel `.appinstaller` file on the 2021 App Installer schema with `OnLaunch HoursBetweenUpdateChecks="0" ShowPrompt="true" UpdateBlocksActivation="true"`, and stand up the local Test/UAT feed folder that serves it, so a v1 → v2 mandatory update can be rehearsed without any production or Azure resource.

## Why

Proposal § 9.1 makes the package mechanism the layer that performs the trusted installation, and § 9.3 requires interrupted updates, unavailable feeds and rollback to be tested. Two facts make this ticket load-bearing: Visual Studio emits the 2017/2 schema, which **silently ignores** `ShowPrompt` and `UpdateBlocksActivation`, and `Package.CheckUpdateAvailabilityAsync` returns `Unknown` for a package that was not installed from an `.appinstaller` — so without a real local feed the startup orchestrator [[DSK-04-09]] cannot be exercised at all. The operator-visible consequence is a mandatory update that is discovered not to block on the day it is needed.

## Implementation steps

1. Orientation. Read `docs/desktop/09-release-update-and-distribution/appinstaller-template.md` end to end and `docs/desktop/08-testing/test-uat-stack.md` §§ *Components* and *Lifecycle*. Call `get_doc_gates <this ticket id>`, then `take_ticket`. Load `pegasus-desktop`, then `winui-packaging`.
2. Check for overlap before creating files: [[DSK-09-03]] owns the pilot and prod `.appinstaller` templates and the validator `eng/packaging/Test-AppInstaller.ps1`. This ticket owns **only** the `teststack` channel and the local feed. If [[DSK-09-03]] has already landed, add the `teststack` variant to its template generator instead of writing a second one, and record that in the plan document.
3. Create the `teststack` `.appinstaller` from the template in `docs/desktop/09-release-update-and-distribution/appinstaller-template.md` § *Template (2021 schema)*, copied literally. The root element must declare `xmlns="http://schemas.microsoft.com/appx/appinstaller/2021"` — the 2017/2 namespace silently ignores the settings below and is the single most common cause of a non-blocking "blocking" update. Keep `<MainPackage Name="CollisionEngineers.Pegasus" ProcessorArchitecture="x64">`, the `<UpdateSettings>` block with `<OnLaunch HoursBetweenUpdateChecks="0" ShowPrompt="true" UpdateBlocksActivation="true" />`, `<AutomaticBackgroundTask />` and `<ForceUpdateFromAnyVersion>true</ForceUpdateFromAnyVersion>`, and omit `<Dependencies>` because the package is self-contained.
4. Set the `teststack` values: the `AppInstaller/@Uri` and `MainPackage/@Uri` must be the exact UNC or local-share paths the workstation installs from — `\\<host>\<share>\teststack\Pegasus.appinstaller` and `\\<host>\<share>\teststack\Pegasus_<ver>_x64.msix`. App Installer records the `Uri` at install time and re-reads it on every check, so a later change breaks updates for every installed machine.
5. Set `MainPackage/@Publisher` to the exact subject of the dev certificate produced by [[DSK-02-14]] (`winapp cert generate --manifest .` matches it to `Package.appxmanifest` `Identity.Publisher`). A mismatch fails installation with a signature error, not a schema error.
6. Give the `.appinstaller` its own monotonically increasing `Version`, independent of the package version, and document in the plan that it must increase on **every** publish including a rollback publish.
7. Create the local feed as a folder with per-channel subfolders (`teststack/` at minimum) shared read-only to the test user and writable only by the publisher account. Because the production feed is SMB (D-003), do not substitute an HTTP server — the point of the stack is to rehearse the real transport. If the local host cannot share a folder, record that as an operator blocker rather than switching transport.
8. Check whether the `Publish-Feed` verb already exists in `scripts/Invoke-LocalDevelopment.ps1` from [[DSK-08-17]], which owns the `TestStack` mode and every verb in it. If it does, supply the `teststack` channel path it publishes into and change none of its behaviour; if it has not landed, add the verb under [[DSK-08-17]]'s contract, restated here verbatim so the two cannot drift — copy the freshly packaged `.msix` and its `.appinstaller` into the channel folder, bump the `.appinstaller` `Version` on every publish including a rollback publish, leave `Uri` equal to the served path, and keep the existing `-Action` values working unchanged — and record in the plan document which case applied. The script's `ValidateSet` at `scripts/Invoke-LocalDevelopment.ps1:3` is the contract other runbooks call, so it is extended and never narrowed.
9. Build and package v1: `.\BuildAndRun.ps1 /p:Configuration=Release -SkipRun` from `.codex/skills/winui-dev-workflow/`, then `winapp package <build-output-dir> --cert ./devcert.pfx --self-contained`. Publish it to the `teststack` folder and confirm the `.msix` file hash matches what the release manifest records.
10. **Operator step**: on a Windows 11 x64 workstation, trust the dev certificate once (`winapp cert install ./devcert.pfx`, elevated), open the `teststack` `.appinstaller` from the share and install. Evidence to hand back: the `Get-AppxPackage CollisionEngineers.Pegasus` output and the `Get-AppxPackageAutoUpdateSettings` output showing on-launch checks.
11. **Operator step**: build and publish v2 with a higher `MainPackage/@Version` and a higher `.appinstaller` `Version`, relaunch the app, and confirm the App Installer prompt appears and activation is blocked until the update is taken. Evidence: a screenshot of the prompt and the `Get-AppxPackage` version before and after. If no prompt appears, check the namespace first (2021 vs 2017/2) and then `Get-AppxPackageAutoUpdateSettings` for a CSP or PowerShell override, which takes precedence over the `.appinstaller`.
12. Record the fail-open behaviour explicitly in the plan document: rename or remove the `.appinstaller` from the share and relaunch — the app still launches. That is expected; the gateway minimum-version gate [[DSK-04-06]] is the fail-closed layer.
13. Run the simplification pass over this branch's diff, record it under a dated `## Simplification pass` heading in the plan document, then open the PR into `dev`.

## Guardrails

- **Azure**: no write. D-003 puts the production feed on an in-house UNC share, so nothing here touches an Azure resource; do not create a storage account "just for the test feed".
- **Scope boundary**: may touch the packaging assets for the `teststack` channel, and may extend `scripts/Invoke-LocalDevelopment.ps1` only under [[DSK-08-17]]'s `TestStack` contract — this ticket does not own that script or the `Publish-Feed` verb. Must not touch the pilot or prod `.appinstaller` templates ([[DSK-09-03]]), the production feed ([[DSK-09-10]]), `src/Pegasus.Web`, or `scripts/Build-ReleaseArtifacts.ps1`.
- **Traps**: One lifecycle script, one `Publish-Feed` verb — [[DSK-08-17]] owns it and [[DSK-04-12]] supplies the `teststack` channel; a second verb or a sibling script is a stop condition. The 2017/2 schema silently ignores `ShowPrompt` and `UpdateBlocksActivation` — always assert the namespace. `ms-appinstaller:` has been disabled by default since December 2023; publish the file path, not the protocol link. CSP/Intune settings override PowerShell settings, which override the `.appinstaller` — check `Get-AppxPackageAutoUpdateSettings` when an update does not apply. A side-loaded MSIX not installed from an `.appinstaller` makes `CheckUpdateAvailabilityAsync` return `Unknown`. Package identity (`Identity.Name`, `Publisher`) must be settled before any user installs; changing it later is a different app.
