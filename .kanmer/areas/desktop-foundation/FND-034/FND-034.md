## What

Create the `src/Pegasus.Desktop/Styles/` resource-dictionary set specified by the design authority mapping, merge `Pegasus.Theme.xaml` from `App.xaml` after `XamlControlsResources`, and enforce that no view carries a colour, font-size or corner-radius literal — every value comes from a `{ThemeResource}` key with Light, Dark and HighContrast variants.

## Why

Proposal § 14.10 requires a theme system, and `docs/design/README.md` is the binding design authority for every UI change (`AGENTS.md` § Simplicity rails). `docs/desktop/06-ui-design/tokens-and-theme.md` already resolves the authority's tokens into WinUI keys, file names and a load order, and states the rule that a value change starts in the authority, never in the dictionary. Without this ticket [[DSK-02-08]] and every area 05 slice would hard-code colours, and a high-contrast operator would be locked out. Operator-visible consequence: forced-colours mode must govern the whole application, and green must never read as "progress".

## Implementation steps

1. Orient: read the plan row, read `docs/desktop/06-ui-design/tokens-and-theme.md` in full and `docs/design/README.md` § Tokens, then `get_doc_gates <this ticket id>` and `take_ticket` on branch `task/desktop-theme` from `origin/dev`.
2. **Agree ownership with [[DSK-06-01]] first.** That ticket authors the same dictionaries from the design side. Decide in the ticket plan which one writes the token values and which one wires and enforces them; do not produce two copies of the palette. The default split this ticket assumes: [[DSK-06-01]] owns the values, this ticket owns the file structure, the `App.xaml` merge and the enforcement.
3. Create the eight files under `src/Pegasus.Desktop/Styles/` with exactly the names in the plan's load order: `Tokens.Colors.xaml`, `Tokens.Typography.xaml`, `Tokens.Spacing.xaml`, `Tokens.Shape.xaml`, `Tokens.Focus.xaml`, `Icons.Lucide.xaml`, the `Controls.*.xaml` set, and `Pegasus.Theme.xaml` which merges them in that order.
4. In `Tokens.Colors.xaml` declare `ResourceDictionary.ThemeDictionaries` with keys `Light`, `Dark` **and** `HighContrast` — never `Default` (`winui-design` skill theming rule). Copy every key and value from the colour-token table in `docs/desktop/06-ui-design/tokens-and-theme.md` § Colour tokens verbatim; do not paraphrase or re-derive a value.
5. Map every HighContrast entry to a system colour resource (`SystemColorWindowColor`, `SystemColorWindowTextColor`, `SystemColorHighlightColor`, `SystemColorHighlightTextColor`, `SystemColorButtonFaceColor`, `SystemColorButtonTextColor`, `SystemColorGrayTextColor`, `SystemColorHotlightColor`) exactly as the table's HighContrast column specifies, so forced-colours mode governs.
6. In `Tokens.Typography.xaml` define the eight styles from the typography table, each `BasedOn` its named built-in WinUI text style, and set `Typography.NumeralAlignment="Tabular"` on the numeric styles. No raw `FontSize` may appear in any view (`winui-code-review`).
7. In `Tokens.Spacing.xaml` define `PegasusSpace1`…`PegasusSpace9` as `x:Double` values 4, 8, 12, 14, 18, 24, 32, 40, 64 and `PegasusGutter` = 24. In `Tokens.Shape.xaml` define `ControlCornerRadius`, `OverlayCornerRadius` and border thickness. In `Tokens.Focus.xaml` override the focus visual to the `PegasusFocusBrush` 3 px ring.
8. Merge in `src/Pegasus.Desktop/App.xaml`: `XamlControlsResources` first, then `Pegasus.Theme.xaml`, so the project overrides win. Reference `Pegasus.Theme.xaml` exactly once in the whole application.
9. Enforce the rule mechanically: add a test to `tests/Pegasus.Desktop.ViewModelTests` (or an architecture fact in `tests/Pegasus.ArchitectureTests` if the check is pure text) that scans `src/Pegasus.Desktop/**/*.xaml` excluding `Styles/` and fails on a hex colour literal (`#` followed by 3, 4, 6 or 8 hex digits), on a raw `FontSize=` attribute, and on a `CornerRadius=` numeric literal. Prove it red first with a temporary fixture string, then green.
10. Verify the three themes visually: run the app under Light, under Dark, and with Windows high contrast enabled, capturing one screenshot per theme of the shell from [[DSK-02-08]]. Attach all three to the ticket proof.
11. Run the contrast check named in the plan: every foreground/background pair must reach 4.5:1 for body text and 3:1 for large text and UI boundaries in Light and Dark. Record any pair that fails as an open question for the design authority rather than silently adjusting the authority's Light values — the Dark column is explicitly an assumption to be adjusted by review, the Light column is authority.
12. Run the `winui-code-review` theming checklist, then the simplification pass recorded under a dated `## Simplification pass` heading in the ticket plan, then open the PR into `dev`.
