## What

Add a `desktop-build` job to `.github/workflows/ci.yml` on `windows-latest` that restores with `--locked-mode`, builds the desktop projects x64 Release and runs `tests/Pegasus.Desktop.ViewModelTests` and `tests/Pegasus.ArchitectureTests` — without slowing or breaking the existing lanes.

## Why

Proposal § 21.2 lists the CI stages (locked restore, Release build, unit and view-model tests, build the MSIX, upload) and § 24 Phase 1 requires a CI Windows build before the gate. The existing workflow `repository-check` runs seven of its nine jobs on `windows-latest` through the composite action `.github/actions/dotnet-build`, which restores and builds the whole `Pegasus.slnx`; once the desktop projects join the solution every one of those lanes starts building them, which is both slower and a way for a desktop failure to redden an unrelated lane. Constraint C-01 makes that cost real: when the repository becomes private, Windows runner minutes bill at a 2× multiplier. Operator-visible consequence: a broken desktop build must be caught on the PR, not at the release terminal.

2. **Decide and record the solution split before editing the workflow.** The composite action builds the whole `Pegasus.slnx`, so `unit`, `sql-integration` and `browser` would all start building the desktop projects. 3. Add a `desktop-build` job to `.github/workflows/ci.yml`: `needs: changes`, `if: needs.changes.outputs.build == 'true'`, `runs-on: windows-latest`, `timeout-minutes: 30`, matching the style of the existing `unit` job (a comment above the job saying what it proves and why it is on Windows).
4. Confirm the path gate needs no change: `scripts/Get-CiChangeFlags.ps1:11` `$buildPattern` already matches `^(src|tests)/`, `\.csproj$`, `\.props$` and `packages\.lock\.json$`, so every desktop path sets `build=true`. State that finding in the ticket plan rather than editing the script; if the split in step 2 adds a new file type (for example `.slnf`), add it to the pattern **and** to `scripts/Test-CiChangeFlags.ps1`'s regression cases.
5. Job steps, in order: `actions/checkout@v7`; `actions/setup-dotnet@v6` with `dotnet-version: 10.0.x` and `cache: true` keyed on `global.json`, `Directory.Packages.props`, `src/**/packages.lock.json`, `tests/**/packages.lock.json`; `dotnet restore ./Pegasus.slnx --locked-mode -r win-x64` (the RID must match the one the desktop lock files were generated with, plan § 7); `dotnet build ./Pegasus.slnx --configuration Release --no-restore -p:Platform=x64`.
6. Test step, chained with `&&` so a failing first project cannot be hidden by pwsh reporting only the last exit code — the reason the existing `unit` job chains: `dotnet test ./tests/Pegasus.Desktop.ViewModelTests/Pegasus.Desktop.ViewModelTests.csproj --configuration Release --no-build && dotnet test ./tests/Pegasus.ArchitectureTests/Pegasus.ArchitectureTests.csproj --configuration Release --no-build`.
