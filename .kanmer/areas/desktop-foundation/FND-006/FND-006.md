## What

Write the four flow-derived ADRs of the reserved block — ADR-0102 (existing Pegasus credentials; desktop session = short-lived access token plus rotated refresh token), ADR-0106 (the Microsoft Graph intake worker stays central and unattended), ADR-0107 (Box and DVLA/DVSA credentials stay behind the gateway; no long-lived provider secret in the package) and ADR-0109 (desktop diagnostics bundle beside the existing Application Insights; no new telemetry fleet) — each with its six-question cloud-justification table answered from the recorded flows, and add their index rows.

## Why

These four decisions are the ones that can only be written honestly **after** the current flows are recorded: what the authentication path actually is today, how Graph intake really runs unattended, where the Box and DVLA/DVSA credentials actually live, and what telemetry already exists. Writing them from memory is how a conversion invents a requirement — the cloud-justification test in proposal §4 demands evidence per answer, not prose. The flow records are produced by [[DSK-01-06]] (authentication, database/migrations, Graph intake) and [[DSK-01-07]] (Box custody, DVLA/DVSA, report rendering) into `docs/desktop/01-inventory-and-parity/flow-records.md`. Without these ADRs, area 04 (auth and session), area 07 (integrations) and area 10 (observability) have no recorded authority for the boundaries they are built to respect.
