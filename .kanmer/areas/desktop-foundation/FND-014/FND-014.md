## What

Re-derive the complete Razor page-model and handler inventory of `src/Pegasus.Web` from the code at the current fork head, and reconcile it against the 46 pre-populated rows (`PAR-01`…`PAR-46`) of `docs/desktop/01-inventory-and-parity/parity-matrix.md`, so every later parity ticket starts from a verified skeleton instead of a dated snapshot.

## Why

Proposal §13 requires the conversion to be driven by a repository-derived feature-parity matrix, "not by page count", reconciled with exact routes, controllers, services, entities and existing tickets during Phase 0. The matrix was pre-filled on 2026-08-23 from fork `main` `191ddf33`, and upstream `collisionengineers/pegasus` `main` is 32 commits ahead of that commit, so a row can already be stale. Operator-visible consequence: a handler that exists in the web app but has no matrix row becomes a desktop capability nobody specified, and the Phase 0 exit gate "every current production capability has an inventory row" cannot be honestly claimed. Siblings [[DSK-01-02]], [[DSK-01-03]], [[DSK-01-04]] and [[DSK-01-05]] populate the rows this ticket confirms; [[DSK-00-12]] registers the matrix as one canonical path.
