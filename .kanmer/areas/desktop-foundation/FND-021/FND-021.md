## What

Verify every row of `docs/desktop/01-inventory-and-parity/azure-resource-register.md` against the live `rg-pegasus-prod` estate using **read-only** Azure MCP tools, fill each row's "Used by (code path)" and proposal §19 target position, confirm the "Declared absent" list, and attach the raw tool output as the ticket proof. Zero Azure writes.

## Why

Proposal §19 opens with "No Azure service is deprovisioned during conversion. The first action is to inventory and tag every current resource and identify which code path uses it", and §24 Phase 0's second exit-gate item is "Every Azure resource has an owner/use statement". §29 item 3 says to export the inventory **without removing anything**. Operator-visible consequence: without a verified owner per resource, a later cleanup deletes something a live workflow still uses, and "a service is not unused merely because no developer remembers it" (§19.2). This register is also the input to the cloud-dependency records in area 11 and to ADR-0101.

## Guardrails

The permitted tools are exactly the read-only Azure MCP set `subscription_list`, `group_list`, `group_resource_list`, `storage`, `keyvault` (names only), `sql`, `containerapps`, `functionapp`, `monitor`, `applicationinsights`, `acr`, `role`, `pricing`, `advisor`, `resourcehealth` — list/show only. Tagging is a write and is deferred to area 11 behind exact-target approval (`docs/runbook.md` § Live-operation approval matrix). If a write appears necessary, produce the approval text and stop.
- **Scope boundary**: editable files are `docs/desktop/01-inventory-and-parity/azure-resource-register.md` and, if drift is found, `docs/desktop/11-azure-disposition/README.md`. It must not touch `infra/`, `src/`, or any deployment.
- **Traps**: nothing is deprovisioned before cutover, observed use and rollback approval — "a service is not unused merely because no developer remembers it"; App Insights is capped at 0.1 GB/day so an empty query is not evidence of no traffic (upstream `PLAT-034`); `docs/operations.md:295` ("release 14") contradicts the release table at `:311-332` — the table is authoritative; the activation gates are fail-closed, so a Worker function reported as disabled is the designed state, not a fault.
