## What

Verify — do not rebuild — the fork's Kanmer board structure that an agent session seeded on **2026-08-24**: the 16 areas, the 11 `HZN` horizon groups (one per proposal phase), the 13 plan-derived `EPIC` groups plus the deliberate `EPIC-014` upstream carry-over group, and a `context.md` on every group. Repair only what is missing or wrong, and reconcile the board's realised shape with the table in the area plan.

## Why

The initial board seed was performed on 2026-08-24 by an agent session working from this plan set (locked decision L-05: the board is seeded from these plans). Seeding is **ungated** in Kanmer — `create_group` and `create_item` succeed in any stage — so a second seeding run silently duplicates groups and tickets instead of failing. The remaining risk is therefore not "is it seeded" but "is the seed correct and complete": a missing horizon or an epic without a `context.md` means every ticket in that batch loses the constraint that binds it, which `AGENTS.md` § Kanmer operating instructions requires an agent to read before starting ("If the ticket is in a group, read the group's `context.md` too"). This ticket is the Phase 0 governance exit-gate evidence that `get_status` shows the expected board. [[DSK-00-04]] does the same for the 208 conversion tickets.
