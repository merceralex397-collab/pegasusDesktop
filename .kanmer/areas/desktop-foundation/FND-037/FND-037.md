## What

Add executable architecture facts to `tests/Pegasus.ArchitectureTests/DependencyDirectionTests.cs` that fail on a forbidden desktop reference (`Pegasus.Infrastructure`, Entity Framework, Azure SDKs, Box, Microsoft Graph, `Microsoft.AspNetCore.*`), on a `Pegasus.Contracts` dependency of any kind, and on a `WebView2` element appearing in desktop XAML — each proven red with a fixture before it goes green.

## Why

The Phase 1 exit gate has two rows this ticket owns: "No WebView/web dependency in the package" and "Architecture boundaries enforced — new `DependencyDirectionTests` facts red on a forbidden reference (prove by a temporary failing fixture)". Proposal § 5.3 states the rule ("Desktop projects must not reference Entity Framework database contexts, Azure SDK credentials or server integration implementations") and the project skill records the single permitted WebView2 use — the isolated, never-visible HTML→PDF report renderer under ADR-0108, which is area 07 and does not exist yet. Operator-visible consequence: a desktop that pulls in Entity Framework is one refactor away from connecting a workstation directly to the production database, which programme exit criterion 9 forbids outright.
