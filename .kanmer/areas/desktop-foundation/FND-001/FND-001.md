## What

Create the missing `dev` branch on the fork `merceralex397-collab/pegasusDesktop` at the frozen baseline commit `191ddf334208b8966dc5e32f4f597e434a086233`, and record that the branch exists in `docs/desktop/README.md` beside the baseline line that is already there.

## Why

The fork has **only** `main` — `git branch -a` and `git tag` on 2026-08-23 show no `dev` and no tags. Every rule the conversion inherits assumes `dev` exists: `AGENTS.md` § Repository task workflow step 2 cuts each task worktree from `origin/dev`; `docs/engineering.md` § Branches and delivery promotes `dev` → `main` as an exact-SHA fast-forward; and the CI `changes` job runs `git fetch --no-tags origin refs/heads/dev:refs/remotes/origin/dev` followed by `scripts/Test-MainBranchHistory.ps1 … -ReleaseBranch origin/dev` on every push to `main` (`.github/workflows/ci.yml:24-32`), which cannot pass while `refs/heads/dev` does not exist. Proposal §29 item 1 ("choose the fork or protected conversion branch and freeze its baseline commit") is exactly this ticket. Until it lands no conversion ticket can open a PR the way the workflow requires, so this is the first ticket of the programme. [[DSK-00-02]] adds the read-only upstream remote on top of the branch this creates.
