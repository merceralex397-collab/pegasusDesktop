## What

Build one testable startup state machine that runs, in order: the App Installer package update check, the gateway compatibility gate with a 24-hour fail-closed cache, a non-blocking WebView2 runtime presence check, and session restore or native login — each step with a user-visible state and a diagnostics log line carrying the correlation id.

## Why

Proposal § 9.2 defines this exact sequence and § 9.3 requires it to be fail-closed: because App Installer skips its check when the feed is unreachable, the gateway gate is the only layer that can stop an obsolete client, and "prolonged inability to check compatibility should eventually prevent work rather than allow indefinite offline use". Without an orchestrator the steps end up scattered across `App.xaml.cs` and untestable, and the operator-visible consequence is a workstation that silently keeps working on a version the gateway has already blocked.

## Implementation steps

1. Orientation. Read `docs/desktop/04-auth-session-update-and-startup/README.md` § 3 decisions 6–7 and § 7 (risks and traps) in full, and `docs/desktop/09-release-update-and-distribution/appinstaller-template.md` § *Known behaviours*. Call `get_doc_gates <this ticket id>`, then `take_ticket`. Load `pegasus-desktop`, then `winui-dev-workflow`.
2. Confirm the platform API contract before coding: `microsoft_docs_search` for `Package.CheckUpdateAvailabilityAsync` (the five results `NoUpdates | Available | Required | Unknown | Error`, and the documented "Access denied" when called on `Package.Current`) and for `PackageManager.RequestAddPackageByAppInstallerFileAsync`. Record the fetch date in the ticket research document.
3. Add `StartupOrchestrator` to `src/Pegasus.Desktop.Infrastructure` under a `Startup/` capability folder as a plain state machine with no WinUI types and no `DispatcherQueue`, so it is testable head-less. Define one enum of states: `CheckingForUpdate`, `UpdateRequired`, `CheckingCompatibility`, `Blocked`, `RuntimeWarning`, `RestoringSession`, `SignInRequired`, `Ready`. Inject `IPackageUpdateProbe`, `ICompatibilityClient`, `IRuntimePresenceProbe`, `ISessionClient`, `TimeProvider` and the diagnostics writer — every one behind an interface so tests can fake them.
4. Implement the package update probe exactly as the trap requires: `new PackageManager().FindPackageForUser(string.Empty, Package.Current.Id.FullName)` and call `CheckUpdateAvailabilityAsync()` on the returned package — **never** on `Package.Current`, which throws Access denied. Treat `Unknown` and `Error` as "not installed from an `.appinstaller`": log and continue, do not block.
5. Handle the results: `Required` → state `UpdateRequired` and no further work; `Available` → log and continue to the compatibility gate; `NoUpdates`/`Unknown`/`Error` → continue. The "Update now" command on the update-required screen calls `PackageManager.RequestAddPackageByAppInstallerFileAsync` against the channel's `.appinstaller` path from the embedded channel configuration; note that `ms-appinstaller:` is disabled by default and must not be used.
6. Implement the compatibility gate: `GET /api/v1/client-compatibility` (anonymous) sending `X-Pegasus-Client-Version` from `Package.Current.Id.Version`. On success, persist the response and the retrieval timestamp through the bounded cache from [[DSK-02-06]]. On a `urn:pegasus:problem:client-unsupported` response, go to `UpdateRequired` carrying the returned `minimumVersion`.
7. Implement the 24-hour fail-closed rule with `TimeProvider`: if the endpoint is unreachable, use the cached response only while it is younger than 24 hours; at 24 hours or older, go to `Blocked` and perform no work. There must be **no** bypass switch, environment variable, or configuration key that extends this — the plan states the cache must not be extended "for convenience".
8. Implement the WebView2 runtime presence probe **without** adding a `Microsoft.Web.WebView2` package reference: the architecture facts from [[DSK-02-12]] fail the build on that reference until ADR-0108 lands. Detect the runtime by reading the documented Edge WebView2 client registry value; confirm the exact key path with `microsoft_docs_search` for "WebView2 runtime detection registry key" before writing it. A missing runtime produces state `RuntimeWarning` and a log line only — it never blocks startup in Phase 2.
9. Implement session restore: if the DPAPI store holds a refresh handle, call `ISessionClient.RefreshAsync`; success → `Ready`; `RefreshRevoked` → clear the store and go to `SignInRequired`; `AccountDisabled` → `Blocked` with the disabled reason.
10. Emit one structured diagnostics line per step through the writer from [[DSK-02-06]] — step name, outcome, elapsed milliseconds, correlation id — and reuse a single correlation id for the whole startup sequence so a support bundle shows the ordered steps.
11. Call the orchestrator from `src/Pegasus.Desktop/App.xaml.cs` after the single-instance redirection from [[DSK-02-10]] and before the main window is shown, and bind each state to its screen: `UpdateRequired` and `Blocked` to the full-window rail-less screens from [[DSK-04-08]], `SignInRequired` to the sign-in page, `Ready` to the shell.
12. Write view-model/state-machine tests in `tests/Pegasus.Desktop.ViewModelTests` with fakes for the package probe, the compatibility client and the clock: `Required` blocks; unreachable with a 23-hour-old cache proceeds; unreachable with a 25-hour-old cache blocks; `client-unsupported` blocks with the minimum version; missing WebView2 warns but proceeds; revoked refresh routes to sign-in. Run `dotnet test tests/Pegasus.Desktop.ViewModelTests`.
13. **Operator step**: on a Windows 11 workstation with the dev certificate trusted, install the package from the local Test/UAT `.appinstaller` feed built by [[DSK-04-12]], publish a higher version to that feed, relaunch, and confirm the real `Required` path end to end. The operator hands back: the `Get-AppxPackage CollisionEngineers.Pegasus` version before and after, a screenshot of the update-required screen, and the rolling-log excerpt showing the ordered startup lines. A side-loaded MSIX **not** installed from an `.appinstaller` returns `Unknown` and cannot prove this path.
14. Run the simplification pass over this branch's diff, record it under a dated `## Simplification pass` heading in the plan document, then open the PR into `dev`.

## Acceptance criteria

- [ ] Every startup state has a screen and a diagnostics log line sharing one correlation id.
- [ ] `CheckUpdateAvailabilityAsync` is called on the package returned by `PackageManager.FindPackageForUser`, never on `Package.Current`.
- [ ] `Required` shows the update-required screen and launches the channel's `.appinstaller`; no other work happens.
- [ ] A compatibility response older than 24 hours, or an unreachable gateway beyond that window, blocks all work; no bypass exists in code or configuration.
- [ ] A `client-unsupported` problem shows the minimum version returned by the gateway.
- [ ] A missing WebView2 runtime warns and continues; it does not block in Phase 2.
- [ ] The orchestrator is exercised in tests with no `DispatcherQueue` and no real package or gateway.
- [ ] No `Microsoft.Web.WebView2` package reference was added.
