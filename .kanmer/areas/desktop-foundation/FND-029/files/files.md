## Ripple effects

- **Tests.** `tests/Pegasus.ArchitectureTests` gains one project reference, one array entry, one
  no-dependency fact and one new serialization file. `dotnet test` over that project is the gate.
  `tests/Pegasus.Core.Tests` and `tests/Pegasus.IntegrationTests` are unaffected — neither references
  Contracts.
- **Restore graph.** A new `src/Pegasus.Contracts/packages.lock.json` must be generated with
  `--force-evaluate` and committed, or `dotnet restore ./Pegasus.slnx --locked-mode` fails in the CI
  composite action (`.github/actions/dotnet-build/action.yml:22`) on every lane.
- **The server entry point.** `Pegasus.Server.slnf` ([[FND-028]]) must gain this path, and
  [[FND-028]]'s `ServerSolutionFilterContainsExactlyTheServerProjects` fact will fail until it does —
  which is the intended coupling, not an accident.
- **Callers — none yet, by design.** No production code consumes these types in this ticket.
  [[GWY-001]] is the first consumer and extends them in place; [[FND-031]] consumes `PegasusHeaders`;
  [[FND-045]] (plan handle `DSK-04-09`) consumes `ClientCompatibilityResponse`.
- **OpenAPI and the generated client — a *future* ripple, not a present one.** There is no
  `openapi/` directory in the repository today (`ls openapi` → *No such file or directory*), so this
  ticket cannot and does not update `openapi/pegasus-v1.json`. [[GWY-004]] (plan handle `DSK-03-04`)
  creates the snapshot and [[GWY-005]] (plan handle `DSK-03-05`) generates the Kiota client from it;
  from that point on, every change to a type in this project ripples into both. Record that as the
  standing consequence of adding a member here.
- **Documentation.** `docs/current-architecture.md` § Components and dependency direction (`:55`)
  gains a row. `scripts/Test-DocumentationLinks.ps1` runs in the CI `documentation` lane
  (`.github/workflows/ci.yml:71-87`) and will check any link added.
- **Nothing in `src/Pegasus.Web` changes.** Adding a project reference from Web to Contracts is
  [[GWY-001]]'s step, not this one's — `ProjectReferencesFollowTheModularMonolithDirection`
  (`DependencyDirectionTests.cs:111-125`) asserts Web references exactly `["Pegasus.Core", "Pegasus.Infrastructure"]`
  today, so touching that here would break a fact this ticket has no mandate over.
