## What

Create the shared DTO project `src/Pegasus.Contracts` (`net10.0`, zero non-BCL package references, zero project references) holding the envelope types the gateway and the desktop both need — paging, RFC 9457 problem details with the stable `urn:pegasus:problem:<slug>` catalogue, the concurrency fields, the operation key, the request header names — plus the first concrete DTO, the client-compatibility response.

## Why

Proposal § 10.3 requires a generated client and forbids hand-written duplicate DTOs; area 03 § 3 records that `Pegasus.Contracts` holds request/response/problem DTOs with no EF, ASP.NET or WinUI types and that Core records are never exposed directly because they carry `ActionActor` and server-only members (`src/Pegasus.Core/Workflow/CaseWorkflowContracts.cs:182`). Every later gateway endpoint ([[DSK-03-01]]) and every desktop call ([[DSK-02-06]]) depends on this project existing with one problem-type list and one paging shape — the repository's "one list per concept" rail (`AGENTS.md` § Simplicity rails) makes a second copy in either layer a defect. Operator-visible consequence: without one problem catalogue the desktop cannot map a server failure to the right operator sentence, so failures surface as generic errors.

1. Orient: read the plan row and the plan sections named under Source of truth, read `src/Pegasus.Core/Workflow/CaseWorkflowContracts.cs:120-200`, then `get_doc_gates <this ticket id>` and `take_ticket` on branch `task/pegasus-contracts` from `origin/dev`.
2. Create `src/Pegasus.Contracts/Pegasus.Contracts.csproj` copying the shape of `src/Pegasus.Core/Pegasus.Core.csproj`: `Microsoft.NET.Sdk`, `<TargetFramework>net10.0</TargetFramework>`, `<RuntimeIdentifiers>linux-x64;win-x64</RuntimeIdentifiers>`, `ImplicitUsings` and `Nullable` enabled. No `PackageReference` and no `ProjectReference` at all — `System.Text.Json` ships in the shared framework.
3. Create `src/Pegasus.Contracts/Paging/PagedResult.cs`: `public sealed record PagedResult<T>(IReadOnlyList<T> Items, int Page, int PageSize, int? Total)`. Page size cap is 200 (area 03 § 3 Paging row); express it as `public const int MaxPageSize = 200;` on a `PagingLimits` static class in the same folder so the gateway and the desktop share one number.
4. Create `src/Pegasus.Contracts/ProblemDetails/PegasusProblemTypes.cs` holding `public const string Prefix = "urn:pegasus:problem:";` and one `const string` per slug, exactly this catalogue and no other: `validation`, `not-authorized`, `version-conflict`, `lease-conflict`, `lease-expired`, `operation-conflict`, `client-unsupported`, `password-change-required`, `account-disabled`, `provider-unavailable`, `not-found`, `rate-limited`, `maintenance` (`docs/desktop/03-gateway-api-and-data/README.md` § 3, Problem details row). Adding a fourteenth slug is an area-03 decision, not a step here.
5. Create `src/Pegasus.Contracts/ProblemDetails/PegasusProblem.cs`: a record carrying the RFC 9457 members (`Type`, `Title`, `Status`, `Detail`, `Instance`) plus `CorrelationId` (always present) and an optional `Extensions` dictionary. It must never carry a payload dump. Add `CurrentVersion` and `MinimumVersion` as typed extension accessors, because the `version-conflict` and `client-unsupported` problems carry them.
6. Create `src/Pegasus.Contracts/Requests/MutationEnvelope.cs` mirroring `CaseMutationRequest` minus the server-only actor: `long ExpectedVersion`, `string OperationKey`, `string Reason`, `string EditLeaseToken`. Add `OperationKeys.MaxLength = 100` and the desktop prefix `desk:` as constants (area 03 § 3 Idempotency row). Do **not** copy `ActionActor` into Contracts — it is a Core type the server owns.
7. Create `src/Pegasus.Contracts/PegasusHeaders.cs` with `public const string ClientVersion = "X-Pegasus-Client-Version";` and `public const string CorrelationId = "X-Correlation-Id";` so [[DSK-02-06]]'s HTTP pipeline and area 03's middleware use one list.
8. Create `src/Pegasus.Contracts/Responses/ClientCompatibilityResponse.cs` with exactly the fields area 04 § 3 item 5 specifies: `string MinimumVersion`, `string CurrentVersion`, `string Channel`, `string? MaintenanceMessage`, `int ValidForSeconds`. This is the first DTO because it is the first endpoint the desktop calls.
9. Enums serialise as strings: add `[JsonConverter(typeof(JsonStringEnumConverter))]` on every enum declared in this project, and add a `PegasusJson` static class exposing a single configured `JsonSerializerOptions` (`PropertyNamingPolicy = JsonNamingPolicy.CamelCase`, `DefaultIgnoreCondition = JsonIgnoreCondition.WhenWritingNull`) so both sides serialise identically. Use `microsoft_code_sample_search` for `JsonStringEnumConverter System.Text.Json` if the attribute form is unclear.
10. Register the project: add `<Project Path="src/Pegasus.Contracts/Pegasus.Contracts.csproj" />` to the `/src/` folder in `Pegasus.slnx`, add the same path to the server entry point created by [[DSK-02-03]] (Contracts is `net10.0` and must build on Linux), and extend the expected array in `DependencyDirectionTests.ApplicationSolutionExcludesSourceWorkspaces` (`tests/Pegasus.ArchitectureTests/DependencyDirectionTests.cs:137-149`) with `src/Pegasus.Contracts/Pegasus.Contracts.csproj` in ordinal position.
