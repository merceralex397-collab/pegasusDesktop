## What

Configure `upstream` = `https://github.com/collisionengineers/pegasus` as a **read-only** remote on the fork, then land the 32 commits that upstream `main` carried ahead of the fork on 2026-08-23 through the normal route: a task branch, a PR into `dev`, an independent review, and an exact-SHA promotion of `dev` to `main`.

## Why

The fork's `main` `191ddf33` **is an ancestor** of upstream `main` `7d6a948a`, which was 32 commits ahead on 2026-08-23 (releases 21–24 plus the PLAT-039, DOCS-010, MAIL-011/012, ENG-013 and CASE-019 fixes). The web application is still live and still receiving those fixes, and the evolved gateway of L-01 is built on the same `Pegasus.Web`, so the conversion has to keep taking them until cutover — proposal §6.3 ("the current web projects remain temporarily", "no permanent second Pegasus repository") and the branching flow item 2 in the area plan. Falling behind upstream means the first gateway change is written against stale code and the parity matrix cites files that have already moved. The sync direction is one-way for a reason: pushing the fork's conversion work into `collisionengineers/pegasus` would put unreleased desktop changes into the live web app's release line. [[DSK-00-01]] must have created `dev` first; [[DSK-01-10]] is the same first sync seen from the inventory plan — one of the two executes it and the other records the result, so claim both before starting.

## Implementation steps

1. Orient: read the plan row and § 3 item 2, `docs/engineering.md` lines 1–52, and `docs/desktop/01-inventory-and-parity/upstream-kanmer-carryover.md` lines 1–20. Call `get_doc_gates <this ticket id>`, then `take_ticket`.
2. Add the remote and disable its push URL in the same breath, so no later command can push the fork upstream by accident:
   ```
   git remote add upstream https://github.com/collisionengineers/pegasus.git
   git remote set-url --push upstream DISABLED_NO_PUSH_TO_UPSTREAM
   git remote -v
   ```
   Done looks like: `upstream … (fetch)` shows the real URL and `upstream DISABLED_NO_PUSH_TO_UPSTREAM (push)`.
3. Fetch and record the upstream heads: `git fetch upstream --no-tags` then `git rev-parse upstream/main` — expected `7d6a948a…` as read on 2026-08-23. If upstream has moved on, record the new SHA in the ticket and sync to that; do not sync to a stale SHA.
4. Prove the merge is a fast-forward and count the work:
   ```
   git merge-base --is-ancestor 191ddf334208b8966dc5e32f4f597e434a086233 upstream/main; echo $?
   git rev-list --count 191ddf334208b8966dc5e32f4f597e434a086233..upstream/main
   ```
   Expected: `0`, then `32` (or the current count, recorded). A non-zero first result means the histories have diverged — stop and raise it, do not force anything.
5. Create the task worktree from `origin/dev` as the workflow requires: `git worktree add ../pegasus-worktrees/upstream-sync -b task/upstream-sync-2026-08 origin/dev`, then `git merge upstream/main` inside it. Expected: a fast-forward or a clean merge commit with no conflicts.
6. Read the diff before proposing it: `git diff origin/dev...HEAD --stat` and `git log --oneline origin/dev..HEAD`. Expect Razor/web changes the conversion eventually retires — **merge them anyway**; the web app is live and upstream owns them. Do not "fix forward" in the fork anything upstream owns; raise it upstream instead.
7. Check the ADR namespace after the merge: `ls docs/adr/` and `grep -n '^| \[0' docs/adr/README.md`. Every upstream ADR must stay below `0100`; the conversion's reserved block ADR-0100…ADR-0110 (`AGENTS.md` § ADR conventions) must be untouched. A collision is a stop condition.
8. Run the local gates the CI lanes mirror: `pwsh ./scripts/Test-DocumentationLinks.ps1`, `pwsh ./scripts/Test-TestMarkdownPlacement.ps1`, `pwsh ./scripts/Test-MigrationGrants.ps1`, `pwsh ./scripts/Test-TestShard.ps1`. All exit 0.
9. Open the PR into `dev` (`gh pr create --base dev`), and have `pegasus-desktop-reviewer` review the **sync diff** specifically for changes that touch files the conversion plans already claim (gateway composition in `src/Pegasus.Web/Program.cs`, contracts, migrations). Merge only with `repository-check` green.
10. **Operator step** — promote `dev` to `main` by exact SHA, with the literal words `MERGE AUTH GRANTED` given immediately before the push:
    ```
    git fetch origin --prune
    git rev-parse origin/main origin/dev
    git merge-base --is-ancestor origin/main origin/dev
    git push --atomic --force-with-lease=refs/heads/dev:<reviewed-dev-sha> origin <reviewed-dev-sha>:refs/heads/main <reviewed-dev-sha>:refs/heads/dev
    git fetch origin --prune && git rev-parse origin/main origin/dev
    ```
    Evidence back: both heads read back equal to `<reviewed-dev-sha>`. A GitHub merge/squash/rebase is not a promotion and does not substitute.
11. Confirm the sync landed: `git fetch upstream --no-tags && git log --oneline dev..upstream/main` prints nothing, and `docs/operations.md` § Production environment now carries the releases 21–24 rows that came with the merge.
12. Record the rule in the ticket plan and the proof: **never** `git push upstream` in any form; the sync is one-way until the D-001 freeze, and the freeze itself is agreed with the upstream owners in [[DSK-00-10]].
