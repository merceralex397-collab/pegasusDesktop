## What

After [[DSK-01-10]] lands the first sync, repeat the one-way `upstream/main` → fork `dev` sync after each upstream release, up to and including the final merge at the D-001 freeze, **re-deriving the range from `upstream/main` HEAD every time**. Each repetition records the head synced, the commit count, and every upstream ticket the sync brought.

## Why

`docs/desktop/01-inventory-and-parity/upstream-kanmer-carryover.md` § Code drift states the repeat rule and [[DSK-00-02]] states the obligation, but [[DSK-01-10]] and [[DSK-00-02]] both own only the **first** sync at `7d6a948a`. Five known items already sit outside that range — upstream `DOCS-013`, upstream `PLAT-041`, upstream `ENG-014`, upstream `INTK-033`, upstream `CASE-021` — and under D-001 upstream work not merged before the freeze does not arrive late, it **vanishes**.

Operator-visible consequence: a production defect fixed upstream after 2026-08-23 (Box call amplification, a stranded triage-request email, an EVA package EVA rejects) ships into the desktop unfixed, with nobody having decided to accept it.

This ticket has **no seeded plan row** — it is the one conversion ticket with no upstream id and no row in the plan set. It was specified verbatim inside [[DSK-01-10]] during board seeding and created from that specification on 2026-08-24; step 11 adds its plan row.

## Implementation steps

1. Orient: read `upstream-kanmer-carryover.md` § Code drift and the first sync, `docs/engineering.md` § Branches and delivery, and [[DSK-01-10]]'s proof document for the head it synced to. Read the group document `HZN-001` / `board-conventions.md` § "Upstream ids versus board ids" before writing any id. `get_doc_gates <this ticket id>`, then `take_ticket`.
2. Establish the trigger and record it: a sync runs when upstream cuts a release, and in any case no less often than every two weeks while the conversion is live. Record the chosen cadence and **who watches for upstream releases** in the ticket plan — a cadence nobody watches is not a cadence.
3. Per repetition: `git fetch upstream main --no-tags`, record `git rev-parse upstream/main` and the date, then `git merge-base --is-ancestor $(git rev-parse main) upstream/main` and `git log --oneline --no-merges main..upstream/main`. **Re-derive the range every time; never replay a recorded list.**
4. Per repetition: name every upstream ticket id the commit subjects carry, tick each off the carry-over register, and record any register row that has **not** arrived. The known watch list at creation time is upstream `DOCS-013`, `PLAT-041`, `ENG-014`, `ENG-015`, `INTK-033`, `CASE-021`. A row still unarrived as the freeze approaches must be raised as a fork ticket **before** the freeze, not after.
5. Per repetition: task branch from `dev`, `git merge upstream/main`, resolve conflicts in favour of upstream for files upstream owns, check `docs/adr/README.md` for a collision with the reserved ADR-0100…ADR-0110 block, run the local gates (`Test-DocumentationLinks.ps1`, `Test-MarkdownPlacement.ps1` with its mandatory `-Base`/`-Head`, `Test-MigrationGrants.ps1`, the test lanes via `run-tests`), open the PR into `dev`, take the independent review, and merge only with `repository-check` green or path-skipped.
6. Per repetition, **Operator step**: promote by the exact-SHA atomic fast-forward from `docs/engineering.md:10-52` after the literal `MERGE AUTH GRANTED`; read both remote heads back equal to the reviewed SHA. A GitHub merge, squash or rebase is **not** a promotion.
7. Per repetition: re-stamp the parity rows citing files the sync touched (`docs/desktop/01-inventory-and-parity/parity-matrix.md`) and append a dated line to `upstream-kanmer-carryover.md` § Code drift recording the head, the count and the tickets brought.
8. **The final sync (the D-001 freeze).** When [[DSK-00-10]] confirms the freeze date with the upstream owners, run one last sync, then record in `upstream-kanmer-carryover.md` and `docs/desktop/README.md` § Locked decisions that upstream is frozen from that SHA: after it, the fork is the single release source and nothing further arrives from upstream. List, by upstream id, every register row still unarrived at that moment — each is now either a fork ticket or a deliberate loss, and this ticket says which.
9. Close only after the freeze sync. Every earlier repetition is recorded in the ticket's `proof` document as a dated entry; the ticket stays open across the whole conversion **by design**, and its checklist is one item per repetition.
10. Record the simplification pass over each branch's own diff (`n/a — docs-only` where the branch carries only the merge and the register lines); upstream commits are never in scope for the pass.
11. Add the `DSK-01-13` row to `docs/desktop/01-inventory-and-parity/README.md` § 5 so this ticket stops being the one board ticket with no plan row, and record in the ticket plan **why the horizon is HZN-010 and not HZN-001**: the ticket *closes* at the freeze in Phase 9, but its first execution is immediately after [[DSK-01-10]] in Phase 0. The horizon must not be read as deferring the intermediate syncs.
