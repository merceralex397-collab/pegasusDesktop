## What

Merge the pending upstream commits from `collisionengineers/pegasus` `main` into the fork's `dev` through a reviewed PR, promote the reviewed SHA to `main` by the exact-SHA procedure, and then re-run the parity rows that cite files the sync touched. The range is **re-derived from `upstream/main` HEAD at execution time**, not taken from the 32-commit set recorded at `7d6a948a` on 2026-08-23. One-way only: nothing is ever pushed to upstream.

## Why

The web application is still live and still receiving fixes the evolved gateway needs (area 00 § 3 branching flow item 2), so the fork must track upstream until cutover. This first sync brings production defect fixes the desktop would otherwise inherit: `PLAT-039` Box access-token renewal (`282ba44`, `79db11f`), `DOCS-010` Box read fixes and evidence-gallery occurrence targeting (`e1d40a6`, `ef5f1b6`), `MAIL-011`/`MAIL-012` (`9c39c1d`, `51da3a3`, `1828a4b`), `ENG-013` (`42a3a84`), `CASE-019` case-export proof (`efbb2a9`). Operator-visible consequence: without the sync, a desktop Box upload path is built on a token that is minted once per process and expires mid-session, and `docs/operations.md` never gains releases 21–24. The recorded 32-commit set is a **planning baseline, not the range to execute** — upstream kept moving after 2026-08-23, and under D-001 anything still unmerged at the freeze is lost, so a sync that replays a fixed list silently drops whatever landed since. Sibling [[DSK-00-02]] owns the same first sync from the governance side — coordinate, do not duplicate. The parity rows re-run afterwards belong to [[DSK-01-02]] … [[DSK-01-05]].
