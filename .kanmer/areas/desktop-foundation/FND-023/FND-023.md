## What

Merge the 32 pending upstream commits (`collisionengineers/pegasus` `main` `7d6a948a`) into the fork's `dev` through a reviewed PR, promote the reviewed SHA to `main` by the exact-SHA procedure, and then re-run the parity rows that cite files the sync touched. One-way only: nothing is ever pushed to upstream.

## Why

The web application is still live and still receiving fixes the evolved gateway needs (area 00 § 3 branching flow item 2), so the fork must track upstream until cutover. This first sync brings production defect fixes the desktop would otherwise inherit: `PLAT-039` Box access-token renewal (`282ba44`, `79db11f`), `DOCS-010` Box read fixes and evidence-gallery occurrence targeting (`e1d40a6`, `ef5f1b6`), `MAIL-011`/`MAIL-012` (`9c39c1d`, `51da3a3`, `1828a4b`), `ENG-013` (`42a3a84`), `CASE-019` case-export proof (`efbb2a9`). Operator-visible consequence: without the sync, a desktop Box upload path is built on a token that is minted once per process and expires mid-session, and `docs/operations.md` never gains releases 21–24. Sibling [[DSK-00-02]] owns the same first sync from the governance side — coordinate, do not duplicate. The parity rows re-run afterwards belong to [[DSK-01-02]] … [[DSK-01-05]].

## Implementation steps

1. Orientation. Read `docs/desktop/01-inventory-and-parity/upstream-kanmer-carryover.md` § Code drift and the first sync, `docs/desktop/00-governance-and-workflow/README.md` § Recommended branching flow, and `docs/engineering.md` § Branches and delivery in full. Check with `search_items` whether [[DSK-00-02]] has already landed the sync; if it has, this ticket does steps 9–12 only. Call `get_doc_gates` for this ticket id, then `take_ticket`.
2. Confirm `dev` exists and matches the baseline: `git branch --list dev` and `git rev-parse dev main`. If `dev` does not exist, stop — [[DSK-00-01]] owns creating it and this ticket is blocked.
3. Add the upstream remote read-only and fetch it:
   `git remote add upstream https://github.com/collisionengineers/pegasus.git`
   `git remote set-url --push upstream DISABLED`
   `git fetch upstream main --no-tags`.
   The push URL is deliberately unusable; the fork must never push to upstream.
4. Prove the fast-forward before merging: `git merge-base --is-ancestor $(git rev-parse main) upstream/main` (expected exit code 0) and `git log --oneline main..upstream/main | wc -l` (expected 32 at the planning baseline; state the actual number). Record both in the ticket plan document.
5. Cut the task branch from `dev` and merge upstream into it, never into `main`:
   `git switch dev && git pull --ff-only && git switch -c task/dsk-01-10-first-upstream-sync && git merge upstream/main`.
   A merge commit is acceptable (the carry-over document says so). Resolve conflicts in favour of upstream for files upstream owns — do not "fix forward" in the fork what upstream owns; raise those upstream instead (area 00 § 7 trap 4).
6. Check for an ADR-number collision immediately after the merge: `ls docs/adr/` and `sed -n '1,80p' docs/adr/README.md`. Upstream keeps issuing ADRs from the low numbers; the conversion uses the reserved block ADR-0100…ADR-0110 and must never take "next free number". If upstream added an ADR whose number the fork also used, that is a blocking finding.
7. Run the full local gate before opening the PR: `pwsh ./scripts/Test-DocumentationLinks.ps1`, `pwsh ./scripts/Test-MarkdownPlacement.ps1`, `pwsh ./scripts/Test-MigrationGrants.ps1`, then the test lanes with the `run-tests` skill (`dotnet test` over `tests/Pegasus.Core.Tests`, `tests/Pegasus.ArchitectureTests`, and `scripts/Invoke-TestShard.ps1` for the integration shards). Done means every command exits 0 and the migration census in `tests/Pegasus.IntegrationTests/IntakePersistenceIntegrationTests.cs` still matches the migration folder.
8. Open the PR into `dev`, request the independent review by `pegasus-desktop-reviewer`, and wait for every `repository-check` job in `.github/workflows/ci.yml` to be green or path-skipped. Merge into `dev` only after both.
9. **Operator step** — promotion to `main`. The release actor needs the literal `MERGE AUTH GRANTED` from the operator before the push. The procedure is the exact-SHA atomic fast-forward from `docs/engineering.md:10-52`: fetch both remote refs, confirm `git merge-base --is-ancestor origin/main origin/dev`, record the reviewed `origin/dev` SHA, then
   `git push --atomic --force-with-lease=refs/heads/dev:<reviewed-dev-sha> origin <reviewed-dev-sha>:refs/heads/main <reviewed-dev-sha>:refs/heads/dev`,
   then fetch again and require both remote heads to equal the recorded SHA. A GitHub merge, squash or rebase is **not** a promotion. Evidence the operator hands back: the granted authorisation text and the reviewed SHA.
10. Confirm `docs/operations.md` now carries releases 21–24 in its release table at `:311-332`. If the `docs/operations.md:295` "release 14" line is still wrong after the sync, record it as a one-line follow-up documentation ticket — do not silently rewrite unrelated upstream text in this PR.
11. Re-run the parity rows that cite files the sync touched: `git diff --name-only 191ddf33..upstream/main` (or `<recorded fork main>..upstream/main`), then for every changed path under `src/Pegasus.Web/Pages`, `src/Pegasus.Core`, `src/Pegasus.Infrastructure/Custody` and `src/Pegasus.Infrastructure/Email`, re-check the matching `PAR` rows in `docs/desktop/01-inventory-and-parity/parity-matrix.md` and update the inventoried-at SHA. `PAR-17` in particular gains the `CASE-019` export proof.
12. Record the sync in the ticket `proof` document (`set_ticket_doc`): commit range, the reviewed SHA, the CI run link, the parity rows re-stamped, and the confirmation that no push to upstream was made. Tick every `open-questions/` item, call `get_doc_gates`, and move the ticket on.
