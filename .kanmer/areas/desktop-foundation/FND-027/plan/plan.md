## Approach

Convert to central package management as a **mechanical, one-commit move** — every
version literal lifted into `Directory.Packages.props` at exactly the value it holds
today, one property (`RestorePackagesWithLockFile`) hoisted into
`Directory.Build.props`, the lock files regenerated with `--force-evaluate`, and the
whole thing proved by the repository's own canonical locked commands from
`docs/runbook.md:298`. The rejected alternative is converting only the projects the
desktop will touch and leaving the rest on inline versions: NuGet's
`ManagePackageVersionsCentrally` is a repository-wide property once
`Directory.Packages.props` sits at the root, so a partial conversion produces `NU1008`
on every unconverted `PackageReference`, and with `TreatWarningsAsErrors=true`
(`Directory.Build.props:8`) that is a build failure rather than a warning. The second
rejected alternative is adding `Microsoft.WindowsAppSDK` here to "save a round trip":
[[FND-030]] (plan handle `DSK-02-05`) owns that, this ticket has no desktop project to
put it in, and pinning a package nothing references is exactly the unreviewed drift
this ticket exists to prevent.

## Risks / open questions

- **`Azure.Storage.Blobs` is referenced at two versions and CPM permits one.**
  Infrastructure `:9` pins `12.26.0`; Worker `:21` pins `12.29.1`. **Default taken:**
  converge on **`12.29.1`**, the newer of the two, because it is already in production
  in the Worker and because a downgrade is the riskier direction. It is proved, not
  assumed, by Verification rows 2–5: the locked restore, the zero-warning Release build
  and both unit lanes all run against the converged graph, and
  `tests/Pegasus.ArchitectureTests/AzureBlobIntakeArtifactStoreTests.cs` (348 lines)
  exercises the blob path directly. **Escape hatch, recorded rather than used
  silently:** if the converged version breaks Infrastructure, add
  `VersionOverride="12.26.0"` on that one `PackageReference` and write the reason into
  this plan and into the PR description — a `VersionOverride` nobody explained is the
  drift this ticket exists to remove. This is a decision this ticket takes, not a
  question for anyone else, and no `open-questions` document is created for it.
- **A partial conversion cannot work.** `ManagePackageVersionsCentrally` applies from
  the root, so any `PackageReference` left with a `Version` raises `NU1008`, which
  `TreatWarningsAsErrors=true` turns into a build failure. *Mitigation:* step 4's
  grep-to-zero check before step 6.
- **`NU1507` (multiple package sources).** There is no `nuget.config` today, so the
  restore uses whatever sources the machine or the runner provides. *Mitigation:*
  step 7 — if it appears, add a single-source `nuget.config` and record it; never
  suppress it.
- **The `$(PlaywrightVersion)` chain is load-bearing and easy to break.**
  `Directory.Build.props:10-16` says why: the `playwright/dotnet` base-image tag at
  `Pegasus.Web.csproj:28` must match the pinned package exactly or Playwright refuses
  to drive a browser build it did not pin (ADR-0028). *Mitigation:* step 3 writes the
  `PackageVersion` as `$(PlaywrightVersion)` rather than a literal, and Verification
  row 9 greps for a stray `1.61.0`.
- **Lock files for the desktop projects will be RID/TFM specific**
  (`docs/desktop/02-architecture-and-foundation/README.md` § 7), so CI must restore
