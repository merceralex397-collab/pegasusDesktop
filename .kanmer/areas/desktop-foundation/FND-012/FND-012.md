## What

Make `docs/desktop/01-inventory-and-parity/parity-matrix.md` the one canonical home of the feature-parity matrix: link it from `docs/index.md` and note it in `docs/capabilities.md`, and record a decision about whether it later moves to the `docs/features/desktop-parity-matrix.md` path the proposal names.

## Why

Proposal §23 says "Create `docs/features/desktop-parity-matrix.md`", and the plan set instead created `docs/desktop/01-inventory-and-parity/parity-matrix.md` — already pre-populated from the fork at `main` `191ddf33`. Two named paths for one artefact is exactly how a second, diverging matrix appears, and the matrix is the evidence base for programme exit criterion 5 ("every critical workflow has automated and UAT parity evidence") and for the per-slice parity evidence in area 05. It is also currently invisible: `docs/index.md` — the one file that answers "which file owns this question" — does not mention it, and neither does `docs/capabilities.md`. The move itself is not free: `scripts/Test-MarkdownPlacement.ps1:31` allows Markdown only under `docs/(prd|frd|adr|design|desktop)` plus a few tool trees, so a `docs/features/` file would fail the CI `documentation` job unless that regex changes — which is a decision, not a rename.
