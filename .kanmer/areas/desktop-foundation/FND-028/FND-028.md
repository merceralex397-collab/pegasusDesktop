## What

Add a server-only build entry point (`Pegasus.Server.slnf` or the recorded equivalent) covering `Pegasus.Core`, `Pegasus.Infrastructure`, `Pegasus.Web`, `Pegasus.Worker` and their three test projects, so a Linux workstation can still restore and build after the Windows-TFM desktop projects join `Pegasus.slnx`, and extend `DependencyDirectionTests` so the solution contents test is updated rather than bypassed.

## Why

Plan § 3 decision 5 records the problem: `src/Pegasus.Desktop` targets `net10.0-windows10.0.26100.0`, and a Windows target framework in `Pegasus.slnx` breaks `dotnet build ./Pegasus.slnx` on Linux, while `docs/runbook.md` § Supported platform states that repository development supports Linux with PowerShell 7 as a first-class workstation. Without this filter, [[DSK-02-05]] silently makes the repository Windows-only for developers. The architecture test `ApplicationSolutionExcludesSourceWorkspaces` (`tests/Pegasus.ArchitectureTests/DependencyDirectionTests.cs:128`) asserts the exact seven-project list, so it must be extended in the same slice the list changes — extending it is the point, bypassing it is a defect.
