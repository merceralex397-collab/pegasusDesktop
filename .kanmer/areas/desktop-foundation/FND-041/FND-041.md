## What

Run the Phase 1 exit review: on a clean Windows 11 x64 machine, install the development-signed MSIX, launch the native shell, navigate every rail route, prove single instance, export a diagnostics bundle, uninstall, and attach evidence for every row of the plan's exit-gate table to the ticket proof — reviewed by an agent that implemented none of it.

## Why

Proposal § 24 Phase 1 states the exit gate (clean Windows 11 test machine launches the native shell; no WebView/web application dependency; foundation tests pass; package install/uninstall works), and § 29 item 8 requires the foundation spike to be reviewed before converting further. Plan § 4 turns the gate into seven testable rows. This ticket is the gate: area 04 and the first vertical slice in area 05 should not start until it passes. Operator-visible consequence: this is the first time a person other than the implementing agent sees the application behave on a machine that is not a development workstation.

## Implementation steps

1. Orient: read the plan row and `docs/desktop/02-architecture-and-foundation/README.md` § 4 in full, then `get_doc_gates <this ticket id>` and `take_ticket`. Confirm in the ticket plan which area 02 tickets the reviewing agent did **not** implement; if it implemented any, hand the ticket to another agent.
2. Confirm every prerequisite ticket is Done: `get_item` for each of [[DSK-02-01]] through [[DSK-02-15]] and record its stage. A gate row whose owning ticket is unfinished is a fail, not a "partially met".
3. Verify the solution shape against the plan § 4 target-state table: `cat Pegasus.slnx` and confirm it lists `Pegasus.Core`, `Pegasus.Contracts`, `Pegasus.Infrastructure`, `Pegasus.Web`, `Pegasus.Worker`, `Pegasus.Desktop`, `Pegasus.Desktop.Infrastructure` and the test projects that exist; confirm the server entry point lists only the server set. Record any divergence as a finding.
4. Gate row "Foundation tests pass": run `dotnet test ./tests/Pegasus.Desktop.ViewModelTests/Pegasus.Desktop.ViewModelTests.csproj --configuration Release` and `dotnet test ./tests/Pegasus.ArchitectureTests/Pegasus.ArchitectureTests.csproj --configuration Release`. Expected: both green, zero skipped. Capture the console output as command-log proof.
5. Gate row "Architecture boundaries enforced": plant a forbidden `PackageReference` in `src/Pegasus.Desktop.Infrastructure` in a scratch worktree, re-run the architecture tests, confirm the suite goes red naming the package, revert. Capture both outputs. A fact that cannot be shown red is not enforcement.
6. Gate row "No WebView/web dependency in the package": scan the built package content and the desktop projects — `grep -rn 'WebView2\|Microsoft.Web.WebView2' src/Pegasus.Desktop src/Pegasus.Desktop.Infrastructure` and list the assemblies inside the produced `.msix`. Expected: no WebView2 assembly and no `WebView2` XAML element. ADR-0108 does not exist yet, so any hit is a gate failure.
7. **Operator step** — clean machine. On a clean Windows 11 x64 machine or a fresh VM snapshot, with the development certificate trusted per [[DSK-02-14]], run `pwsh ./tests/Pegasus.Packaging.Tests/Test-InstallUninstall.ps1 -Package <msix>`. The operator hands back the script log, the `Get-AppxPackage` output showing `Name`, `Publisher`, `PackageFamilyName` and `Version`, and confirmation that installation needed no administrator elevation.
8. Gate row "Clean Windows 11 machine launches the native shell": on that machine launch via `winapp run`, screenshot the shell, and navigate every rail route in the approved order, screenshotting each. Confirm the environment badge is visible (non-production channel) and the status bar shows connection state.
9. Gate row "Single instance": launch the installed application a second time on the same user session. Expected: exactly one window and one process; the activation log records the redirect. Capture the screenshot and the log excerpt.
10. Gate row "Diagnostics bundle exports": use the Diagnostics settings route's Export diagnostics command (`Settings.ExportDiagnostics`), extract the produced zip, and check the manifest against the documented schema from [[DSK-02-11]]. Run `Select-String -Path <extracted>\* -Pattern 'Bearer '` and expect no matches. Capture the manifest and the scan result.
11. Gate row "Install/uninstall leaves only intended user settings": after uninstall, confirm `%LOCALAPPDATA%\Packages\<PackageFamilyName>` is gone and no DPAPI credential-store file remains. Capture the directory listing.
12. Run the keyboard and accessibility pass by hand: tab through the shell, exercise the access keys `Alt+D/I/U/Q/C/O/A`, `Ctrl+K` and `F5`, and view the shell in Light, Dark and Windows high contrast. Automated checks do not replace this manual review (`docs/engineering.md` tier 7). Capture the three theme screenshots.
13. Write the verdict into the ticket proof with one row per gate row: gate, evidence artefact, pass/fail, and the ticket that owns any failure. Every failure becomes a new Kanmer ticket in `desktop-foundation` naming the gate row it blocks; do not fix code in this ticket. Then `set_ticket_doc` the proof and move the ticket, calling `get_doc_gates` first.
