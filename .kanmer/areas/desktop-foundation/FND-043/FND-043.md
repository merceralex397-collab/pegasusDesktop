## What

Build the desktop session client in `src/Pegasus.Desktop.Infrastructure`: a sign-in call against the gateway token endpoint, the access token held only in memory, the refresh handle held only in the DPAPI credential store from [[DSK-02-06]], one silent refresh on an expired access token, sign-out, and the `X-Pegasus-Client-Version` / `X-Correlation-Id` headers on every request.

## Why

Proposal § 8.2 requires a desktop-compatible session that does not change user credentials: post credentials over TLS, receive a short-lived access token plus a rotated refresh token, keep the access token in memory, store only the refresh handle, and carry a client version and correlation identifier on every request. Nothing in the repository does this today — `src/Pegasus.Web` issues only the `__Host-Pegasus` cookie (`src/Pegasus.Web/Program.cs:370`) and an OpenIddict client-credentials token for the Automation MCP actor. Without this ticket the native login screen [[DSK-04-08]] and the startup orchestrator [[DSK-04-09]] have nothing to call, and the operator-visible consequence is that no desktop workflow can authenticate at all.

2. Read the two projects this ticket builds on before writing code: `src/Pegasus.Desktop.Infrastructure` (created by [[DSK-02-06]] — find the credential-store interface and the `DelegatingHandler` that already adds `X-Pegasus-Client-Version` and `X-Correlation-Id`) and `src/Pegasus.Contracts` (created by [[DSK-02-04]] — the problem-details envelope). If the type names differ from the ones below, use the ones that exist and say so in the plan document.
3. Add a session contract to `src/Pegasus.Desktop.Infrastructure` under a `Session/` folder (capability folders, never a `Common`/`Helpers` folder — `docs/engineering.md` § Capability organization): `ISessionClient` with `SignInAsync(string userName, string password, CancellationToken)`, `RefreshAsync(CancellationToken)`, `SignOutAsync(CancellationToken)`, and a read-only `CurrentAccessToken` that is only ever a field in memory. Done when the project compiles with `TreatWarningsAsErrors=true`.
4. Implement the token call against `POST /connect/token` with `Content-Type: application/x-www-form-urlencoded` and the exact form fields for the password grant: `grant_type=password`, `username`, `password`, `client_id=pegasus-desktop`, `scope=pegasus.desktop offline_access`. Parse `access_token`, `refresh_token`, `expires_in`, and on failure the OAuth `error` and `error_description`. Confirm the field names with `microsoft_docs_search` for the OAuth 2.0 resource-owner password grant if unsure; do not invent a field.
5. Implement `RefreshAsync` as `grant_type=refresh_token` with the stored handle, and persist the **new** refresh token every time (the grant is rolling — decision 2). Never persist the password, not even under a "remember me" affordance (area plan § 7, and proposal § 8.2 "Do not store the user's password").
6. Persist the refresh handle only through the DPAPI store from [[DSK-02-06]] (`ProtectedData` with `DataProtectionScope.CurrentUser`, file under `ApplicationData.Current.LocalFolder`). Add a unit test that writes a handle, reads it back, and asserts the on-disk bytes do not contain the plaintext handle.
7. Add `SessionAuthorizationHandler : DelegatingHandler` to the HTTP pipeline: attach `Authorization: Bearer <access token>`; on a `401` carrying `WWW-Authenticate: Bearer error="invalid_token"`, call `RefreshAsync` **once**, then retry the original request exactly once. A second `401` must surface as a session failure, never a refresh loop.
8. Map every row of the area plan's *Session failure matrix* to a single `SessionFailure` value the view models can switch on: `AccessTokenExpired`, `RefreshRevoked` (token endpoint `invalid_grant`), `AccountDisabled` (`urn:pegasus:problem:account-disabled`), `PasswordChangeRequired` (`urn:pegasus:problem:password-change-required`), `ClientUnsupported` (`urn:pegasus:problem:client-unsupported`, carrying `minimumVersion`), `Unreachable` (transport exception), `RateLimited` (HTTP `429`, carrying the `Retry-After` seconds). Do not add a value the matrix does not list.
9. Extend the log redactor from [[DSK-02-07]] so `access_token`, `refresh_token`, `password`, `Authorization` and `Set-Cookie` values are never written to the rolling log, and add a test that runs a full sign-in against a stubbed handler and asserts the log file contains none of those literals.
10. Register `ISessionClient`, the DPAPI store and `SessionAuthorizationHandler` in the generic host in `src/Pegasus.Desktop/App.xaml.cs` (composed by [[DSK-02-07]]), wiring the handler into the named `HttpClient` that talks to the gateway.
11. Write tests in `tests/Pegasus.Desktop.ViewModelTests` against a fake `HttpMessageHandler`: successful sign-in stores a refresh handle and no password; an expired access token triggers exactly one refresh and one retry; `invalid_grant` clears the store and reports `RefreshRevoked`; `429` reports `RateLimited` with the `Retry-After` value; a transport exception reports `Unreachable` and never `invalid credentials`.
12. Run `dotnet test tests/Pegasus.Desktop.ViewModelTests` — expected: all tests pass, including the redaction test and the DPAPI round-trip test.
13. Prove it end to end against the local stack: `pwsh ./scripts/Invoke-LocalDevelopment.ps1 -Action Start`, note the printed Web readiness URL, point the desktop `local` channel configuration at it, build and launch with `.\BuildAndRun.ps1` from `.codex/skills/winui-dev-workflow/`, and sign in with the local Administrator the initialization step creates.
